A recorded hosted acceptance pass covering the complete account lifecycle — signup/verification, guest-data import into a newly created account, sign-out/in with saved data restored, password recovery, email change, and account deletion — using real delivered emails and two disposable account fixtures. Must demonstrate neither disposable account can read/write the other's records, and that deletion removes only the deleted owner's data.

This ticket does not perform any new hosted configuration change, deploy, or migration — it verifies the release T231 already shipped.

**Hard constraint on execution (from the harness's own action-safety rules, which take precedence over ticket instructions):** creating accounts and entering passwords to authenticate are prohibited actions for the agent to perform, even with explicit authorization, and permanently deleting data is likewise prohibited for the agent to perform directly. Concretely, this means:

- The owner performs every signup, sign-in, sign-out, password-entry, email-change, password-recovery, and account-deletion action themselves, in their own browser.
- The agent prepares exact steps, exact copy/values to enter, and what to look for; the agent does not fill credential fields, click "Create account"/"Delete account", or otherwise authenticate as any test account itself.
- The agent can perform read-only verification (checking route availability, inspecting already-completed states the owner reports, reviewing the existing automated authorization test suite, reviewing Resend delivery logs or Supabase Auth logs if the owner shares them) and can reuse `supabase/tests/data-api`'s existing T155.7 cross-user isolation suite as backend-layer evidence rather than re-deriving it by hand.
- Cross-account isolation is proven primarily via T155.7's existing pgTAP/Data-API suite (already `Done`, covers anonymous denial, cross-user isolation, and per-operation grant matrices at the RLS layer) plus the owner's own UI observation that account B's app never shows account A's tricks/history/goals/notes after each performs the same actions with their own data.
