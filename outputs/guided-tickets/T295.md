## What the code does today (inspected 2026-11-09)

| Seam | Current behaviour | Consequence for native |
| --- | --- | --- |
| `src/shared/supabase/supabase-client.ts` | Returns `null` when `Platform.OS !== 'web'`. On web it uses PKCE, `detectSessionInUrl: false` and AsyncStorage session storage. | This is the single gate. Every native "unavailable" state follows from it. |
| `src/features/auth/model/account-availability.ts` | `areAccountsAvailable` returns true only on web. `/auth/*`, the Profile guest section and the landing CTA use it. | The predicate must change at the same time as the client gate. |
| `auth-provider.tsx` lines 234, 251, 267, 351 | Builds `redirectTo` from `window.location.origin`. | This crashes or gives a wrong URL on native. A platform-aware callback URL builder is needed. |
| `auth-provider.tsx` optimistic cached-session read | Reads the GoTrue session straight from AsyncStorage by key (`getGoTrueStorageKey`). | It must read through the same storage adapter as the client. If not, the session moves to SecureStore and this read silently stops working. |
| `auth-callback-screen.tsx` | Handles `code`, `error`, `message` and `flow` query params. The hash error read is web-only and already guarded. | The screen can be reused for a `dailydama://auth/callback?code=…` deep link, because Expo Router maps the scheme path to the same route. |
| `identity-provider.tsx` refresh-failed "Try again" | Calls `window.location.reload()`. | On native the button does nothing. An in-app auth re-initialisation is needed. |
| `sync-coordinator-provider.tsx`, `use-sync-coordinator.ts` | Online state comes from `window` online/offline events. On native it is always `true`. AppState foreground already triggers a sync. | Native never shows "offline". Reconnection only happens on foreground or the next mutation. |
| `native-start/state/use-native-onboarding-status.ts` | Reads only the **guest**-scoped profile. | A signed-in user who relaunches the app sees the Start screen. The start route must use the active identity. |
| `src/app/app/home.tsx` | Blocks onboarding while a guest import is pending, and resyncs after the import. | There is no guard for "signed in, with no import, before the first profile pull". An existing account can briefly see onboarding. |
| `submit-feedback.ts` and feedback migrations | Uses the shared client. The `anon` and `authenticated` INSERT policies exist. A server trigger owns the `email` value. | Native feedback works for guests and users once the client exists. No migration is needed. |
| `app.json` | `scheme: "dailydama"`. No `expo-secure-store` is installed. | The scheme is ready. SecureStore is a new dependency and needs a native rebuild. |
| `supabase/config.toml` | `additional_redirect_urls` contains only `http://localhost:8081/auth/callback`. | The native callback must go on the allow-list, locally and on the hosted project (owner gate). |

## Decisions and authority

| # | Decision | Recommendation and tradeoff | Owner decision | Scope / date |
| --- | --- | --- | --- | --- |
| D1 | Native Supabase client | Use one `getSupabaseClient` with a platform storage adapter. Keep PKCE and `detectSessionInUrl: false`. On native, call `auth.startAutoRefresh()`/`stopAutoRefresh()` on AppState changes, as Supabase's React Native guide says. Do not create a second client module, because the memoisation and storage-key contract must stay single. | pending | T313.1 |
| D2 | Session storage | Use SecureStore on native and keep AsyncStorage on web. A Supabase session (access token, refresh token, user JSON) can be larger than SecureStore's documented ~2 KB value guidance. T313.1 first measures a real session against the SDK 57 limit. If the limit applies, use Supabase's documented pattern: a random AES key in SecureStore and the encrypted session in AsyncStorage. Do not split values into many keychain items, because a partial write gives a corrupt session. The web key derivation must stay the same, or web users are signed out. | pending | T313.1 |
| D3 | Email-link callback | Use the custom scheme `dailydama://auth/callback`. Build it with `expo-linking`'s `createURL` and send it to the existing `/auth/callback` screen. Universal Links and App Links need an Associated Domains entitlement and a hosted AASA file. The current personal-team iOS build cannot use Associated Domains, so defer them. Tradeoff: a link opened on another device cannot finish PKCE. The existing `missingVerifier` copy already tells the user to open it on the device that requested it. Owner gate: add the scheme URL to the hosted Supabase redirect allow-list. | pending | T313.2 |
| D4 | Identity switching | Reuse `AuthProvider` → `IdentityProvider` as they are. The identity change already remounts the domain providers on a new scoped namespace. Replace only the web reload in refresh-failed recovery with a native re-initialisation. Logout keeps the logout guard and the fail-closed discard rules. | pending | T313.1 |
| D5 | Guest import and sync on native | Do not change the import or sync logic. Both use AsyncStorage and the shared client. Add native online detection with `expo-network`'s state listener (managed, no NetInfo). This makes "offline" status and reconnection sync work. Tradeoff: one more native module and a rebuild. The alternative is to accept "always online" and depend on foreground retries, but that fails S040's "offline mutation and reconnection" criterion. | pending | T313.6 |
| D6 | Sign in from the Start screen | Add a Sign in action next to Get started. After sign-in, the root and Home routes wait for the first profile pull before they decide on onboarding. If the pull fails (offline or server error), show a retry screen and do not show onboarding. This fails closed for an existing account. Make the start route identity-aware, so a signed-in relaunch goes to Home. | pending | T313.4 |
| D7 | Guest feedback on native | Allow it. This matches web: the `anon` insert policy exists, and the server forces `email` to null for guests. There is no new abuse surface beyond web. | pending | T313.5 |
| D8 | Account management on native | When the predicate changes, the existing Profile account section, security screen (email change, password), forgot/reset password, logout and account deletion all appear. Enable and verify all of them. Apple requires in-app account deletion for apps that allow account creation (App Review Guideline 5.1.1(v)). Do not hide deletion. | pending | T313.2, T313.3, T313.6 |
| D9 | Rollout gate | Change `areAccountsAvailable` for native in T313.1, together with the client. Do not add a feature flag. The native app is not published yet (personal dev build only), so a half-finished flow does not reach users. A flag would add a third state to test. | pending | T313.1 |
| D10 | Android evidence | Android has no verified development build. Recommendation: make an Android dev build a stated prerequisite of T313.6. Record Android checks in T313.1–T313.5 as `not run` until the build exists. Do not block iOS delivery on Android. | pending | T313.6 |

### T313.1 — Give native a Supabase client with secure session storage
- **Planning:** Required. **Area:** Auth / native.
- **Work:** D1, D2, D4 (native refresh-failed retry), D9. Add a platform storage adapter. Route the optimistic cached-session read through the adapter. Add AppState auto-refresh. Change `areAccountsAvailable` and the client gate for iOS and Android. Update ARCHITECTURE.md and the AGENTS.md auth notes.
- **Exit criteria:** Unit tests prove these points. (a) On iOS and Android the adapter writes the session through SecureStore (or the encrypted-blob scheme) and never writes the plaintext refresh token to AsyncStorage. (b) Web still uses AsyncStorage with the unchanged `resolveGoTrueStorageKey` output. (c) The optimistic cached-session read returns a stored session on native. (d) AppState `background` stops and `active` starts auto-refresh. (e) A failed SecureStore write during sign-in returns a structured failure and does not leave the user signed in. (f) "Try again" in refresh-failed recovery re-initialises auth on native. On the iOS Simulator, sign-in with a local Supabase test account survives a cold relaunch. The guide records the measured session size against the limit. `yarn tsc --noEmit` and the auth and persistence suites pass.

### T313.2 — Complete email links in the app
- **Planning:** Required. **Owner gate:** hosted Supabase redirect allow-list (agent prepares exact value; owner applies).
- **Work:** D3. Add a platform-aware callback URL builder for sign-up confirmation, password reset and email change (`?flow=email_change`). Add `dailydama://auth/callback` to the local `supabase/config.toml` allow-list. Prove that a cold-start deep link and a warm deep link both reach `AuthCallbackScreen`.
- **Exit criteria:** Unit tests prove these points. The builder returns `https://<origin>/auth/callback` on web (unchanged) and `dailydama://auth/callback` on native. No `window` access happens on native. The email-change flag is kept. On the iOS Simulator with local Supabase and Mailpit, the sign-up confirmation link opened with `xcrun simctl openurl` signs the user in. A password-reset link opens the reset screen. A cold-start link also works. An expired link and a link without a verifier show the existing copy. The hosted allow-list change is recorded as owner-applied, with the date. Hosted email-link behaviour on a device stays `not run` until it is observed.

### T313.3 — Make the sign-up and sign-in screens work on native
- **Planning:** Implementer.
- **Work:** Show the existing sign-up, sign-in, check-email and forgot-password screens on native. The web-only keydown handlers are already guarded. Check keyboard avoidance, `textContentType`/`autoComplete` for password managers, focus order and safe areas.
- **Exit criteria:** Route tests render each screen on `ios`. On the iOS Simulator: sign-up reaches check-email. Sign-in with valid credentials reaches Home. Invalid credentials show the existing error. The keyboard does not cover the submit button on iPhone 17e. Password fields use `textContentType` `password` or `newPassword`. Android is `not run` (D10).

### T313.4 — Let existing accounts sign in from the Start screen without redoing onboarding
- **Planning:** Required.
- **Work:** D6. Add a Sign in action to `NativeStartScreen`. Make `useNativeStartRoute` identity-aware. Add a first-profile-pull gate for a user identity that has no guest import pending.
- **Exit criteria:** Tests prove these points. (a) The Start screen shows Sign in next to Get started. (b) A signed-in identity with a completed cloud profile goes to Home on relaunch, and the Start screen never renders. (c) After sign-in from Start, onboarding does not render while the first profile pull is pending. (d) A failed pull shows a retry state and not onboarding. (e) A new account with no cloud profile goes to onboarding after the pull. (f) A guest who has local data and signs in still enters the existing guest-import flow. On the iOS Simulator, an account that finished onboarding on web signs in from Start and arrives on Home with its rank.

### T313.5 — Send feedback from the native app
- **Planning:** Implementer.
- **Work:** D7. Show `FeedbackScreen` on native and remove the `FeedbackUnavailableScreen` branch from `src/app/feedback.tsx`. Delete the unused component and tests if nothing else uses them.
- **Exit criteria:** Route tests render the form on `ios`. A `submitFeedback` test covers the native client path. On the iOS Simulator with local Supabase, a guest submission and a signed-in submission each insert one `api.feedback` row. The guest row has `email` null, and the user row has the server-derived email. A network failure shows the existing retry feedback.

### T313.6 — Verify backup, sync and account lifecycle on iOS and Android
- **Planning:** Required. **Prerequisite:** an Android development build (D10).
- **Work:** D5 (add `expo-network` online state) and D8. Run the S040 acceptance pass.
- **Exit criteria:** A test proves that native online and offline events update `SyncStatus` and that reconnecting starts a sync. On the iOS Simulator and the Android Emulator, the guide records each of these points: offline mutation, then reconnection, then the row appears in another client. Account isolation: a different account on the same device sees none of the first account's data. An active Sesh survives a sign-in and a token refresh. Logout with pending changes is blocked by the guard. Account deletion purges the local namespace and returns to guest. Any check that was not performed is recorded as `not run`.
