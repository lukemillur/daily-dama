## Newly discovered blockers (owner decision needed)

Both block T231's own "app routes" / "Auth callback" exit criteria; neither is in scope for any other open ticket (T227 only owns the five `:trickId` dynamic-route rewrites, not flat static routes).

1. **Production flat routes 404 (`/auth/*`, `/feedback`).** Fix is a one-line `vercel.json` addition (`"cleanUrls": true`), which is the standard, documented fix for exactly this static-export-on-Vercel gap. Low risk — it only affects extensionless-URL resolution, and `vercel.json`'s explicit `rewrites` entries (T227's five dynamic routes) take priority over it, so they're unaffected. Requires a normal code change (task branch → `development` → `main` → `production`) to take effect, i.e. another full promotion cycle.
2. **Staging Preview URL is behind Vercel SSO.** Needs a Vercel dashboard decision: disable Deployment Protection for this project/environment (simplest — matches the Supabase Dev Auth Redirect URL already pointing at this exact origin), or scope T231's staging-callback plan to something else (e.g. a `bypass` token or a different verification approach). This is a dashboard setting change, not a code change.
