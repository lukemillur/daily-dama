This ticket must:

- Add a narrow CSP `connect-src` allowance for the exact Sentry ingest origin the DSN resolves to (not a broad `*.sentry.io` wildcard — this repo's CSP philosophy elsewhere is exact-origin, e.g. `security/README.md`'s rationale section).
- Deploy and trigger one deliberate nonsensitive error from the live production site, confirm it reaches the Sentry project, and inspect the captured event for credentials or sensitive callback parameters before calling this closed.
- Confirm unrelated external connection origins remain denied (i.e. the CSP change is additive and narrow, not a relaxation of other rules).

Explicitly out of scope (per the ticket notes): source-map upload, tracing, session replay, `Sentry.wrap()`, manual `captureException` calls, native (iOS/Android) Sentry config — matches T218's original scope boundary.
