`FirstLaceBanner` became a thin wrapper over it with byte-identical accessibilityLabel/text output (verified by rerunning the pre-existing first-lace tests before touching goal logic), and a new sibling `GoalCelebrationBanner({ goal, tense })` renders goal copy ("Goal achieved" / "You just reached your goal — {formatGoalTarget(goal)}" in-sesh, past tense on wrap-up) through the same shell. `Sesh` now freezes `goalBaselines` (`GoalProgress[]`) at the moment a trick is picked (in `TrickPicker`'s `onSelect` and `CompletedSesh`'s `onRepeat`) via `selectGoalsForTrick(goals, trickId).map(g => selectGoalProgress(g, sessions))`, and threads it into `ActiveSesh`. `ActiveSesh` derives count-goal celebrations as a pure per-render filter (`isGoalNewlyAchieved(goal, baseline.current, landings.length) && !isGoalNewlyAchieved(goal, baseline.current, landings.length - 1)`, so it self-hides on the next landing with no latch needed), and derives time-goal crossings the same way against `elapsedMs`, then latches genuinely-new ones once via a `useRef<Set<string>>` checked inside a `useEffect` before any `setState` — the ref (not the effect's dependency array) is what prevents re-adding on every 250ms timer tick, and once shown a time celebration stays visible for the rest of the active sesh by design (no auto-dismiss). `Sesh`'s completion effect now also computes `justAchievedGoals` from the pre-record `sessions` snapshot (before `recordCompletedSesh` runs, mirroring the ordering guarantee `isFirstLaceForTrick` already relies on) via `selectGoalsForTrick` + `selectGoalProgress` + `getGoalContribution` + `isGoalNewlyAchieved`, resetting it to `[]` alongside `firstLaceCelebration` in both `onReset` and `onRepeat`; `CompletedSesh` gained an optional `justAchievedGoals?: readonly Goal[]` prop (default `[]`) rendered as `GoalCelebrationBanner`s near the existing first-lace banner. `MultiTrickSesh` was left untouched, consistent with existing precedent. New tests in `sesh.test.tsx`: `ActiveSesh` count-goal cases (crosses on the qualifying landing, not the next one; never fires when the baseline is already at target), an `ActiveSesh` time-goal case using the file's existing `jest.useFakeTimers()` pattern (crosses once with no landings, and further timer ticks don't duplicate the celebration — asserted by comparing banner-node counts before/after rather than a hardcoded length, since styled-components' composite+host node duplication meant `toHaveLength(1)` was the wrong assertion, matching the existing `findBanner` tests' `toBeGreaterThan(0)` pattern), `CompletedSesh` wrap-up cases (shows past-tense banner for a goal in `justAchievedGoals`; shows nothing when it's empty), and a `Sesh`-level wiring regression test that mounts real `GoalProvider` + `PracticeHistoryProvider` + `UserProfileProvider` + `NoteProvider`, adds a count goal, drives the real picker → countdown → active → laced × 3 → "End Sesh" flow (using a `pressByVisibleText` helper added for the End Sesh button, which — unlike other buttons in this file — carries no `accessibilityLabel`), and confirms the wrap-up shows the achieved-goal banner; this is the test that would catch a baseline computed from post-record sessions instead of pre-record ones. Verified by `yarn test --runInBand` (405 tests passing), `yarn lint`, `yarn tsc --noEmit`, `yarn expo export --platform web` (all clean), and an in-browser walkthrough on the Expo dev server: on a "Big cup" trick with 5 recorded laces, added a 6-lace count goal (unmet, 5/6), a 3-lace count goal (already achieved, showing an "Achieved" badge), and a 7:00 practice-time goal (unmet, 6:21/7:00); started a 1-minute timed sesh, landed once — the "Goal achieved / You just reached your goal — 6 laces" banner appeared immediately — landed a second time and confirmed the banner was gone; let the sesh run out with no further action and confirmed the wrap-up showed both the 6-laces and 07:00 goals in past tense ("You reached your goal") while the pre-achieved 3-laces goal never appeared in either the in-sesh or wrap-up celebrations.
