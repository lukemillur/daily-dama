## Starting-rank decision (recommendation)

1. Before any assessment step, read Profile > "Assessed Kentei rank" on the small device and record it in the notes (device, rank, plus which standard tricks are already laced, from Tricks/Stats). Take a screenshot as the record.
2. Do NOT try to restore the rank. Restoring requires an onboarding retake (resets selection/laced data) or a data wipe - both destructive to the simulator's existing owner-style data and outside "documentation only". Record in `DESLOPPIFY.md` that promotion changed the simulator's assessed rank from X to Y and that the simulator data is audit data, not owner practice. (The simulator is already marked as audit data in the existing section.)
3. Plan the promotion so it costs little: pick the starting-rank path so the stored rank is N and N has few unlaced standard tricks (check the Tricks screen for laced state). If every rank-N trick is already laced the rank would already be N+1, so choose the lowest rank with the fewest unlaced tricks. If the stored rank is high and ranks need many tricks, record promotion as a concrete blocked reason ("N unlaced tricks, not practical") only after attempting it to the extent feasible; a half-promoted run still yields skip and end evidence first.
4. Order the assessment so promotion is LAST (see step 6), so a partial run still yields complete skip/end rows. Also do the multi-trick run BEFORE the assessment: laces landed in multi-trick runs on standard tricks count toward rank and could cause an early, unobserved promotion that would pop the celebration modal mid-run. Use custom tricks (e.g. `T289.3 trick A/B/C`, created via Tricks > Define new trick > Standalone, unranked) or already-laced standard tricks for the multi-trick run so it cannot move the rank. If a promotion modal does appear unexpectedly, capture it as evidence and note the cause.

## Risks

- Unintended early promotion (laces on standard tricks in the multi-trick run): avoided by using custom/already-laced tricks; if the modal appears, treat as evidence and adjust.
- The rank cannot be lowered: the promotion step is one-way and consumes the only fresh promotion opportunity; run it last and capture the starting state first.
- Tool lag/swallowed taps: use simctl screenshots, wait for a stable frame before every tap, and record failures as blocked.
- The assessment's multi-rank flow can create many history records if laces are logged; land the minimum needed and note the data left behind.
