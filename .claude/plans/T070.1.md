# T070.1 — Reset the Profile route after leaving Kentei assessment

## Good enough for this iteration

Pressing the assessment wrap-up’s `Go to Home` action must leave the user on
Home and unwind the nested Profile assessment route, so selecting Profile later
shows the default Profile screen rather than the previous assessment wrap-up.
The assessment result copy and existing assessment persistence/promotion
behavior remain unchanged. No transient assessment UI state is persisted, and
mobile validation remains deferred under the repository’s active platform
scope.

## Ordered implementation plan

1. Update `src/features/sesh/components/assessment-entry.tsx` so the
   assessment completion callback uses Expo Router’s nested-stack dismissal
   behavior (`router.dismissTo('/')`, or the equivalent route-reset mechanism
   confirmed against the installed Expo Router API) instead of only replacing
   the current child route. Keep `finishButtonLabel="Go to Home"`, the
   assessment result footer, and all local `AssessmentEntry` state unchanged.
   The reset must affect only this assessment exit path; regular Sesh and
   Profile navigation should retain their current semantics.

2. Extend the focused assessment regression coverage in
   `src/features/sesh/components/assessment-entry.test.tsx` (or add a nearby
   route-focused test if the installed router test surface requires it). Mock
   the selected router reset method and exercise the existing real component
   flow: start from the assessment entry reached from Profile, complete a run,
   assert the assessment result copy and `Go to Home` action are present, press
   `Go to Home`, and assert the router targets Home. Add the route/stack
   assertion needed to prove that returning to Profile renders its default
   content and contains no assessment result; if a full Expo Router tree is
   not practical in Jest, use a small test navigator/route harness that models
   the Profile stack and verifies the assessment child is removed rather than
   merely asserting a redirect call.

3. Preserve or update existing router mocks and result-copy assertions so the
   test continues to demonstrate that result copy is available before leaving,
   and so no unrelated `MultiTrickSesh` navigation behavior changes.

## Files likely to change

- `src/features/sesh/components/assessment-entry.tsx` — reset the nested
  Profile route when the assessment wrap-up action is pressed.
- `src/features/sesh/components/assessment-entry.test.tsx` — regression
  coverage for assessment completion, Home navigation, and stale-route
  clearing; exact additions may be split into a route test under
  `src/app/profile/__tests__/` if that gives the router boundary stronger
  coverage.
- `src/app/profile/__tests__/index.test.tsx` — only if the route-level harness
  needs to verify that a subsequent Profile visit renders the default screen.

Do not change persistence models/providers, `MultiTrickSesh`’s generic wrap-up
contract, or the Profile screen’s product copy unless verification exposes a
direct regression caused by the reset.

## Test strategy

- Keep the existing assessment result-copy tests passing, including the
  promotion/held result distinctions.
- Add one end-to-end-in-component or route-harness regression for the exact
  sequence: Profile → Kentei assessment → completed run → `Go to Home` →
  Profile, asserting default Profile content and no assessment wrap-up.
- Assert the reset targets `/` and that the action is not triggered before the
  wrap-up button is pressed.
- Run the focused assessment/profile tests first while iterating.
