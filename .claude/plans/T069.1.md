# T069.1 — Establish the nested Tricks route and back convention

## Scope and convention decision

Make the per-trick goals destination a resource-scoped route at
`/tricks/[trickId]/goals`. Convert the current flat `src/app/tricks.tsx` route
into a `tricks/` route tree with a headerless stack so this screen (and the
remaining T069 destinations) have a real navigation parent.

The second layer inside a destination is **not** routed: `TrickGoalsScreen`'s
`list` and `add` are transient states of one per-trick goals screen and remain
local component state. Its Cancel/Save transitions return to `list`; only the
screen-level Back control returns to `/tricks`. T069.2 must apply the same rule
to a per-trick Notes route: Notes `list`/`add`/`edit` remain local steps, while
the per-trick Notes screen itself receives one real URL. This avoids URLs for
unsaved form state while giving each top-level Tricks destination browser and
native back semantics.

## Ordered implementation plan

1. Restructure the route files without changing the directory UI: move
   `src/app/tricks.tsx` to `src/app/tricks/index.tsx` and add
   `src/app/tricks/_layout.tsx` containing a headerless Expo Router `Stack`.
   Keep the existing profile/custom-trick/notes/goals/history derivations in
   the index route, but remove `goalsTrick` from its local state and from the
   T068 reset function. Change the directory's `goalsAction.onOpen` callback to
   `router.push({ pathname: '/tricks/[trickId]/goals', params: { trickId } })`.
   This preserves the generic `TrickDirectory` API and makes the visible Goals
   action produce the concrete URL.

2. Adapt T068 to the new navigator hierarchy. In `src/app/tricks/index.tsx`,
   subscribe the existing local-pseudo-screen reset to the parent tab navigator
   (rather than the new Tricks stack) so edit/delete/notes/all-goals/laced/new
   views still reset when Tricks is reselected. In
   `src/app/tricks/_layout.tsx`, listen for the active Tricks tab's `tabPress`
   event and replace the nested path with `/tricks`. Keep this route-reset
   behavior in the layout, which remains mounted while a child screen is open,
   and filter to the Tricks trigger so switching to another tab does not
   perform an unrelated replace. This is the reusable real-route convention:
   child destinations use the layout's tab reselect behavior; unconverted
   pseudo-screens retain their local reset until T069.2 moves them.

3. Add `src/app/tricks/[trickId]/goals.tsx` as the route adapter. Read the
   dynamic `trickId`, use `useCustomTricks` plus
   `createProfileDirectoryTricks(KENDAMA_KENTEI_TRICKS, tricks)` to resolve the
   current display name for both standard and custom tricks,
   and retain the onboarding guard. Render `TrickGoalsScreen` inside the same
   `Screen` edge treatment the old conditional branch used. Redirect an absent
   or invalid trick ID to `/tricks` instead of rendering an ambiguous screen.
   Pass an explicit route-owned `onBack` callback that replaces `/tricks`, so
   Back is deterministic even for a directly opened/deep-linked URL rather
   than relying on browser history or `router.back()`.

4. Update `src/features/goals/components/trick-goals-screen.tsx` only at its
   presentation boundary: rename the `onClose` contract to `onBack`, replace
   the list screen's `Close` button with clear Back-to-Tricks copy/control, and
   leave the goal list, add form, validation, persistence actions, and its
   local `list`/`add` state machine unchanged. The route layer owns path and
   parent navigation; this feature component remains reusable and has no
   Expo Router dependency beyond its existing practice links.

5. Add focused automated coverage alongside the new route tree. Create a
   route test under `src/app/tricks/__tests__/` that mocks local route params
   and router calls, verifies the standard/custom trick lookup feeds the right
   name, invalid IDs return to Tricks, and the screen-level Back action targets
   `/tricks`. Add a layout/navigation test that emits a Tricks `tabPress` and
   verifies an open child is replaced by `/tricks` while other tab presses are
   ignored. Add or extend a `TrickGoalsScreen` component test to protect the
   Back label and the retained local add → list Cancel/Save behavior. Update
   `src/features/tricks/components/trick-directory.test.tsx` only if the
   action wiring API changes; keep its existing count-label coverage intact.

6. Verify in increasing scope. Run the new focused Jest tests, then the full
   project sequence with `node .claude/scripts/verify.mjs`. Start this
   worktree's Expo web dev server (not a generic static server), navigate from
   `/tricks` to a trick's Goals, confirm the address is
   `/tricks/<id>/goals`, confirm Back returns to the directory, and confirm
   pressing the selected Tricks tab returns to the directory from that route.
   Repeat the same flow in iOS and Android, including the platform back control
   from the goals route and a Tricks-tab reselect, and check existing local
   Tricks pseudo-screens still obey T068 while T069.2 has not migrated them.

## Non-goals / follow-up

Do not route Goals `add` as `/add`, introduce persistence changes, or convert
Notes and the other pseudo-screens in this task. T069.2 owns those destinations
and must reuse the route-tree, explicit `onBack`, layout-level tab-reset, and
local-form-step conventions established here.
