# T076.2 — Apply and verify the reset contract across Sesh screens

## Good enough for this iteration

The web implementation has one verified Sesh-tab reset path: pressing the Sesh tab from the canonical single-trick completion screen, casual multi-trick setup/countdown/active/wrap-up screens, and assessment setup/countdown/active/wrap-up screens lands on `/sesh` and renders a fresh canonical Sesh picker. Existing flow-specific actions remain unchanged: single-trick reset/repeat behavior, casual multi-trick finish/cancel/back behavior, assessment cancel behavior, assessment practice-history origin, and assessment “Go to Home” dismissal to `/`.

Native validation, redesign of the Sesh flows, changes to persistent state, and changes to the meaning or ordering of other tabs are out of scope.

## Ordered implementation plan

1. **Reconfirm the T076.1 boundary before changing feature code.**
   - Treat `src/app/sesh/_layout.tsx` as the route-level authority: the parent tab listener filters for the declared Sesh tab key and replaces the nested route with `/sesh`.
   - Keep the web tab declaration in `src/components/app-tabs.web.tsx` and the five-link order unchanged.
   - Do not add navigation state, router handles, or reset flags to the profile, custom-trick, or practice-history providers.

2. **Add a focused route integration harness for all reachable Sesh surfaces.**
   - Extend `src/app/sesh/__tests__/layout.test.tsx` or add a colocated focused integration test that models the parent tab `tabPress` event and a route host capable of rendering `/sesh`, `/sesh/multi-trick`, and the assessment entry surface.
   - Make the harness assert the post-press route and the canonical Sesh picker marker, not merely that `router.replace('/sesh')` was called. Exercise the Sesh tab target from:
     - single-trick completion;
     - casual multi-trick selection/setup, first countdown, active practice, and wrap-up;
     - assessment flow picker/rank picker, first countdown, active practice, and assessment wrap-up.
   - Include an unrelated-tab press assertion so the reset listener remains scoped to Sesh.
   - If the assessment route cannot be rendered honestly beneath the Sesh stack because it is nested under Profile, keep its component-level screen in the existing assessment test and share only the tab-event/reset harness behavior; do not change the route hierarchy to make the test easier.

3. **Preserve and explicitly test direct actions while adding tab coverage.**
   - In `src/features/sesh/components/sesh.test.tsx`, retain focused coverage that a completed single-trick run records exactly one practice-history entry and that “Start another sesh” returns to the picker while “Repeat sesh” stays on the same trick flow.
   - In `src/features/sesh/components/multi-trick-sesh-entry.test.tsx`, retain coverage for selection back, first-countdown cancel, and wrap-up finish/cancel routing to `/sesh`, including the existing session count and fresh remount assertions.
   - In `src/features/sesh/components/assessment-entry.test.tsx`, retain coverage for first-countdown cancel returning to the assessment flow picker, wrap-up history records carrying `origin: 'assessment'`, and “Go to Home” calling `router.dismissTo('/')` exactly as before.
   - Add only the smallest test seam needed to inject or simulate the Sesh-tab press; direct completion callbacks must not be repurposed to implement tab behavior.

4. **Verify the web route behavior manually at the focused boundary.**
   - Run the Expo development server for this worktree and use the web surface, not a generic static file server.
   - From each listed screen, press the visible Sesh tab and confirm the canonical picker is rendered and stale local child state is gone. Check at least one setup/active path and each wrap-up path; use the automated harness for deterministic countdown/active transitions where manual timing is costly.
   - Confirm the Sesh tab still occupies its existing position and that Home, Tricks, Stats, and Profile semantics are untouched.

5. **Run proportional automated verification and inspect regressions.**
   - Run the focused Sesh/layout/component suites first.
   - Run `node .claude/scripts/verify.mjs` (or its equivalent four commands): Jest, lint, TypeScript, and web export.
   - Treat new warnings or route errors separately from the two documented benign warnings. Record native validation as deferred per `AGENTS.md`.

6. **Finish the ticket only after the exit criteria are demonstrated.**
   - Update `TASKS.md` and `TASKS_DONE.md` in the implementation commit according to the repository workflow; this planner must not mark the task done prematurely.
   - Keep the implementation focused to the reset contract and its verification. Defer any broader navigation abstraction, direct-practice lifecycle changes, and mobile hardening to their own tickets or explicitly authorized work.

## Expected implementation touch points

- `src/app/sesh/_layout.tsx` — preserve the T076.1 listener contract; change only if integration testing reveals a concrete route-boundary defect.
- `src/app/sesh/__tests__/layout.test.tsx` — route/tab reset integration coverage and canonical picker assertion.
- `src/features/sesh/components/sesh.test.tsx` — single-trick completion/history regression coverage if the existing test seam needs extension.
- `src/features/sesh/components/multi-trick-sesh-entry.test.tsx` — casual multi-trick route/reset coverage.
- `src/features/sesh/components/assessment-entry.test.tsx` — assessment wrap-up/cancel/history coverage and any minimal tab-press seam.
- `src/components/app-tabs.web.tsx` — inspect only; do not alter tab order or labels unless a failing focused web check proves the existing trigger is not the T076.1 target.

## Risks and constraints

- A Sesh tab press from `/profile/kentei-assessment` is a parent-tab navigation event while the assessment screen is Profile-nested; tests must model the real parent event rather than falsely treating the assessment as a child of `/sesh`.
- The route replacement must remount `src/app/sesh/index.tsx` so `Sesh` starts in `choosing`, while the profile assessment’s explicit `dismissTo('/')` remains a separate direct action.
- Practice-history writes are observable behavior, not incidental implementation detail: tab reset must not record, duplicate, or discard sessions.
