# T085.1 — Add automatic and custom text color to the theme model

## Scope confirmed

Model + persistence + `ResolvedTheme` derivation only. No UI work: `theme-color-picker.tsx`
stays untouched here (that control is T085.2's job) and no screen consumes `theme.text` yet
(that's T085.3). This plan still wires a reducer action + provider action creator for
`themeTextColor` (not just a bare field), because the exit criteria require reducer tests and
T085.2 will need a dispatch path to write/reset it independently of background/accent.

## Files touched, in order

### 1. `src/features/profile/model/user-profile.ts`

- Add `readonly themeTextColor?: string;` to `UserProfile`, right after `themeAccentColor`.
- Add a new action `{ readonly type: 'themeTextColorUpdated'; readonly themeTextColor?: string }`
  to `UserProfileAction`. Keep it separate from `themeColorsUpdated` rather than adding a third
  param to that action — `themeColorsUpdated`'s existing two-arg shape is exercised by
  `theme-color-picker.tsx` today, and T085.2's notes describe the text control resetting
  independently, which a dedicated action supports directly without touching the
  background/accent call sites.
- Add the reducer case:
  ```ts
  case 'themeTextColorUpdated':
    return { ...state, themeTextColor: action.themeTextColor };
  ```
  (mirrors `streakThresholdUpdated`'s unconditional-overwrite style, not `themeColorsUpdated`'s
  two-field style, since this is a single field.)

### 2. `src/features/profile/persistence/user-profile-persistence.ts`

- Destructure `themeTextColor` out of the parsed record alongside `themeBackgroundColor`/
  `themeAccentColor`.
- Validate with the existing `isThemeColor` helper (already generic — no new validation
  function needed): `if (themeTextColor !== undefined && !isThemeColor(themeTextColor)) return undefined;`
- Add a `themeTextColorField` spread (same pattern as `themeBackgroundColorField`) and include it
  in both the `hasCompletedOnboarding` and not-onboarded return branches.
- No document-version bump — per AGENTS.md's provisional-v1 policy, this is an in-place v1 shape
  change; old persisted documents without the field simply parse with `themeTextColor: undefined`.

### 3. `src/features/profile/state/user-profile-provider.tsx`

- Add `setThemeTextColor: (themeTextColor: string | undefined) => void` to `UserProfileActions`.
- Implement with `useCallback` dispatching `themeTextColorUpdated`, add it to the `actions` memo
  object and to that `useMemo`'s dependency array (alphabetical, matching existing style).

### 4. `src/features/profile/state/use-resolved-theme.ts`

Refactor so the derivation logic is a plain, independently-testable function, and the hook is a
thin wrapper — matches how the rest of this codebase separates pure logic from hook plumbing.

- Add `readonly text: string;` to `ResolvedTheme`.
- Add a local `ThemeColorPreferences` interface with the three optional fields (avoids importing
  the full `UserProfile` type just for three fields, and keeps this module decoupled from the
  profile shape growing further).
- Add `deriveAutomaticTextColor(background: string, accent: string): string`: picks whichever of
  `AppColors.ink` / `AppColors.cream` maximizes the *minimum* of its contrast ratio (via
  `contrastRatio` from `@/shared/color/contrast`) against both the resolved background and the
  resolved accent. Using both inputs (not just background) is deliberate: text can sit on accent
  surfaces (buttons, badges) too, and the min-of-both approach picks the readable choice for
  either. Verified numerically against current defaults: for the default sage/yellow pair, ink
  scores min≈8.1 vs cream's min≈1.2 (picks ink, matching today's fixed color); for a synthetic
  dark pair (`#101418`/`#1a1f24`), cream scores min≈16.0 vs ink's min≈1.3 (picks cream).
- Export a pure `resolveTheme(preferences: ThemeColorPreferences): ResolvedTheme` that computes
  `background`/`accent` (existing fallback logic, unchanged) and `text` (custom
  `themeTextColor` if set, else `deriveAutomaticTextColor(background, accent)`).
- `useResolvedTheme()` becomes `return resolveTheme(useUserProfile());`.
- Update the module doc comment to mention the text field and its derivation, consistent with the
  existing comment's detail level.

`AppThemeProvider` (`src/features/profile/components/app-theme-provider.tsx`) needs no change —
it already forwards the full resolved theme object through `theme` prop; `theme.text` becomes
available automatically. Do not wire it into any screen here (T085.3).

## Order rationale

Model (1) before persistence (2) before provider (3) — persistence and the provider both import
the `UserProfile` type/action shape. `use-resolved-theme.ts` (4) depends on nothing from 1–3
except the field name, so it could technically go first, but doing it last keeps the "reducer
round-trips" and "resolved theme derivation" concerns cleanly separated while writing tests
alongside each step.

## Tests

### `src/features/profile/model/user-profile.test.ts`

Add tests mirroring the existing `themeColorsUpdated` tests just below them:
- Dispatching `themeTextColorUpdated` sets `themeTextColor`.
- Dispatching it again with `themeTextColor: undefined` clears it.
- Setting it doesn't clobber unrelated fields (e.g. `selectedTrickIds`), same style as the
  existing "does not clobber unrelated profile fields" test.
- An unrelated action (e.g. `selectedTrickToggled`) leaves an existing `themeTextColor` untouched.

### `src/features/profile/persistence/user-profile-persistence.test.ts`

Add tests mirroring the existing theme-color tests:
- Round-trips a profile with `themeTextColor` set alongside background/accent (serialize →
  deserialize → `toEqual`).
- `deserializeUserProfile` leaves `themeTextColor` `undefined` when absent from a valid document.
- `it.each` malformed-value rejection using the same malformed-hex fixture list already used for
  `themeBackgroundColor`/`themeAccentColor` (`['not-a-color', '#fff', '#1234567', '#gggggg', '']`).
- Extend or add a `loadUserProfile` full-hydration-path test analogous to the existing
  "loads a valid persisted profile with theme colors through the full hydration path" test, with
  `themeTextColor` included.

### `src/features/profile/state/use-resolved-theme.test.ts` (new file)

Test the exported pure `resolveTheme` function directly — no React rendering needed, so this
stays a plain `describe`/`it` file with no `react-test-renderer` or provider setup:
- Returns the custom `themeTextColor` verbatim when set, regardless of background/accent.
- Light-background case: `resolveTheme({})` (using the default sage/yellow fallbacks) resolves
  `text` to `AppColors.ink`.
- Dark-background case: `resolveTheme({ themeBackgroundColor: '#101418', themeAccentColor: '#1a1f24' })`
  resolves `text` to `AppColors.cream`.
- (Optional, cheap to include) one assertion that `background`/`accent` still fall back to
  `AppColors.sage`/`AppColors.yellow` when unset, guarding the existing behavior this refactor
  must not change.
