# T144 — Show which trick each goal belongs to, directly on the goal card

## Goal (exit criteria recap)

- `TrickGoalsScreen` (single trick's goals): show a heading "`<Trick name> goals`" grouping the
  goal cards, but only when that trick has more than one goal. Currently there is no such
  heading — only the page-level `PageTitle` (`DisplayTitle`) showing the bare trick name, which
  is unrelated to this per-list heading and stays as-is.
- `AllTrickGoalsScreen` (all tricks with goals): the existing per-trick `SectionTitle` currently
  always renders `{group.trickName}` (no "goals" suffix) regardless of goal count. Change its
  text to "`<Trick name> goals`" and gate its rendering on `group.progress.length > 1`.
- `yarn test --runInBand` passes, including new/updated cases for single-goal (no heading) and
  multi-goal (heading present, correct name) on both screens.

## Files

- `src/features/goals/components/trick-goals-screen.tsx`
- `src/features/goals/components/all-trick-goals-screen.tsx`
- `src/features/goals/components/trick-goals-screen.test.tsx`
- `src/features/goals/components/all-trick-goals-screen.test.tsx`

No model/reducer changes needed. `TrickGoalGroup.progress` (from `selectGoalProgressByTrick` in
`src/features/goals/model/goal.ts`) already carries everything required (`trickName`,
`progress.length`); `TrickGoalsScreen` already computes `trickGoals` (via `selectGoalsForTrick`)
and has `trickName` as a prop. Nothing here touches persistence or the goal domain boundary.

## Step 1 — `AllTrickGoalsScreen`: make `SectionTitle` conditional and update its text

In `all-trick-goals-screen.tsx`, inside the `groups.map((group) => ...)` block (~line 93-97):

```tsx
<Section key={group.trickId}>
  {group.progress.length > 1 ? (
    <SectionHeader>
      <SectionTitle>{`${group.trickName} goals`}</SectionTitle>
    </SectionHeader>
  ) : null}
  <GoalList>
    ...
```

Important: use a single interpolated template-literal string as the child
(`` {`${group.trickName} goals`} ``), not `{group.trickName} goals` as two JSX children. The
test helper `findText` in both test files matches on exact `node.props.children` equality
against one string, so a two-child JSX text node (`["Big Cup", " goals"]`) would not match
`findText(root, 'Big Cup goals')`. Keep this consistent with how `Introduction` in the same file
already builds its string via a single template-literal expression.

`SectionHeader` currently has `justify-content: space-between` for a title plus (currently
nonexistent) trailing content — leave that styling as-is since nothing else occupies the row;
it degrades gracefully with a single child.

## Step 2 — `TrickGoalsScreen`: add the equivalent heading

In `trick-goals-screen.tsx`, add a heading directly above `<GoalList>` (~line 69), gated on
`trickGoals.length > 1`:

```tsx
{trickGoals.length > 1 ? (
  <SectionTitle>{`${trickName} goals`}</SectionTitle>
) : null}
<GoalList>
  ...
```

Add a new styled component `SectionTitle` in this file matching `AllTrickGoalsScreen`'s
`SectionTitle` style (`color: ${AppColors.ink}; font-size: 18px; font-weight: 900;`) — don't
import it from `all-trick-goals-screen.tsx` (that file already imports `GoalRow`/`GoalForm`
*from* `trick-goals-screen.tsx`; importing back the other way would create a cycle). Duplicating
this small styled-text definition in both files is consistent with how each screen already
defines its own `Scroll`/`Content`/`PageTitle`/etc. rather than sharing a shared-styles module.

Do not touch the existing `PageTitle`/`Eyebrow`/`Introduction` block — that's the page-level
identity ("Goals" / trick name / goal count sentence), separate from this new per-list grouping
heading placed just above the cards.

## Step 3 — Update `all-trick-goals-screen.test.tsx`

The existing test `'lists goals from multiple tricks with per-goal progress, achieved and
unachieved rendered distinguishably'` (~line 114) adds exactly one goal per trick (trick A and
trick B each get one goal via `add-goal-a` / `add-goal-b`), then asserts:

```ts
expect(findText(root, 'Big Cup')).toHaveLength(1);
expect(findText(root, 'Stall')).toHaveLength(1);
```

With the new gating, neither trick has >1 goal, so the `SectionTitle` heading will no longer
render literal `'Big Cup'`/`'Stall'` text nodes — these two assertions will start failing
(nothing produces those exact strings anymore, since the only remaining `trickName`-derived
text was this heading). Two changes needed here:

1. Add a helper to add a second goal to trick A (e.g. a new `add-goal-a2` `Pressable` in
   `Harness` calling `addGoal({ kind: 'time', trickId: TRICK_A.id, trickName: TRICK_A.name,
   targetMinutes: 10 })`, mirroring the existing count-goal press buttons) so trick A ends up
   with 2 goals and trick B stays at 1. Press it in this test before the assertions.
2. Replace the two failing assertions with:
   - `expect(findText(root, 'Big Cup goals')).toHaveLength(1);` (trick A, 2 goals → heading
     shown)
   - `expect(findText(root, 'Stall')).toHaveLength(0);` and
     `expect(findText(root, 'Stall goals')).toHaveLength(0);` (trick B, 1 goal → no heading at
     all, in either form)

   This keeps the test's original assertion intent (per-goal progress/achieved rendering
   unaffected) while also covering the new heading behavior for both the >1 and ==1 cases in one
   pass. Alternatively, add these two as fully separate `it(...)` blocks below the existing test
   if you'd rather keep that test's scope narrow to progress/achieved-badge behavior only and not
   further overload it — either is fine; prefer separate `it` blocks if the existing test's name
   ("...achieved and unachieved rendered distinguishably") no longer accurately describes what it
   covers once the second goal is added.

Also check `'shows the empty state when there are no goals'` (~line 141) and the goal-creation
test (~line 201) for any assertions that would collide with the new `"<name> goals"` string —
skim them once more while editing to confirm they don't currently assert on `trickName` alone in
a way that would now spuriously match or fail (they don't appear to based on the excerpt read,
but confirm before finishing).

## Notes / risks

- The two screens' `SectionTitle`-equivalents are now near-duplicates in text logic
  (`${trickName} goals` gated on `count > 1`) but live in genuinely different components with
  different data shapes (`TrickGoalsScreen` has one trick's flat `trickGoals` array;
  `AllTrickGoalsScreen` has an array of `TrickGoalGroup`). Don't over-abstract this into a shared
  component for a one-line conditional — matches the existing duplication level in this feature
  (e.g. `Scroll`/`Content`/`PageTitle` are already duplicated per-screen).
- Do not confuse this task with `PageTitle` on `TrickGoalsScreen`, which already shows the bare
  trick name unconditionally as the page's overall title — that is out of scope and must not be
  changed or removed.
- `GoalRow`/`GoalForm` are imported by `all-trick-goals-screen.tsx` *from*
  `trick-goals-screen.tsx`. Keep the new `SectionTitle` in `trick-goals-screen.tsx` local
  (not exported/reused by the other file) to avoid a temptation to "share" it and create an
  import cycle.
