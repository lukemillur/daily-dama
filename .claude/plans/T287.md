# T287 plan: honest native feedback unavailable state and exit

## Findings (verified against branch)
- `getSupabaseClient()` (`src/shared/supabase/supabase-client.ts`) returns `null` whenever `Platform.OS !== 'web'`, so `submitFeedback` always returns `failed`; `FeedbackScreen` shows generic "try again" copy and the unsubmitted form has no Back action (root layout is `Slot`, no native header).
- `src/app/feedback.tsx` is a thin route rendering `<FeedbackScreen />`. Profile links to it via `router.push("/feedback")`; the submitted state's exit is `router.push('/app/profile')` (reuse this).
- IMPORTANT: jest-expo defaults `Platform.OS` to `'ios'`. The existing `feedback-screen.test.tsx` renders `<FeedbackScreen />` under that default and treats it as the working form. If `FeedbackScreen` itself branched on `Platform.OS`, those web tests would break. "Existing web tests pass unchanged" therefore forces the platform decision to live OUTSIDE `FeedbackScreen`.
- Native rebuild: NOT needed. JS-only change; no native dependency, no config plugin or app.json change. Existing dev client (`com.dailydama.app`) with Metro is enough.

## Design
Select by platform in the route; keep `FeedbackScreen` and `submit-feedback.ts` untouched.

1. New `src/features/feedback/components/feedback-unavailable-screen.tsx` exporting `FeedbackUnavailableScreen`:
   - `Screen align="center"` + `Centered`-style layout mirroring the submitted state in `feedback-screen.tsx` (Eyebrow "Feedback", `DisplayTitle` e.g. "Feedback isn't available in the app yet", `BodyText` explaining that sending feedback currently works from the web version at dailydama.com and the app does not send it; no promise of delivery).
   - One `Button` `accessibilityLabel="Back to Profile" fill`, `onPress={() => router.push('/app/profile')}` via `useRouter` from `expo-router`.
   - No TextField, no Send button, no import of `submitFeedback`/`getSupabaseClient` -- "cannot submit" is structural, not a disabled flag.
   - Do not hardcode the URL if the repo already has a canonical site-URL constant; otherwise phrase as "the web version of Daily Dama" (do not add personal info; check DEPLOYMENT_HANDOFF.md before naming a domain).
   - Duplicating the small `Centered`/title styled pieces is acceptable (first near-copy); do not refactor the submitted state.
2. Edit `src/app/feedback.tsx`: `Platform.OS === 'web' ? <FeedbackScreen /> : <FeedbackUnavailableScreen />`, evaluated at render time (import `Platform` from `react-native`). Comment why: native has no Supabase client (`getSupabaseClient` guard), so the form cannot succeed; revisit when native transport lands (separate ticket). Do not enable native Supabase or add a transport.
3. Docs: add a one-line note to `ARCHITECTURE.md` (feedback section if one exists, else near the native guest-only/Supabase note) that native shows an unavailable state. Update TASKS.md status per the claim protocol on close.
