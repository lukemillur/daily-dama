# T316 plan: Android Tricks create and overflow actions

## Verified facts
- `src/app/app/tricks/index.tsx` `TricksNativeHeader` (non-web) sets `headerSearchBarOptions` and `unstable_headerRightItems`. Installed expo-router 57.0.29 types (`build/react-navigation/native-stack/types.d.ts`) mark `unstable_headerRightItems` `@platform ios`; `headerRight?: (props: NativeStackHeaderItemProps) => ReactNode` is the cross-platform API and "will be overridden by headerRightItems on iOS". So setting both is safe: iOS keeps SF-symbol items, Android uses `headerRight`.
- `useHeaderConfigProps.js` supports header search on any platform where react-native-screens reports `isSearchBarAvailableForCurrentPlatform` (Android supported in RNS 4.26.2). Search wiring is already platform-neutral, so likely works unchanged. Verify on the emulator; do not assume. If Android search is not shown or filtering fails, fix inside this ticket (in scope: "Search filters the library").
- `TrickDirectory` already receives `nativeHeader` and `search` when `Platform.OS !== 'web'`, and the in-list header actions are removed, so Android currently has no entry points. `/app/tricks/custom/new` hosts `ChoiceScreen` (standalone/sequence). `goals`, `notes`, `laced` routes exist.
- Repo has no RN `<Modal>` precedent for menus (overlays are absolute-fill Views). No existing menu component. Existing test: `src/app/app/tricks/__tests__/tricks-index-route.test.tsx` (mocks `Stack.Screen` to capture options; uses `jest.replaceProperty(Platform,'OS',...)`).
- The worktree has no node_modules; run tests from a checkout with deps (or `yarn install` per repo practice) and do not touch the owner's main checkout.

## Design
Keep it bounded: add a small header-actions component for Android, leave the iOS branch and web untouched.

1. New file `src/features/tricks/components/tricks-header-actions.tsx` (feature-owned, not in `src/app`): `TricksHeaderActions({ onDefine, onOpenGoals, onOpenNotes, onOpenLaced })`, rendered as `headerRight`. Contents:
   - A `+` Pressable: `accessibilityRole="button"`, `accessibilityLabel="Define new trick"`, min 48x48 touch target (`hitSlop` as needed), calls `onDefine`.
   - An `...` (ellipsis glyph text, no new icon dependency) Pressable: label "More trick actions", `accessibilityState={{ expanded }}`, toggles a menu.
   - Menu: RN `Modal` (`transparent`, `animationType="fade"`, `onRequestClose={close}` so Android Back closes the menu instead of popping Tricks), full-screen backdrop Pressable (label "Close menu") plus a top-right anchored panel with three items (`accessibilityRole="menuitem"` or `button`, 48px min height): Trick goals, Trick notes, Laced tricks. Selecting an item closes the menu then calls the handler. Use theme colors via `useResolvedTheme`/`deriveNestedHeaderColors` and styled-components, consistent with the app's flat, ink-bordered look; no gradients/glass.
   - Menu open state is local `useState` in this component (UI-only state, not persisted).
   - Because `headerRight` is rendered by the navigator, keep the component self-contained (it must not depend on parent state); it gets router callbacks via closure.
2. `TricksNativeHeader` in `index.tsx`: add `headerRight: () => <TricksHeaderActions .../>` only when `Platform.OS === 'android'` (keep `unstable_headerRightItems` for iOS; pass `headerRight: undefined` elsewhere). Extract a shared `routes`/handlers object so iOS items and Android component use the same push targets (`/app/tricks/custom/new`, `/goals`, `/notes`, `/laced`). Do not change the T312.3-T312.5 row styling area; edit only `TricksNativeHeader`.
3. Update `deriveTricksIndexScreenOptions` only if Android large-title/transparent header styling hides `headerRight` (check on device; `headerLargeTitleEnabled` is iOS-only, `headerStyle: transparent` on Android may need a solid background). Make a platform-conditional fix there, with its test in `nested-stack-headers.test.tsx`, if observed.
4. Document in `ARCHITECTURE.md` (navigation/header section, if it describes the Tricks header) the iOS/Android split; keep it to one or two lines.

## Risks / notes
- On Android `headerRight` plus the transparent header style could clip or lose contrast; confirm visually.
- Modal on Android draws over the status bar; set `statusBarTranslucent` so the anchor math is consistent, and position the panel under the header using `useSafeAreaInsets().top + header height` (or `useHeaderHeight` from expo-router if available) rather than hardcoded numbers.
- Android search may require tapping the search icon in the header (collapsed by default); acceptable if filtering and clearing work. `hideWhenScrolling: false` is already set.
- Do not add a dependency (e.g. a popup-menu lib). If emulator becomes unresponsive, record the criterion as unverified instead of calling it passed.
- Update TASKS.md status/closure in the closing commit per protocol.
