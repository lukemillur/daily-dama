# T290 plan: fixed bottom tab bar on native

## Verified starting state
- `src/components/app-tabs.tsx` (native) uses `NativeTabs` from `expo-router/unstable-native-tabs`; colors come from `Colors[useColorScheme()]` (system appearance) -- that is the mismatch to fix.
- `src/components/app-tabs.web.tsx` is a separate file chosen by extension. Do NOT touch it or its test (`app-tabs.web.test.tsx`); that is how "web unchanged / 320 px fit" is satisfied.
- `AppTabs` is mounted in `src/app/app/_layout.tsx` inside `AppThemeProvider`, so `useResolvedTheme()` (saved app theme: `background`, `text`, `textMuted`, `accent`) is available there.
- `expo-symbols` is NOT in package.json, but yarn.lock already resolves `expo-symbols@^57.0.3` (transitive via expo-router), as does `sf-symbols-typescript` (currently imported type-only without being a direct dep). `node_modules` is absent in the planning worktree; run `yarn install` first.
- `src/app/app/profile/_layout.tsx` adds a `tabPress` listener through `navigation.getParent()`; JS `Tabs` is react-navigation based and emits `tabPress`, so this keeps working. Re-verify on the simulator (tap Profile while inside a Profile sub-route).
- Screens use `Screen edges={["top","left","right"]}` (no bottom edge), which is correct for a JS tab bar: the bar owns the bottom safe-area inset and the scene sits above it, so nothing scrolls underneath. Do not add bottom edges.
- `BottomTabInset` (src/constants/theme.ts) is used only by `src/app/app/profile/index.tsx` (`paddingBottom: 120 + BottomTabInset`).
