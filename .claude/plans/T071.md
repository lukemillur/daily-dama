# T071 — Make multi-trick Sesh entry prominent

## Goal

Make the multi-trick practice route a clearly identifiable, accessible primary option on the Sesh home picker without changing the existing single-trick format-selection flow or the `/sesh/multi-trick` setup route.

## Good enough for this iteration

- The Sesh home presents a dedicated multi-trick action with purpose-specific visible copy and an accessible link semantic.
- Activating the action targets `/sesh/multi-trick` through the existing Expo Router `Link`.
- Timed and Open-ended single-trick controls remain rendered and usable at the repository’s supported narrow web width (320 px).
- Focused component tests protect the entry action, route target, retained controls, and narrow-width-safe layout assumptions.

Defer changes to the multi-trick setup wizard, session state, persistence, tab navigation, mobile hardening, and decorative illustration or animation.

## Implementation plan

1. **Refactor the `TrickPicker` entry hierarchy in `src/features/sesh/components/sesh.tsx`.**
   - Replace the current `MultiTrickLink` text-only treatment with a dedicated route option placed before the single-trick `Practice format` controls, preserving the current order in which users encounter both modes.
   - Keep the existing `Link href="/sesh/multi-trick" asChild` navigation contract and give its child an explicit `accessibilityRole="link"` plus a stable, descriptive accessibility label if needed.
   - Use dedicated copy that names the action and its outcome (for example, “Practice several tricks” with a short supporting line), rather than relying on the current conversational “Or…” sentence. Avoid a generic dashboard card; style it as a purposeful Sesh mode/action using the existing ink, yellow, paper, border, spacing, and button/choice conventions.
   - Ensure the action has a sufficiently large press target and its text wraps naturally at 320 px. Do not alter the Timed/Open-ended state model, duration/target inputs, personal-best controls, or single-trick selection behavior.
   - Remove the obsolete `MultiTrickLink` styling and add narrowly named styles for the new treatment only if the existing shared `Button`/choice primitives cannot express the hierarchy cleanly.

2. **Extend `src/features/sesh/components/sesh.test.tsx` with focused Sesh-home coverage.**
   - Reuse the existing provider-backed `mountSesh` test setup used for the plain picker and add a test that renders the normal Sesh home, finds the dedicated multi-trick action by its accessibility label/role, asserts its dedicated visible copy, and verifies its `href` is exactly `/sesh/multi-trick`.
   - Invoke the action’s press handler (or verify the Link child’s route contract in the same way existing route component tests inspect links) so the test proves the identifiable action is wired to the existing route rather than only checking text.
   - Assert that the same render still contains `Practice format`, `Timed`, and `Open-ended`, and that the existing duration control remains present. This protects single-trick access while the visual hierarchy changes.
   - If the implementation adds a width-sensitive layout branch or changes horizontal grouping, add a targeted narrow-width assertion using the project’s existing React Native window-dimension mocking pattern; otherwise keep the narrow-width criterion covered by the stable stacked/flexible styles and the test’s retained-control assertions rather than introducing a brittle pixel snapshot.

3. **Run proportional verification and inspect the diff.**
   - Run the focused Sesh component test first, then `yarn test --runInBand`, `yarn lint`, `yarn tsc --noEmit`, and `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export` (or the repository verification wrapper).
   - Confirm no new warnings or route errors appear, and manually inspect the Sesh home in the Expo web development server at 320 px if the implementation changes layout beyond simple vertical flow. Do not use a generic static file server for this route.
   - Record any native validation as deferred under the repository’s active web-only platform scope.

4. **Close the ticket in the implementation commit.**
   - After all exit criteria pass, move T071 from `TASKS.md` to `TASKS_DONE.md` in the same focused implementation commit, following the repository workflow. Remove this durable plan only as part of the implementation handoff’s normal cleanup, not while planning.

## Expected files

- `src/features/sesh/components/sesh.tsx` — replace and style the multi-trick entry action.
- `src/features/sesh/components/sesh.test.tsx` — test accessibility, dedicated copy, route target, and retained single-trick controls.
- `TASKS.md` / `TASKS_DONE.md` — workflow bookkeeping in the later implementation commit.

## Risks and constraints

- `Link asChild` must continue to receive a single pressable/link-compatible child; avoid nesting a `Pressable` inside another interactive element.
- The action should remain a normal route link, not a callback that imperatively pushes navigation, so the web `href` and accessibility semantics stay inspectable.
- The supported web navigation already fits 320 px; do not create a side-by-side mode layout that forces the new action or the two single-trick format controls below an unusable width.
- This ticket does not authorize changes to mobile verification or native project configuration.
