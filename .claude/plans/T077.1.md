# T077.1 — Exit direct-practice wrap-up to Sesh home

## Goal

When a Sesh is entered through a direct-practice link (`trickId` plus `mode=practice`), retain the preselected trick and quick-start presentation for that initial entry only. After the completed run's “Start another sesh” action, render the canonical Sesh home picker, and ensure pressing the Sesh tab still resets any nested route/query state to that same picker.

## Ordered implementation plan

1. Update `src/features/sesh/components/sesh.tsx` to separate initial quick-start entry from post-completion choosing state.
   - Keep the existing `quickStart` prop and validated preferred-trick gate so direct-practice links still open on the requested trick and plain `/sesh` visits still use `TrickPicker`.
   - Add the smallest local, non-persisted consumed/active flag initialized from `quickStart`; use that flag when deciding whether the `choosing` state renders `QuickStart`.
   - In the existing `onReset` callback used by `CompletedSesh`’s “Start another sesh” action, clear the quick-start flag before dispatching `seshReset`, while preserving the existing celebration/goal cleanup.
   - Leave `onRepeat` unchanged: “Repeat sesh” is intentionally the same trick and plan, whereas “Start another sesh” exits the direct-practice entry context. Do not change the Sesh reducer, practice-history schema, or `lastSesh` persistence contract.

2. Extend the Sesh route/component regression coverage for the direct-practice lifecycle.
   - Build on the existing quick-start tests in `src/features/sesh/components/sesh.test.tsx` to start a direct-practice Sesh, drive it through countdown/active/completion with the established test helpers and fake timers, press “Start another sesh,” and assert the full Sesh home picker (format controls and the available trick list) is rendered instead of “Ready when you are.”
   - Add or extend an app-level route harness, likely in `src/app/sesh/__tests__/layout.test.tsx`, so the same scenario represents a `/sesh?trickId=...&mode=practice` entry and then verifies the Sesh tab’s existing `router.replace('/sesh')` behavior renders the canonical picker without a route/query lock. Reuse the established mocked tab-navigation and route-host patterns rather than introducing a second navigation abstraction.
   - Keep assertions mechanical and scoped to this behavior: initial direct entry is quick-start, completion exit is the normal picker, and a subsequent Sesh-tab press remains canonical. Preserve existing plain-visit and nested-route reset coverage.

3. Verify the focused behavior and web baseline.
   - Run the focused Sesh and Sesh-layout Jest tests, then run `yarn lint` and `yarn tsc --noEmit`.
   - Run `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export` (or the repository verification wrapper if convenient) to confirm the route/query change remains exportable.
   - Do not perform iOS or Android validation; native hardening is explicitly deferred for this project iteration.

## Scope and assumptions

- The route remains `/sesh`; no new route or persistence field is needed. Consuming quick-start in the mounted Sesh component is sufficient to make the post-completion picker usable, while the existing Sesh layout listener clears nested route/query state when the tab is pressed.
- T077.2 owns exposing timed/open-ended and duration/target customization before a direct-practice run. This task only changes the post-completion destination and must not redesign `QuickStart`.
- Existing completion recording, `lastSesh` updates, stats snapshots, and reducer transitions remain unchanged.
