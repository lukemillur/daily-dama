# T292 plan: native start screen

## Findings (verified in current code)
- `src/app/index.tsx` renders `LandingPage` on every platform and calls `useRedirectOnboardedVisitorHome()`. Native has no separate path today.
- Guest onboarding is NOT a route. `src/app/app/home.tsx` renders `<KenteiOnboarding />` when `!profile.hasCompletedOnboarding`. So "Get started" = navigate to `/app/home`; no new onboarding route is needed.
- `useCachedOnboardingStatus` (`src/features/landing/state/use-cached-onboarding-status.ts`) on native starts as `DEFAULT_STATUS` (not onboarded) and updates after one async `AsyncStorage.getItem`. Reusing it as-is would flash the start screen for returning users before redirecting. A distinct "loading" state is required.
- Native has no "exit to landing" link (only `app-tabs.web.tsx` uses `LANDING_ARRIVAL_*`), so the in-app-arrival param is irrelevant natively.
- Native is guest-only (no Supabase client), so onboarding status from the guest-scoped key is authoritative.
- Theme: `DefaultAppThemeProvider` (fixed palette) wraps the root. `CachedAppThemeProvider` (auth route group precedent) resolves the cached guest theme and has a native AsyncStorage path. `Screen` reads `theme.background`; `Button` reads `theme.buttonBackground*`; `DisplayTitle`/`BodyText` read theme text colors.

## Design
Keep one route file; split by platform at the component level (no conditional hooks):
`RootRoute` -> `Platform.OS === 'web' ? <WebLandingRoute/> : <NativeStartRoute/>`.
`WebLandingRoute` is the current body verbatim (Head tags + redirect hook + LandingPage). Web behaviour must be byte-for-byte unchanged.

New feature dir `src/features/native-start/` (do not put it in `features/landing`, which is web marketing):
1. `model/resolve-native-start-route.ts` - pure function:
   `type NativeStartDecision = 'loading' | 'redirect-home' | 'show-start'`
   `resolveNativeStartDecision(status: CachedOnboardingStatus | undefined)`:
   `undefined` -> `loading`; `hasCompletedOnboarding && kenteiRank !== undefined` -> `redirect-home`; else `show-start`.
   (Same completeness rule as `useRedirectOnboardedVisitorHome` / `useRequireOnboarding`.)
2. `state/use-native-onboarding-status.ts` - one AsyncStorage read of the guest-scoped key via `readCachedOnboardingStatus`, returning `CachedOnboardingStatus | undefined` (`undefined` until resolved; cancel flag on unmount). Reuse `physicalKey(GUEST_IDENTITY, USER_PROFILE_STORAGE_KEY)`. Do not change the public shape of `useCachedOnboardingStatus` (web + landing CTAs depend on it). If the key constant is duplicated a third time, export it from `read-cached-onboarding-status.ts` and use it in all three rather than copying again. Read rejection must resolve to the default (not onboarded) status rather than hanging on `loading`.
3. `state/use-native-start-route.ts` - composes (2)+(1); `useEffect` calls `router.replace('/app/home')` on `redirect-home`; returns the decision.
4. `components/native-start-screen.tsx` - wrapped in `CachedAppThemeProvider`; `Screen` (centered column), `DisplayTitle` "Daily Dama" wordmark (text wordmark; T293 owns any splash art), short tagline, and an actions container (a vertical `gap` column) holding a single `Button` "Get started" -> `router.push`/`replace('/app/home')` (use `replace` so back cannot return to Start). Do NOT add a Sign in button; the column layout leaves room for T295's second action. Use theme tokens (no hardcoded colors beyond `AppColors` already used elsewhere) so it follows the app theme. Accessibility: button has role and label; wordmark `accessibilityRole="header"`.
5. `components/native-start-route.tsx` - `loading` and `redirect-home` render `null` (the existing `AnimatedSplashOverlay` covers first frames; a blank for one AsyncStorage read is acceptable and avoids a flash); `show-start` renders the screen.

## Risks
- Flash/blank: handled via the explicit `loading` state; verify on simulator that relaunch does not show Start for even one frame (splash overlay should cover it).
- Do not touch `useCachedOnboardingStatus` semantics - web prerender relies on its hydration gate.
- A user who abandons onboarding midway sees Start again on relaunch; acceptable (Get started resumes at Home onboarding).
