# T032 — Prevent onboarding seed data from immediately promoting the assessed rank

## Root cause (confirmed against current code)

`getSeedLacedTrickIds` in `src/features/onboarding/model/kentei-assessment.ts` marks every trick
**below the assessment's entrance rank (`startingRank`)** as seeded/laced, then unions that with
`landedTrickIds` (tricks actually landed during assessment):

```ts
export function getSeedLacedTrickIds(
  startingRank: number,
  landedTrickIds: readonly string[],
): readonly string[] {
  const belowStartingRank = KENDAMA_KENTEI_TRICKS.filter(
    (trick) => trick.kenteiRank < startingRank,
  ).map((trick) => trick.id);
  return Array.from(new Set([...belowStartingRank, ...landedTrickIds]));
}
```

It's called from `src/features/onboarding/components/kentei-onboarding.tsx` (line 52):

```ts
const lacedTrickIds = getSeedLacedTrickIds(state.startingRank, state.landedTrickIds);
completeOnboarding(state.rank, state.selectedTrickIds, lacedTrickIds);
```

`startingRank` is the entrance rank for the chosen level (e.g. Advanced → 4), fixed at
`levelSelected` and carried unchanged through the whole assessment state machine
(`kentei-assessment.ts`, `assessing`/`rankReveal`/`selecting` states). `state.rank` is the
**final resolved rank** — it can end up *lower* than `startingRank` when the very first trick of
the entrance rank is failed (`trickNotLanded` with `isFirstTrickInRank` decrements `rank` by one,
see lines 79–86 of `kentei-assessment.ts`), and in that path `landedTrickIds` is empty for that
rank because nothing in it was ever tested.

Concretely: enter at Rank 4 (`startingRank = 4`), fail the very first assessment trick →
`state.rank = 3`, `state.landedTrickIds = []`. The current seed call
`getSeedLacedTrickIds(4, [])` includes every trick with `kenteiRank < 4`, i.e. **all of Rank 3's
tricks**, purely on the "assumed known below the entrance rank" heuristic — even though Rank 3 is
the actual assessed result, never verified, and is exactly the rank the user is supposed to still
be working toward.

Those seeded IDs land in `manuallyUnlockedTrickIds` via `userProfileReducer`'s
`onboardingCompleted` case (`src/features/profile/model/user-profile.ts`), which is exactly the
"effective laced" input `KenteiRankAutoPromotion` (`src/features/profile/state/kentei-rank-auto-promotion.tsx`)
feeds into `selectPromotedKenteiRank` / `isKenteiRankComplete`
(`src/features/tricks/model/trick-directory.ts`). Since Rank 3 now reads as fully laced,
`selectPromotedKenteiRank(3, ...)` immediately returns 4, and the effect in
`KenteiRankAutoPromotion` calls `advanceKenteiRank(4)` on the very first render after onboarding —
an unearned promotion one rank past the assessed result.

The fix is narrow: the "assume everything below is already known" boundary must be the **final
resolved rank**, not the assessment's entrance rank. `landedTrickIds` already guarantees full
coverage of every rank the user actually passed through between the entrance rank and the final
rank (the reducer only advances a rank after every trick in it lands), so swapping the boundary to
`state.rank` is strictly correct and doesn't regress the "lower prerequisite ranks stay seeded"
requirement — verified by hand-tracing both the immediate-fail case and the multi-rank-advance
case (see notes below).

## Steps

1. **Fix the seed helper** — `src/features/onboarding/model/kentei-assessment.ts`
   - Rename `getSeedLacedTrickIds`'s first parameter from `startingRank` to `rank` (it now means
     "the final resolved Kentei rank," not the assessment's entrance rank).
   - Change the filter from `trick.kenteiRank < startingRank` to `trick.kenteiRank < rank`.
   - Add a short comment above the function explaining why the boundary must be the *resolved*
     rank and not the entrance rank — name the failure mode (immediate failure at the entrance
     rank makes the entrance rank itself look like a "below" prerequisite of a rank that was never
     earned) so a future reader doesn't quietly revert this to `startingRank`.
   - Leave the `startingRank` field on `KenteiAssessmentState` and its threading through the
     reducer untouched — it becomes unused outside of tests once this lands, but removing it is a
     broader refactor (touches ~10 `toEqual` assertions in the existing test file) that isn't
     required by the exit criteria. Don't fold it into this change.

2. **Fix the call site** — `src/features/onboarding/components/kentei-onboarding.tsx`, line 52.
   Change:
   ```ts
   const lacedTrickIds = getSeedLacedTrickIds(state.startingRank, state.landedTrickIds);
   ```
   to:
   ```ts
   const lacedTrickIds = getSeedLacedTrickIds(state.rank, state.landedTrickIds);
   ```
   This is the only production call site (confirmed via repo-wide grep).

3. **Update existing unit tests** —
   `src/features/onboarding/model/kentei-assessment.test.ts`, `describe('getSeedLacedTrickIds', ...)`
   block (currently lines 276–303).
   - These three existing tests all happen to use scenarios where `startingRank === rank`, so
     their assertions don't need to change numerically — but they're written and named around
     "starting rank" semantics that are no longer accurate. Rename the local variables/wording
     (`startingRank` → `rank`) so the test file doesn't describe behavior the function no longer
     has.
   - Add a new test that is the actual regression case: call
     `getSeedLacedTrickIds(3, [])` (i.e. entrance rank 4, immediate first-trick failure) and assert
     the result contains every Rank 1 and Rank 2 trick ID but **none** of Rank 3's trick IDs (use
     `getTricksForRank(1)`, `getTricksForRank(2)`, `getTricksForRank(3)` from the same module to
     build the expected/forbidden ID sets — don't hand-list trick names).

4. **Add a pure-reducer regression test for the exact exit-criteria scenario** — same file,
   `kentei-assessment.test.ts`. Drive the real state machine end-to-end rather than hand-building a
   state object, so the test also catches any future change to the reducer's fail-on-first-trick
   branch:
   ```ts
   let state = kenteiAssessmentReducer({ status: 'levelSelect' }, { type: 'levelSelected', level: 'Advanced' });
   // state: assessing, rank 4, trickIndex 0, startingRank 4, landedTrickIds []
   state = kenteiAssessmentReducer(state, { type: 'trickNotLanded' });
   // state: rankReveal, rank 3, startingRank 4, landedTrickIds []
   ```
   Assert `state.rank === 3` (sanity check on the existing reducer, not new behavior), then compute
   `getSeedLacedTrickIds(state.rank, state.landedTrickIds)` and assert the same
   include/exclude shape as step 3's new test (Rank 1 + 2 in, Rank 3 out). This is the bridge
   between "the reducer produces this state" and "the seed helper handles it correctly," which the
   step-3 test alone doesn't cover (it starts from a hand-built `rank`/`landedTrickIds` pair).

5. **Add the integrated provider/reducer regression test required by the task Notes** —
   `src/features/profile/state/kentei-rank-auto-promotion.test.tsx`. This file already mounts the
   real boundary the Notes call out (`UserProfileProvider` + `PracticeHistoryProvider` +
   `KenteiRankAutoPromotion`, with a `Harness` that calls the real `completeOnboarding` action) and
   already has an AsyncStorage read/write pattern via `USER_PROFILE_STORAGE_KEY`. Extend it rather
   than building new scaffolding:
   - The current `Harness` hardcodes `completeOnboarding(1, [], [])`. Either parameterize it (pass
     `rank`, `selectedTrickIds`, `lacedTrickIds` as props with the existing call as the default) or
     add a small sibling harness component for this test — either is fine, keep it consistent with
     the file's existing style of tiny `Pressable` stand-ins.
   - In the new test, derive the seed scenario the same way step 4 does (drive
     `kenteiAssessmentReducer` from `levelSelect` → `levelSelected: 'Advanced'` →
     `trickNotLanded` to reach `rank: 3, landedTrickIds: []`), then compute
     `lacedTrickIds = getSeedLacedTrickIds(state.rank, state.landedTrickIds)` — i.e. call the
     *real* onboarding functions, not a hand-crafted ID list, so this test actually exercises the
     seed helper the fix touches.
   - Mount via `mountAndHydrate()`, press `start-onboarding` (wired to
     `completeOnboarding(3, someSelectedIds, lacedTrickIds)`), let effects flush.
   - Assert:
     - `hasAccessibilityLabel(root, 'Rank up celebration')` is `false` (no unearned promotion —
       mirrors the existing "does not render... already-advanced profile" test's pattern).
     - Read the persisted profile back out (`AsyncStorage.getItem(USER_PROFILE_STORAGE_KEY)` +
       `deserializeUserProfile`, both already imported in this file) and assert:
       - `kenteiRank === 3` (persisted profile stayed at the assessed rank, not silently bumped)
       - `manuallyUnlockedTrickIds` contains every Rank 1 and Rank 2 trick ID
       - `manuallyUnlockedTrickIds` contains **none** of Rank 3's trick IDs
   - This test is the one that actually satisfies the task Notes ("test the provider/reducer
     boundary used by onboarding, not only the seed helper in isolation") and the exit criteria
     line item about "no immediate unearned rank-up is produced" — steps 3–4 alone only prove the
     pure function is correct, not that the wiring through `onboardingCompleted` →
     `manuallyUnlockedTrickIds` → `KenteiRankAutoPromotion` stays correct.

## Order rationale

Steps 1–2 (the actual fix) must land before any of the new tests are written against them, since
the new tests assert the *corrected* behavior and would fail against current `main`. Steps 3–4
(pure model-level tests) are cheaper to write and debug than step 5 (full provider tree + async
storage flush), so get the core logic locked down first, then build the integration test on top of
it with confidence the underlying pieces are already correct — if step 5 fails, the bug is in the
wiring (userProfileReducer / KenteiRankAutoPromotion), not in the seed math.
