- Nested screens are entered with `router.push` from the section index (tricks/index.tsx, stats/index.tsx, profile/index.tsx, account-section.tsx, sesh.tsx `<Link>`), so a native back stack entry normally exists. Exceptions: deep link / `auth-callback-screen` `router.replace('/app/profile/account/security')` produce a single-entry stack (no native back button). Handle with the `headerLeft` fallback below.
- Existing in-page back controls call `router.replace(parent)`; that can leave a duplicate index entry under the stack. Not part of this ticket, but watch for it in simulator checks (header back from a screen must land on the parent; if a duplicate-index quirk is visible after in-page Save/Cancel, switch those handlers to `router.dismissTo(...)` if it exists in expo-router 57.0.29, and note it in the PR).
- `Screen` (`src/components/ui/screen.tsx`) is a `SafeAreaView` with `edges={['top','left','right']}` in all these routes. With a visible native header the top inset is already consumed by the header. react-native-safe-area-context's native `SafeAreaView` measures real overlap so it should yield 0, but this MUST be confirmed on the simulator (risk: doubled top gap). If doubled, drop `'top'` from edges on native only via a small shared helper rather than per-route Platform checks.

## Design

### 1. Shared native-header options (new file `src/components/nested-stack-options.ts`)

Mirror `deriveTabBarColors` in app-tabs.tsx:

- `deriveNestedHeaderColors(theme: ResolvedTheme)` -> `{ background: theme.background, tint: theme.text, title: theme.text, border: blendHexColors(theme.text, theme.background, 0.2) }`. Always from the saved theme, never system appearance.
- `useNestedStackScreenOptions(): NativeStackNavigationOptions` (or a pure `deriveNestedStackScreenOptions(theme, platformOS)` plus a thin hook) returning, for native: `headerShown: true, headerStyle: { backgroundColor }, headerTintColor, headerTitleStyle: { color }, headerShadowVisible: true (or colored border), headerBackButtonDisplayMode: 'default'` and `contentStyle: { backgroundColor }`; for web: `{ headerShown: false }`. Keep the platform decision in one pure function taking `Platform.OS` as a parameter so it is trivially unit-testable (no module mocking).
- Check iOS 26/27 behavior on the simulator: the liquid-glass header may ignore `headerStyle.backgroundColor` or apply a blur. If the saved theme is not respected, set `headerTransparent: false`, `headerBlurEffect: 'none'` (iOS) and re-check. System dark appearance on must not change header colors or the back chevron/title color (that is the exit criterion; test with Simulator Settings > Developer > Dark Appearance, or `xcrun simctl ui booted appearance dark`).
- Back control: native stack provides the chevron back button when the stack has history. Add a fallback so the control exists on single-entry stacks (deep link, auth-callback replace): in each layout use options function `({ navigation }) => navigation.canGoBack() ? {} : { headerLeft: () => <HeaderBackFallback href={parent} tint=... /> }`. Implement `HeaderBackFallback` as a small `Pressable` + text/SF symbol (`chevron.left` via `expo-symbols`, already a dependency) with `accessibilityRole="button"` and `accessibilityLabel="Back to <Parent>"`, calling `router.replace(parent)`. Put it in the same new module or `src/components/nested-header-back.tsx` (one purpose per file).
- Titles: static per screen via `Stack.Screen options={{ title }}`; set `headerBackTitle`/`headerBackButtonDisplayMode: 'minimal'` so long titles do not collide on a small iPhone (check on iPhone 17e).

### 2. Section layouts

In `tricks`, `profile`, `sesh`, `stats` `_layout.tsx` replace `<Stack screenOptions={{ headerShown: false }} />` with:

```tsx
const options = useNestedStackScreenOptions();
<Stack screenOptions={options}>
  <Stack.Screen name="index" options={{ headerShown: false }} />
  <Stack.Screen name="goals" options={{ title: 'Goals' }} />
  ...
</Stack>
```
`index` stays headerless (the tab bar remains the primary navigation). Keep the Tricks/Profile/Sesh tab-press effects exactly as is. Stats layout currently has no hooks; adding one is fine (it is inside the themed providers).

## Risks to watch

- iOS 26+ glass header may ignore theme background/tint; confirm visually (see section 1).
- Doubled top safe-area padding from `Screen edges={['top', ...]}` under the header.
- `Stack.Screen name` mismatches for nested/dynamic route paths produce runtime warnings and a headerless default; the disk-drift test plus simulator run guards this.
- Hidden back links leaving empty spacing or orphaned containers.
- `router.replace`-based in-page handlers leaving duplicate index entries in the stack (existing behavior; see above).
- Do not touch the `tabPress` reset effects or the persistence providers.
