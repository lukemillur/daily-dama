# T049 — Split multi-trick sesh setup into a two-step wizard

## Current shape (baseline)

`src/features/sesh/components/multi-trick-sesh-entry.tsx` has a two-state machine today:

```ts
type MultiTrickSeshEntryStep =
  | { readonly kind: 'choosingTricks' }
  | { readonly kind: 'running'; readonly tricks: readonly PracticeTrick[]; readonly plan: SeshPlan };
```

`choosingTricks` renders `TrickDirectory` with a `footer` that bundles the selection count, the "Time per trick" numeric field, the "Advance after one lace" checkbox row, and the "Start sesh" button all together. `selectedTrickIds`, `advanceOnFirstLace`, and `perTrickDurationMinutes` are independent `useState` hooks, not nested inside `step` — this matters below.

Precedent to follow: `src/features/sesh/components/assessment-entry.tsx`'s `choosingFlow → choosingRank → running` machine, with a literal-text `Back` button (`variant="secondary"`) that calls `setStep({ kind: 'choosingFlow' })`. Mount route for browser verification is `/sesh/multi-trick` (`src/app/sesh/multi-trick.tsx` → `src/app/sesh/_layout.tsx`, `headerShown: false`).

## Plan

1. **Extend the step union** in `multi-trick-sesh-entry.tsx` to three states:
   ```ts
   type MultiTrickSeshEntryStep =
     | { readonly kind: 'choosingTricks' }
     | { readonly kind: 'configuringRun' }
     | { readonly kind: 'running'; readonly tricks: readonly PracticeTrick[]; readonly plan: SeshPlan };
   ```
   Keep `selectedTrickIds`, `advanceOnFirstLace`, and `perTrickDurationMinutes` as top-level `useState`, untouched by this change — they already live outside `step`, so navigating `choosingTricks → configuringRun → choosingTricks` preserves them for free. This is *why* the existing state shape matters: don't be tempted to nest selection state inside the step objects, that would require manually threading it back out on Back.

2. **Step 1 (`choosingTricks`)**: keep the existing `TrickDirectory` call, but shrink its `footer` down to just the selection-count text plus a `Continue` button:
   - Reuse `SelectionCount` (unchanged copy/logic: "Select at least one trick to continue." / "N tricks selected.").
   - Replace the duration field, advance-on-lace row, and `FinishButton`/`handleStart` wiring with a single `Continue`-labeled button (reuse the `FinishButton` styled component, rename usage or just keep it as-is) that is `disabled={selectedCount === 0}` and does `setStep({ kind: 'configuringRun' })`.
   - Remove `PerTrickDurationField`/`AdvanceOnFirstLaceRow`/duration validity logic from this footer — it moves to step 2.

3. **Step 2 (`configuringRun`)**: new render branch, styled after `assessment-entry.tsx`'s `Content`/`Eyebrow`/`DisplayTitle`/`BodyText` pattern rather than reusing the `TrickDirectory` footer chrome (there's no trick list on this screen anymore, so the sticky-footer-over-a-list layout doesn't apply):
   - `Eyebrow` "Multi-trick sesh", a `DisplayTitle`-based heading (e.g. "Set your\ntiming."), and a short `BodyText` line showing the selection count so the user has a persistent record of what they picked (reuse the same singular/plural logic as `SelectionCount`).
   - The existing `PerTrickDurationField` (label, `PerTrickDurationInput`, `PerTrickDurationHint`) and `AdvanceOnFirstLaceRow` markup move here verbatim — same state (`perTrickDurationMinutes`, `advanceOnFirstLace`), same validity derivation (`hasPerTrickDuration`, `hasValidPerTrickDuration`, `plan`).
   - `Start sesh` button: same `handleStart` and same `disabled={selectedCount === 0 || (hasPerTrickDuration && !hasValidPerTrickDuration)}` condition as today (selectedCount can't actually be 0 here since step 1 gates it, but keep the guard — cheap and matches "starting a run behaves exactly as today").
   - `Back` button: `variant="secondary"`, literal text "Back", `onPress={() => setStep({ kind: 'choosingTricks' })}`. Match `assessment-entry.tsx`'s `BackButton` styling (`align-self: flex-start; margin-top: 30px;`) rather than inventing new back-button styling.

4. **`handleFinished`** (called from `running` → back to setup) should reset to `{ kind: 'choosingTricks' }` (not `configuringRun`) and clear all three pieces of local state, same as today — starting a fresh run always begins at trick selection, not at the timing step.

5. **Styling cleanup**: the step-2 screen no longer needs `FinishBackdrop`'s sticky/pinned split (that existed to keep the footer visible over a scrolling `TrickDirectory` list, which step 2 no longer has). Give step 2 its own simple centered panel (mirror `assessment-entry.tsx`'s `Content` styled-component: `width: 100%; max-width: 760px; flex: 1; justify-content: center; padding: ...; align-self: center;`) instead of trying to force it into `SelectionContent`/`FinishArea`. Keep `SelectionContent` as step 1's outer wrapper unchanged. Don't carry over `shouldPinSelectionChrome`-driven styling into step 2 — that flag only matters when a scrollable list is present.

6. **Accessibility labels**: give the step-1 "Continue" button and step-2 "Back" button distinct `accessibilityLabel`s (or rely on visible-text lookup like `assessment-entry.test.tsx`'s `pressByVisibleText` helper does) so they're unambiguously targetable if a test is added later and by any manual/automated in-browser interaction.

7. **No changes needed** to `MultiTrickSesh`, `sesh.ts` model helpers (`createTimedSeshPlan`, `isValidTimedSeshMinutes`, `OPEN_ENDED_SESH_PLAN`, `selectSeshPracticeTricks`), `trick-directory.tsx`, or the route files — this is a self-contained render/state split inside one component.

## Order of work

Steps 1–4 are one coherent edit to `multi-trick-sesh-entry.tsx` (the state machine and both render branches depend on each other and should land together, not incrementally). Do the styled-components cleanup (step 5) as part of the same edit rather than after, since the new step-2 branch needs *some* container styling to render at all — there's no working intermediate state to commit between "old single screen" and "new two-screen" here.

  - Continue advances to step 2, which shows only the duration field, advance-on-lace checkbox, Start sesh, and Back — no trick list visible.
  - Back returns to step 1 with the previously checked tricks still checked (and, as a bonus check even though not required, that the duration/advance-on-lace values you set are also still there — confirms the state-outside-`step` design didn't regress).
  - Start sesh from step 2 begins a run identical to today's behavior (open-ended when duration is blank, timed when a valid duration is entered, respects advance-on-lace).
- Recheck the 320px viewport width for both new screens per AGENTS.md's web-navigation note — though this component isn't the 5-link nav bar itself, the same "narrow viewport" scrutiny is worth a quick check since step 2's controls (duration input, checkbox row, two buttons) are new layout, not previously verified at that width in isolation.

## Risks / non-obvious things

- Don't nest `selectedTrickIds`/`advanceOnFirstLace`/`perTrickDurationMinutes` inside the step union when refactoring — keeping them as independent top-level state is what makes "Back preserves prior selection" free. This is the one invariant most likely to get silently broken by a well-intentioned refactor.
- T050 (focused-section sorting) and T051 (a back-to-`/sesh` control) both touch this same file's step-1 render. Expect rebase friction if those land concurrently, per the task notes — no action needed now beyond being aware the footer/header JSX you're touching is a shared edit surface.
