# T034 — Align Kentei assessment language with promotion-only behavior

## Scope confirmation (read first)

The rank-setting model behind the *real, timed* "Kentei assessment" flow
(`AssessmentEntry` → `MultiTrickSesh` → practice history → auto-promotion) is
genuinely monotonic. Confirmed by tracing the actual call chain:

- `KenteiRankAutoPromotion` (`src/features/profile/state/kentei-rank-auto-promotion.tsx`)
  only ever calls `advanceKenteiRank(promotedRank)`, and `promotedRank` comes
  from `selectPromotedKenteiRank` (`src/features/tricks/model/trick-directory.ts:149`),
  whose loop starts at `currentRank` and only ever increments (`rank += 1`)
  while the current rank is complete — it can never return less than
  `currentRank`.
- The `kenteiRankAdvanced` reducer case (`src/features/profile/model/user-profile.ts:140`)
  just writes whatever rank it's given, but the only caller of
  `advanceKenteiRank` in the whole codebase is the auto-promotion effect
  above, so in practice this path never regresses.

So the Notes' premise holds **for this flow** and the task is legitimately
copy-only. No blocker.

**However**: there is a second, separate rank-setting path that is *not*
monotonic and is intentionally out of scope for this task — see "Explicit
non-goal" below. Do not touch it; touching it would either require the
larger domain-model rescope the task's Notes rule out, or would make its
copy less accurate, not more.

### Explicit non-goal: the onboarding "Retake assessment" flow

`src/app/profile/index.tsx` (lines ~48–57) has a *second* assessment-shaped
section, "Retake assessment," whose button calls `restartOnboarding()`. That
routes back through the onboarding self-declared placement quiz
(`src/features/onboarding/model/kentei-assessment.ts`,
`src/features/onboarding/components/kentei-onboarding.tsx`). Its
`completeOnboarding` action
(`src/features/profile/model/user-profile.ts` — `onboardingCompleted` case)
overwrites `kenteiRank` directly with whatever the quiz produces, with no
comparison to the prior rank. `restartOnboarding` itself
(`onboardingRestarted` case) sets `kenteiRank: undefined` immediately on
button press, before the user even redoes the quiz.

This is a real, pre-existing, already-accurately-described authoritative
reassessment path — it already says "Retaking the assessment **updates**
your rank," which is true in both directions for that flow. The code itself
draws this distinction deliberately: see the doc comment atop
`AssessmentEntry` ("Not to be confused with the self-declared placement quiz
in `.../onboarding/model/kentei-assessment.ts` — that's a one-time
onboarding estimate with its own reducer; this is real timed practice.").

**Do not edit the "Retake assessment" section's copy in this task.** Rewriting
it to promotion-only language would make it *less* accurate, since that flow
genuinely can lower or replace the rank. If this inconsistency across the two
"assessment" affordances on one screen bothers you, that's a legitimate
follow-up, but it's a product/model question (should retaking onboarding be
allowed to demote at all?) outside T034's copy-only remit — flag it
separately rather than folding it in here.

## Files touched, in order

### 1. `src/features/sesh/model/kentei-assessment-run.ts` — add the result-copy selector

Add a new pure function alongside the existing `selectAssessmentTricks` /
`selectAssessmentRankBounds` / `selectNextRankStartIndex`:

```ts
/**
 * Copy for the assessment wrap-up screen, given the rank the profile had
 * when the run started and the rank it has now (after any auto-promotion
 * from practice recorded during the run). Because the underlying rank model
 * is promotion-only (see selectPromotedKenteiRank in trick-directory.ts),
 * `resultRank` can never be lower than `startingRank` — this only has to
 * distinguish "advanced" from "held," never handle a regression case.
 */
export function selectAssessmentResultCopy(
  startingRank: number | undefined,
  resultRank: number | undefined,
): string {
  if (resultRank === undefined) {
    return 'Keep practicing — you have not earned a rank yet.';
  }
  if (startingRank === undefined || resultRank > startingRank) {
    return `Rank up! You're now Rank ${resultRank}.`;
  }
  return `You held Rank ${resultRank}. Land every trick in a rank to advance.`;
}
```

Treat the exact strings as a starting proposal, not final copy — the
important part for the exit criteria is the three-way branch (not-yet-earned
/ advanced / held), not the specific words. Whatever wording is chosen must
avoid "assessed at" / "reassessed" framing, since that's the phrase the task
exists to remove (it reads as "this run determined/replaced your rank," which
is misleading in the "held" case).

Do this first — it's the one piece with no rendering dependencies, and step 2
depends on its signature.

### 2. `src/features/sesh/model/kentei-assessment-run.test.ts` — cover the new selector

Add a `describe('selectAssessmentResultCopy', ...)` block, following the
existing file's style (plain `describe`/`it`, no component rendering).
Cover:

- `resultRank === undefined` → the "not yet earned" copy, regardless of
  `startingRank`.
- `startingRank === undefined`, `resultRank` defined → "advanced" copy (first

- `resultRank > startingRank` → "advanced" copy, and the copy contains

  language implying replacement/reassessment (assert it doesn't match

(`resultRank < startingRank` is not a case worth testing — the type allows it
for defensiveness, but the model guarantees it can't happen; don't invent
