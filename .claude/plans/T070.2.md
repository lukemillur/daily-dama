# T070.2 implementation plan

## Goal

Remove the transient generic `Sequence complete / Nice work.` render that can
appear for one render while an assessment-style `MultiTrickSesh` run is moving
from a laced trick to its next trick or to the assessment wrap-up. Preserve the
ordinary multi-trick completion panel and the assessment-specific wrap-up.

## Ordered implementation steps

1. Update `src/features/sesh/components/multi-trick-sesh.tsx` at the
   completed-state transition boundary. Keep the existing effect as the
   authority for recording the summary and advancing `sequence`; change only
   the render behavior for the assessment/auto-advance transition so the
   intermediate fallback cannot expose the generic completion panel. The
   implementation should allow the effect to settle on either the next
   trick's countdown/active state or the finished sequence's `MultiTrickWrapUp`
   without changing reducer transitions, history recording, skip behavior, or
   the deliberate regular multi-trick fallback behavior. Do not remove or
   alter the `MultiTrickWrapUp`'s intentional `Nice work.` heading.

2. Pass or derive the narrow assessment transition signal at the existing
   `AssessmentEntry`/`MultiTrickSesh` boundary. Prefer an explicit prop or
   equivalent contract if that makes the scope clear; avoid coupling generic
   `MultiTrickSesh` presentation to Kentei-specific rank/result logic. Preserve
   the existing `origin="assessment"`, auto-advance, countdown skipping, and
   assessment footer/result behavior.

3. Extend `src/features/sesh/components/multi-trick-sesh.test.tsx` with
   component-level regression coverage for the two transition cases required
   by the ticket:

   - an assessment-style run where lacing the final trick reaches the intended
     assessment wrap-up without rendering the transient generic panel;
   - an assessment-style run where lacing a non-final trick advances to the
     intended next trick without rendering that panel.

   Use the existing renderer helpers and fake-timer setup. Assert the generic
   transient copy is absent at the transition and assert the destination
   (wrap-up/result content for the final case, next trick for the non-final
   case) is present. Keep or add a regular multi-trick completion assertion so
   the ordinary wrap-up and its intentional `Nice work.` heading remain
   covered.

4. Run focused component tests first, then the repository verification sequence
   from `AGENTS.md`: `yarn test --runInBand`, `yarn lint`, `yarn tsc --noEmit`,
   and `yarn expo export --platform web --output-dir
   /tmp/daily-dama-web-export`. Do not perform native validation; the active
   project scope is web and automated verification only.

## Files expected to change

- `src/features/sesh/components/multi-trick-sesh.tsx`
- `src/features/sesh/components/assessment-entry.tsx` only if an explicit
  transition prop is used
- `src/features/sesh/components/multi-trick-sesh.test.tsx`

No persistence, reducer, practice-history, navigation, or task-backlog changes
are expected. The durable plan should be removed by the implementer when the
ticket is completed, per the ticket workflow.

## Exit-criteria mapping

- Final assessment trick: component test proves no transient generic panel and
  the assessment wrap-up remains visible.
- Non-final assessment trick: component test proves no transient generic panel
  and the next trick remains visible.
- Regular multi-trick completion: existing or strengthened component coverage
  proves the normal completion behavior remains unchanged.
