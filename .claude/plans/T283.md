# T283 plan: readable themed control foregrounds

## Findings (verified against the branch)
- `ResolvedTheme` (`src/features/profile/state/use-resolved-theme.ts`) has `background, accent, text, textMuted, buttonBackground, buttonBackgroundSecondary`. `buttonBackground` is ink or paperStrong, chosen against the page background only. Nothing checks the foreground placed on it.
- `theme.accent` is used as a text color on two kinds of surface that the theme never checks:
  1. `theme.buttonBackground` (ink or paperStrong): `Button` primary label (`src/components/ui/button.tsx` ButtonLabel); `LacedButtonText` and `LacedCount` (`src/features/sesh/components/sesh.tsx` ~1326-1327).
  2. Fixed `AppColors.ink` surfaces:
     - Sesh: `PlanChoiceTitle` and `ChallengeChoiceTitle` when selected (ink bg), `NotePromptButtonText` (ink bg).
     - Stats: `OverviewValue` (`src/app/app/stats/index.tsx`, ink `OverviewMetric`), `BestValue` (`src/app/app/stats/[trickId].tsx`, ink `BestRow`).
     - Home: `StreakValue` (ink badge), `MomentumValue` (ink strip) in `src/features/home/components/daily-home.tsx`.
- Button secondary label uses `theme.text` on `buttonBackgroundSecondary`. That pairing is also unchecked, because `text` can be a user override.
- The blue preset (`#d8e8f7` / `#1f6fb2`) puts accent on ink at roughly 2.4:1, which fails. Default theme (yellow on ink) is fine. This is the observed defect.
- Disabled treatment is opacity only (Button 0.35, Laced 0.45). Keep it as is.
- `src/shared/color/contrast.ts` already has `contrastRatio`, `meetsMinimumContrast` and `WCAG_AA_MIN_CONTRAST_RATIO` (4.5).
- `DefaultTheme` is declared in `src/types/styled-components.d.ts`. Test files that build a literal `DefaultTheme` will fail typechecking when required fields are added. They are: `button.test.tsx`, `text-field.test.tsx`, `typography.test.tsx`, `sesh.test.tsx`, and the auth tests `sign-up`, `sign-in`, `forgot-password`, `reset-password`, `password-input` and `account-security` under `src/features/auth/components/__tests__/`.

## Design
Add semantic foreground roles. Keep the decorative `accent` and the persisted preference shape untouched. No change to `user-profile-persistence`, cloud mapping, or `ThemeColorPreferences`. The roles are derived at resolve time only.

New `ResolvedTheme` fields:
- `onButton`: label/value color for `buttonBackground`. Used by primary Button, Laced text and count.
- `onButtonSecondary`: label color for `buttonBackgroundSecondary`. Preferred color is `theme.text`.
- `onInk`: foreground for fixed `AppColors.ink` surfaces (Stats values, selected Sesh choices, Home streak/momentum, note prompt button). Preferred color is `accent`.

New pure function `deriveReadableForeground(surface, preferred, minRatio = WCAG_AA_MIN_CONTRAST_RATIO)`, placed in `use-resolved-theme.ts` next to the other derivers (or `src/shared/color/` if a generic home reads better):
- If `contrastRatio(preferred, surface) >= minRatio`, return `preferred`. This keeps the owner's chosen decorative color whenever it is already legible. Do not forbid or alter custom accents.
- Otherwise return the candidate with the highest contrast among `[AppColors.cream, AppColors.ink]`.
- If `contrastRatio` returns `undefined` (invalid hex), return the best neutral. Do not throw.
- Pure and deterministic.

Wire into `resolveTheme`: `onButton = deriveReadableForeground(buttonBackground, accent)`; `onButtonSecondary = deriveReadableForeground(buttonBackgroundSecondary, text)`; `onInk = deriveReadableForeground(AppColors.ink, accent)`. `CachedAppThemeProvider` and `DefaultAppThemeProvider` already go through `resolveTheme`, so they pick the roles up for free.

## Risks and notes
- Adding required `DefaultTheme` fields causes churn, but only in test literals.
- On the blue theme, selected Sesh choices and Stats values fall back to cream or ink, so the decorative accent no longer shows there. That is the intended trade; accent still shows wherever it is legible.
- Use 4.5 everywhere via `WCAG_AA_MIN_CONTRAST_RATIO`, including large text, since the ticket says 4.5.
- Do not touch the saved profile document, cloud mapping, or sync code.
