# T125 - Give screenshot containers a background distinct from the page

## Current state (verified on this branch, post-T124)

`src/features/landing/components/landing-page.tsx`:

- Page background: `Screen background={AppColors.paper}` (`#f8f1dd`).
- `ScreenshotItem` (around line 232, after T124's `$isWebLayout` prop was added) currently reads:
  - styled.View.attrs({ style: { boxShadow: '6px 6px 0 #18382e' } })
  - generic type param: { readonly $isWebLayout: boolean }
  - gap: 10px; align-items: center; width: 100%;
  - max-width: 560px web / 360px mobile via $isWebLayout
  - padding: 26px 26px 30px web / 18px 16px 22px mobile
  - background-color: AppColors.paperStrong
  - border: 2px solid AppColors.ink
  - border-radius: Radii.panel px
- `background-color: AppColors.paperStrong` (`#f6efd9`) against page `AppColors.paper` (`#f8f1dd`) is a ~2-value RGB difference, effectively imperceptible. This is the root cause of the QA "doesn't read as distinct" complaint, more than the shadow size.

`src/features/landing/components/landing-cta.tsx`'s `CtaPanel` is the treatment to align with. At the JSX call site it renders:

    <CtaPanel
      $variant={isReturning ? 'returning' : 'firstTime'}
      entering={FadeInUp.duration(450).springify()}
      style={{ boxShadow: `8px 8px 0 ${AppColors.ink}` }}
    >

and the styled-component itself has:

    border: 2px solid ${AppColors.ink};
    border-radius: ${Radii.panel}px;
    background-color: ${({ $variant }) => ($variant === 'returning' ? AppColors.sage : AppColors.yellow)};

**Important finding: the current `boxShadow` on `ScreenshotItem` likely isn't rendering at all.** `landing-cta.tsx` has an explicit code comment (lines 54-61) explaining that `styled.View.attrs({ style: { boxShadow: ... } })` is *not* sufficient to apply the shadow: styled-components/native's `.attrs` config is only consulted while resolving the CSS template literal's interpolations, and is not merged into the final rendered `style` unless the call site *also* passes its own `style` prop. `CtaPanel` works around this by passing `style={{ boxShadow: ... }}` explicitly at the JSX call site. The comment calls out `trick-card.tsx`'s `Card` as the "(currently inert)" precedent that gets this wrong -- and `ScreenshotItem` uses that same inert `.attrs`-only pattern (its JSX call site currently passes no `style` prop). So today the screenshot containers most likely have **no visible shadow at all**, on top of the near-invisible background contrast. Both problems compound the QA finding.

## Plan

1. **Fix the background contrast.** In `landing-page.tsx`, change `ScreenshotItem`'s `background-color` from `AppColors.paperStrong` to `AppColors.cream` (`#fffaf0`). Rationale: `cream` is meaningfully lighter/whiter than `paper` (`#f8f1dd`), giving real perceptual contrast, and it stays a neutral card treatment rather than borrowing `sage`/`yellow`, which `CtaPanel` uses to carry variant meaning (returning vs. first-time user). Reusing one of those here would blur that meaning elsewhere on the page. Do not add a new palette entry -- `cream` already exists in `AppColors` for exactly this "lighter neutral surface" role.

2. **Fix the shadow so it actually renders, and align size/color with `CtaPanel`.** In `landing-page.tsx`:
   - Remove the `.attrs({ style: { boxShadow: '6px 6px 0 #18382e' } })` from the `ScreenshotItem` styled-component definition -- it is dead weight given the JSX call site currently passes no `style` prop.
   - At the JSX call site (~line 153), pass the shadow explicitly, matching `CtaPanel`'s pattern: add a `style` prop with `boxShadow: '8px 8px 0 ' + AppColors.ink` (template literal, same form as `CtaPanel`) to the `<ScreenshotItem ...>` element alongside its existing `key`, `testID`, and `$isWebLayout` props.
   - Use an 8px 8px 0 offset (not 6px 6px 0) to match `CtaPanel` per the exit criteria, and reference `AppColors.ink` instead of a hardcoded hex literal (the existing `'#18382e'` already equals `AppColors.ink`'s value, but referencing the token avoids a second hardcoded copy and matches `CtaPanel`'s style).
   - Port `CtaPanel`'s explanatory comment (or a shortened form) above `ScreenshotItem`, since this is the second component to hit this styled-components/native `.attrs`-vs-`style` gotcha -- worth a one-line pointer to `landing-cta.tsx` for future readers rather than re-deriving the explanation a third time.

3. **Verify no layout regression from the larger shadow.** `ScreenshotItem` sits inside `ScreenshotSection` (`gap: 28px`) inside `Content` (`padding: 40px 22px 80px`) inside a `ScrollView`. `box-shadow` is not clipped by ancestor `overflow` on web (it's not `overflow: hidden` on `ScreenshotItem` itself), so growing from 6px to 8px offset should not get cut off. Sanity-check visually at both the mobile (360 max-width) and desktop (560 max-width, `$isWebLayout`) breakpoints that the shadow doesn't visually collide with the next item given the 28px gap -- an 8px offset is well within that gap, so no spacing change should be needed. Do not preemptively increase `ScreenshotSection`'s gap; only touch it if the visual check shows a real collision.

4. **Leave everything else alone.** Do not touch the screenshot data arrays, `$isWebLayout` sizing logic (T124's work), border width/color (`2px solid AppColors.ink` already matches `CtaPanel`), or `Radii.panel` usage -- all already consistent or out of scope per the task's "visual-only" note.
