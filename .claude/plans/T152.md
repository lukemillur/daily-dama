# T152 -- Play an audio cue when a timed Sesh's timer reaches zero

## Confirmed facts (from exploration on this branch)

- `expo-audio` is **not yet a dependency**. Recommended version for Expo SDK 57 (this
  project's installed SDK, confirmed via `package.json`: `"expo": "~57.0.10"`) is
  **`~57.0.4`**, per the SDK-57 Expo docs page for `expo-audio`. Install with
  `npx expo install expo-audio` so Expo resolves the exact SDK-compatible version rather
  than hand-pinning it.
- No config plugin entry is needed in `app.json`. The `expo-audio` config plugin only
  configures microphone permissions and background-playback native settings -- this task
  only plays a short bundled cue in the foreground, so the default (no plugin) config
  works. Don't add `expo-audio` to the `plugins` array.
- No audio assets exist anywhere in the repo yet (`assets/` only has `images/`, `expo.icon/`,
  `tabIcons/`). A cue asset must be added from scratch.
- The Sesh reducer (`src/features/sesh/model/sesh.ts`) has no notion of "why" an
  `active`->`completed` transition happened -- `seshEnded` and `timerElapsed` both call the
  same private `completeSesh` helper and produce an identical `SeshState` shape (a
  `SeshSummary`). **Do not add a transition-source field to `SeshState`/`SeshSummary`** --
  per `AGENTS.md`'s Sesh section and this task's own Notes, that tracking belongs in the
  component layer, not the reducer's state shape.
- `src/features/sesh/components/sesh.tsx` exports a top-level `Sesh` component (line ~75)
  that owns the `useReducer(seshReducer, ...)` call and stays mounted across every status
  transition (`choosing` -> `countdown` -> `active` -> `completed`); only `ActiveSesh`,
  `CompletedSesh`, etc. mount/unmount as `state.status` changes. `Sesh` already has a
  `useRef` (`recordedSummaryId`) used to dedupe the practice-history-recording effect that
  runs once per newly-completed summary (lines ~122-144). This effect and ref are the
  existing pattern to extend, not a new one to invent.
- The dispatch call sites for the two actions that matter are both inline JSX props in
  `Sesh`'s `active`-status render branch (~line 232-236):
  onEnd -> dispatch({ type: 'seshEnded', now: Date.now() })
  onTimerElapsed -> dispatch({ type: 'timerElapsed', now: Date.now() })
  `onTimerElapsed` itself is only ever invoked from one place: an effect inside
  `ActiveSesh` (~line 656-658) that fires when `elapsedMs >= plan.durationMs` for a timed
  plan -- i.e. natural expiration only. The "End Sesh" button's `onEnd` is a fully separate
  code path. This structural separation is what makes the two transitions distinguishable
  without touching the reducer.

## Design decision: where the AudioPlayer instance lives

Do **not** put `useAudioPlayer` inside `ActiveSesh`. `ActiveSesh` unmounts on the same
render pass that swaps in `CompletedSesh` once `state.status` becomes `'completed'`.
`useAudioPlayer`'s automatic release-on-unmount could plausibly cut the cue off before it
finishes playing (a real risk given the exit criteria requires it to be *audible*, not just
triggered). Instead, instantiate the player once in the top-level `Sesh` component, which
stays mounted for the whole practice-to-completion lifecycle. This also puts it right next
to the existing `recordedSummaryId` dedupe-ref pattern.

## Implementation steps, in order

1. Add the dependency. Run `npx expo install expo-audio` from the repo root. Confirm
   `package.json` lands on `~57.0.4` (or whatever `expo install` resolves for SDK ~57.0.10)
   and note the pinned version in the commit/PR description.

2. Add the cue asset before wiring any code to it (so later steps have something real to
   `require()`). Add `assets/audio/sesh-timer-complete.wav`. No suitable audio asset exists
   in the repo or is fetchable from this environment (no network access to a stock-audio
   source, no `ffmpeg` installed), so synthesize a short placeholder tone locally with
   Python's stdlib `wave` module -- no new tooling needed. Example generator (two quick
   ascending beeps, ~500 ms total, gentle attack/decay envelope to avoid a harsh click):

   ```python
   import wave, struct, math

   RATE = 44100
   def tone(freq, ms, amp=0.3):
       n = int(RATE * ms / 1000)
       samples = []
       for i in range(n):
           t = i / RATE
           fade = min(1.0, i / (RATE * 0.015), (n - i) / (RATE * 0.015))
           samples.append(amp * fade * math.sin(2 * math.pi * freq * t))
       return samples

   samples = tone(880, 150) + tone(0, 40, 0) + tone(1320, 220)
   with wave.open('assets/audio/sesh-timer-complete.wav', 'w') as f:
       f.setnchannels(1)
       f.setsampwidth(2)
       f.setframerate(RATE)
       f.writeframes(b''.join(struct.pack('<h', int(s * 32767)) for s in samples))
   ```

   Treat this as a real (if simple) placeholder cue, not a stub -- it should be pleasant and
   clearly audible, since the exit criteria include a manual audible-at-zero check. Adjust
   frequencies/durations if the result sounds harsh when you listen to it locally. `.wav` is
   fully supported by `expo-audio` cross-platform (including web), so there's no need to
   fight the lack of `ffmpeg` to produce an `.mp3`.

3. Wire the player and transition-source ref into `Sesh` in
   `src/features/sesh/components/sesh.tsx`:
   - Add `import { useAudioPlayer } from 'expo-audio';` near the top.
   - Inside `Sesh` (near the existing `recordedSummaryId` ref, ~line 94), add:
     ```ts
     const timerCuePlayer = useAudioPlayer(require('@/assets/audio/sesh-timer-complete.wav'));
     const timerElapsedTransitionRef = useRef(false);
     ```
   - Change the `onTimerElapsed` dispatch prop (~line 236) to mark the ref immediately
     before dispatching:
     ```ts
     onTimerElapsed={() => {
       timerElapsedTransitionRef.current = true;
       dispatch({ type: 'timerElapsed', now: Date.now() });
     }}
     ```
     Leave `onEnd`'s `seshEnded` dispatch (~line 235) untouched -- it must never set this ref.
   - In the existing completed-summary effect (~lines 122-144, the one guarded by
     `recordedSummaryId.current === summaryId`), right after
     `recordedSummaryId.current = summaryId;`, add:
     ```ts
     if (timerElapsedTransitionRef.current) {
       timerCuePlayer.seekTo(0);
       timerCuePlayer.play();
     }
     timerElapsedTransitionRef.current = false;
     ```
     Resetting unconditionally (not just inside the `if`) is important: it guarantees the
     flag can never leak into a later, differently-caused completion (e.g. after `onRepeat`
     starts a new sesh that this time ends via `seshEnded`). Because this whole effect body
     only runs once per distinct `summaryId` (existing dedupe), the cue is guaranteed to
     play at most once per natural expiration.

   This is a minimal, additive change to `Sesh` -- no changes to `seshReducer`, `SeshState`,
   `SeshSummary`, or `ActiveSesh`'s own effect are needed.

4. Tests -- add a new `describe` block in `src/features/sesh/components/sesh.test.tsx`.
   Mock `expo-audio` safely (avoid the classic jest hoisting/TDZ trap: don't reference an
   outer `const` from inside the `jest.mock` factory -- construct and expose the mock
   player entirely inside the factory closure):
   ```ts
   jest.mock('expo-audio', () => {
     const mockAudioPlayer = { play: jest.fn(), seekTo: jest.fn() };
     return { useAudioPlayer: jest.fn(() => mockAudioPlayer), __mockAudioPlayer: mockAudioPlayer };
   });
   ```
   Then, near the top of the test file (after imports), pull the player out for assertions:
   ```ts
   import * as ExpoAudio from 'expo-audio';
   const mockAudioPlayer = (ExpoAudio as unknown as { __mockAudioPlayer: { play: jest.Mock; seekTo: jest.Mock } }).__mockAudioPlayer;
   ```
   Reset call counts in a `beforeEach`/`afterEach` for the new describe block (don't rely on
   global state leaking from other tests).

   Model both new tests directly on the existing `'Sesh regular practice origin (T062.1)'`
   describe block (~line 1678) -- same provider nesting, same
   `pressByAccessibilityLabel(root, 'Start a sesh with ${TRICK.name}')` flow, same 3x
   `jest.advanceTimersByTime(1000)` to clear the 3-second countdown. Use
   `initialPlan={createTimedSeshPlan(1)}` on the rendered `<Sesh>` so the duration is a
   round 60_000 ms (avoids relying on the picker's default and keeps advance-by numbers
   small):

   - "plays the timer-complete cue once when a timed sesh completes naturally": after
     clearing the countdown, `jest.advanceTimersByTime(60_000)` to cross `durationMs`
     without any manual end action. Assert `mockAudioPlayer.play` was called exactly once
     (and, if useful, that `seekTo` was called with `0` first).
   - "does not play the cue when a timed sesh is ended early": after clearing the

     `pressByVisibleText(root, 'End Sesh')` -- mirrors the existing T062.1 test's early-end

   Both tests exercise the full `Sesh` component (not `ActiveSesh` in isolation), since the
   player and the ref live at that level -- this is also what makes the test faithful to the
   exit criteria's wording ("the active->completed transition driven by timerElapsed
   and not on one driven by seshEnded").

## Risks / non-obvious points for the implementer

- The unmount-cuts-off-audio risk described above is the main reason the player must live
  in `Sesh`, not `ActiveSesh` -- don't "simplify" by moving it down into `ActiveSesh`'s
  existing `onTimerElapsed`-triggering effect even though that looks like a shorter diff.
- Browsers often block autoplay/audio until a user gesture has occurred on the page.
  Starting a Sesh already requires pressing "Start a sesh with ...", so a user gesture will
  always have occurred earlier in the flow -- this should be enough for the browser to allow
  playback when the cue fires later, but call this out if the manual browser check shows a
  blocked/silent playback (e.g. missing `setAudioModeAsync` configuration or an autoplay
  policy issue) rather than silently working around it.
- Keep `Date.now()`/timer-elapsed detection entirely inside `ActiveSesh`'s existing effect
  and the reducer as today -- this task only adds a side effect reacting to the existing
  `timerElapsed`-driven transition, per `AGENTS.md`'s Sesh section.
- This is scoped to the web-only active platform per `AGENTS.md`'s "Active platform scope".
  Don't add iOS/Android-specific audio-session configuration (e.g. `setAudioModeAsync`
  background-playback options) -- none of that is needed for a short foreground cue anyway.
