# T293 plan: wordmark splash screen (iOS acceptance, Android config only)

## Findings that shape the plan (verified on origin/development)

- `app.json` already has an `expo-splash-screen` plugin entry: `backgroundColor: "#dfe8ca"` (sage), `image: splash-icon.png` (Expo template art), `imageWidth: 76`. The "yellow brand background" is `AppColors.yellow = '#f4c94d'` (`src/constants/theme.ts`). Per owner, the wordmark is typography only (ink `#18382e`, weight 900, as in `animated-icon.web.tsx` and the provider fallbacks).
- `src/app/_layout.tsx` calls `SplashScreen.preventAutoHideAsync()` at module scope and renders `<AnimatedSplashOverlay />`. On native that is `src/components/animated-icon.tsx`: an Expo-template leftover, a `#208AEF` blue overlay with `expo-logo.png`, which calls `SplashScreen.hideAsync()` on its first layout, so the native splash is hidden almost immediately, then a BLUE Expo-logo overlay animates out. This directly breaks the exit criteria (no hydration hold, a stray off-brand blue flash). Web uses `animated-icon.web.tsx` (text wordmark, sage), which must stay untouched in behavior.
- Hydration gates already exist and are the source of truth: `IdentityProvider` (auth `initializing`), `UserProfileProvider`, `PracticeHistoryProvider` and the other domain providers all render a "Loading your practice..." fallback until hydrated, and only mount children after. Anything mounted inside the innermost provider in `src/app/app/_layout.tsx` is therefore by construction post-hydration.
- `/` on native is `NativeStartRoute` (T292): `useNativeStartRoute` returns `undefined`-ish/null while the AsyncStorage read is pending, `'redirect-home'` for onboarded users (then `/app/home` mounts the provider gate), or `'show-start'`.
- Routes that never pass through the `/app` provider tree: `src/app/auth/*`, `feedback.tsx`, `account-deleted.tsx`, `IdentityProvider`'s `refreshFailed` recovery screen, and the root `ErrorBoundary` (`FatalErrorFallback`). If the splash is held and none of these hides it, the user is stranded behind the splash. This is the main risk of the ticket.

## Design

Native splash is held by `preventAutoHideAsync` (already present) and hidden by an explicit, idempotent "app is showing real UI" signal emitted from the first real screen, not by a timer and not by the overlay. No new hydration logic: the signal piggybacks on the existing gates.

## Steps

1. **Wordmark asset.** Create `assets/images/splash-wordmark.png`: the text "Daily Dama", transparent background, color `#18382e`, weight 900, letter-spacing about -0.03em, rendered at roughly 3x (about 900 px wide). Generate it with a throwaway script (headless Chrome / ImageMagick / sharp with the same system font the web wordmark uses; keep the script out of the repo or in `outputs/` only if reusable). Typography only, no mark or artwork. Delete or leave `splash-icon.png` only if still referenced elsewhere (grep first; android adaptive icon assets are separate).
2. **`app.json`.** Update the plugin entry: `image: ./assets/images/splash-wordmark.png`, `backgroundColor: "#f4c94d"`, `imageWidth` about 220 (tune on simulator), `resizeMode: "contain"`. Also set the same background for `dark` (or omit `dark` and confirm iOS does not switch to a white/black splash in dark mode; the app has `userInterfaceStyle: automatic`, so a dark-mode white flash is a real risk, check the simulator in dark appearance). Read `node_modules/expo-splash-screen` README/plugin types for SDK 57 (the installed version is the source of truth) to confirm option names; the plugin options differ from older SDKs. Android gets the same config via the plugin; do not verify it (record "not run").
3. **Splash-ready helper (shared, tiny).** Add `src/shared/splash/hide-native-splash.ts` exporting `hideNativeSplash()`: no-op on web (`Platform.OS === 'web'`), calls `SplashScreen.hideAsync()` once (module-level flag), and catches/logs rejection (hide failure must not crash the app; this is diagnostic only, no user-facing recovery needed). Add `src/shared/splash/splash-ready.tsx` exporting `<HideSplashWhenMounted />`: renders null, effect calls `hideNativeSplash()` after one `requestAnimationFrame` so the first real frame has been committed. Unit-test the helper (single call, web no-op, rejection swallowed) with `expo-splash-screen` mocked.
4. **Move `preventAutoHideAsync`** into the same module (`holdNativeSplash()` called from `_layout.tsx` at module scope, native only) so hold and release live together. Keep the call at module scope in the root layout (must run before first render). Catch its rejection too.
5. **Remove the native overlay.** Replace `src/components/animated-icon.tsx` native `AnimatedSplashOverlay` with nothing: the root layout must not render a native overlay. Cleanest: grep `AnimatedIcon`/`animated-icon` usage; if `AnimatedIcon` is unused (likely, see DESLOPPIFY.md), delete the native file's template content and leave `animated-icon.tsx` exporting `AnimatedSplashOverlay = () => null`, or rename the web file to `web-splash-overlay.web.tsx` with a null native sibling and update the import in `_layout.tsx` and the mock in `src/app/__tests__/root-layout.test.tsx` (it mocks `@/components/animated-icon`). Choose whichever leaves a single obvious web-only overlay; delete `expo-logo.png`/`logo-glow.png` only if nothing else references them. Update the comment in `animated-icon.web.tsx` that says its background "must match app.json's static splash backgroundColor": after this change it is only the web default-theme baseline, not native config.
6. **Release signals** (each mounts only when real UI is visible):
   - `src/app/app/_layout.tsx`: render `<HideSplashWhenMounted />` inside `AppThemeProvider` beside `AppTabs`. Do not place it above providers.
   - `NativeStartRoute`: render `<HideSplashWhenMounted />` only when `decision === 'show-start'`. For `redirect-home` and pending, keep the splash held; `/app/home` releases it after hydration (no flash of the null route).
   - `src/app/auth/_layout.tsx`, `feedback.tsx`, `account-deleted.tsx`: mount `<HideSplashWhenMounted />` (these render outside the provider gate and are directly deep-linkable).
   - `IdentityProvider` `RefreshFailedRecovery` branch and `FatalErrorFallback`: mount it too (FatalErrorFallback must stay dependency-free RN primitives; the helper only imports `expo-splash-screen`/`Platform`, which is acceptable, but keep it context-free).
   - Safety ceiling: in `holdNativeSplash()`, schedule a one-shot timeout (about 8 s) that calls `hideNativeSplash()` so no missed route can strand the user. Clear nothing; hide is idempotent. Document why in a comment.
7. **Tests.** Helper unit tests (step 3). Update `root-layout.test.tsx` mock as needed. Add a small test that `NativeStartRoute` mounts the release component only for `show-start` (extend `native-start-screen`/route tests, mocking the helper). Add an app-shell test or extend an existing `src/app/app/__tests__` test asserting the release component renders after the provider gate and not while a provider shows its loading fallback (the gating is the existing behavior; this protects the ordering). Keep web tests passing unchanged: `Platform.OS === 'web'` no-op.
8. **Docs.** Update `ARCHITECTURE.md` (the diagram at ~line 158 lists "Animated splash overlay"; describe: web overlay + native splash held until the first hydrated screen, release signals list). Note in `outputs/ios-personal-build-setup.md` that splash config changes need a native rebuild. Mark T293 done in the same commit per TASKS.md convention (move entry per the repo's practice).

## Risks and notes

- Splash image is raster by necessity (iOS storyboard needs an image); the font cannot be live text. Keep the source/generation recipe noted in the commit message so the PNG is reproducible.
- Yellow (splash) to sage (default screen background) is a visible color change at handoff; that is the owner's chosen design, not a bug. If it looks jarring on the simulator, report it rather than altering app theming.
- `hideAsync` can reject if called before the native view controller is ready; swallow and log (step 3). Never let the helper throw into render.
- Do not add a second hydration flag or context: the gate placement of the release component is the contract.
