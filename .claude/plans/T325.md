# T325 plan: keep long-form Save/Cancel reachable above the Android keyboard

## Findings (verified in current code)
- `src/components/ui/keyboard-aware-scroll.tsx` is a ~15 line `ScrollView` wrapper; only iOS gets props. Adopters: `src/app/app/tricks/index.tsx` (`FormScroll`, custom-trick forms), `all-notes-screen.tsx`, `trick-notes-screen.tsx`, `trick-goals-screen.tsx`, `profile/index.tsx`. Fixing the primitive covers all of them; no per-screen offsets.
- Expo ~57 / RN 0.86: Android edge-to-edge is always on and `app.json` sets no `softwareKeyboardLayoutMode`. Under edge-to-edge, `adjustResize` does not shrink the RN window, matching T322 (`InsetsSource type=ime`, no resize). So a config change is not the fix; do not spend time there beyond a quick confirmation. A JS-only solution needs no native rebuild.
- Decision (per orchestrator note): JS-only, built-in `Keyboard` events. Do NOT add `react-native-keyboard-controller` (native rebuild, dependency change). Mention it as the fallback only if the JS approach fails on the emulator.

## Design
1. Add `src/components/ui/use-android-keyboard-overlap.ts` (hook, one purpose): given a `ScrollView` ref, returns `{ overlap: number, onLayout, onScroll handlers? }`. Only active when `Platform.OS === 'android'`; on iOS/web it must subscribe to nothing and return 0.
   - Subscribe to `Keyboard` `keyboardDidShow`, `keyboardDidHide` (and `keyboardDidChangeFrame`? only if Gboard height changes, e.g. emoji/suggestion rows; include if cheap). Clean up subscriptions in the effect return.
   - On show: `scrollRef.current.measureInWindow((x, y, w, h) => ...)`; `overlap = max(0, (y + h) - e.endCoordinates.screenY)`. Measuring the real scroll view bottom (not using `endCoordinates.height`) absorbs the in-flow tab bar and nav-bar inset, mirroring the iOS comment's "real overlap" principle. On hide: overlap = 0.
   - Keep state a plain number; ignore stale async measure results after hide (compare a ref counter / bail if keyboard hidden).
2. `KeyboardAwareScroll` (keep `forwardRef`; merge the forwarded ref with an internal ref, e.g. callback ref setting both): on Android render a trailing `<View style={{ height: overlap }} />` after `children` (simpler than flattening the caller's `contentContainerStyle`; avoids breaking callers that pass styled-components styles). Also set `keyboardDismissMode: 'on-drag'` on Android? Optional; skip unless needed (scope).
3. Keep focused field visible: after overlap is applied (next frame / `onContentSizeChange`), read `TextInput.State.currentlyFocusedInput()`, `measureInWindow` it, and if its bottom > keyboardTop - margin (~16) or top < scroll view top, `scrollTo({ y: currentOffset + delta, animated: true })`. Track `currentOffset` via an internal `onScroll` (scrollEventThrottle 16) that also calls the caller's `onScroll`. Verify `currentlyFocusedInput` is available in RN 0.86 types; else use a `focus` listener alternative. Covers the sequence form's `Search existing tricks` field at 720x1280. Re-run on `keyboardDidShow` only (not every keystroke).
4. Do not add a second scrolling mechanism; do not touch iOS props or web output (web DOM must be unchanged: no spacer when not Android).
5. Update the Android sentence in the `ARCHITECTURE.md` "Keyboard-aware forms" paragraph (line ~725): describe Android overlap spacer + focused-field scroll, remove the "wrapper does nothing / tracked as T325" text; keep "physical devices unverified".

## Tests (jest, react-test-renderer; extend `keyboard-aware-scroll.test.tsx`)
- Mock `Keyboard.addListener` (jest spy capturing handlers) and `measureInWindow` on the ScrollView instance (via ref/`jest.spyOn` on the host component or a mocked ref).
- Android: after `keyboardDidShow` with `screenY` below the scroll bottom, no spacer height (overlap 0); with overlap N, spacer height equals N; after `keyboardDidHide`, spacer 0; listeners removed on unmount.
- iOS and web: no `Keyboard.addListener` call and no spacer child; existing three tests unchanged and still passing.
- Stale-result case: hide arrives before measure callback resolves -> overlap stays 0.

- Gboard height changes while open (suggestion strip): handle `keyboardDidChangeFrame` or accept minor staleness.
