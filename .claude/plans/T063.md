# T063 — Preselected-trick "Start sesh" variant

## Signal design

Add a new `mode` search param, value `'practice'`, sent only by the five
practice-entry call sites alongside their existing `trickId` (and, for the
Challenge action, `plannedDurationMs`). A plain visit to `/sesh` never sets
`mode`, so `lastSesh`-driven prefill is completely untouched.

Gate on **two** independent things, per the task notes:
1. `mode === 'practice'` was explicitly present in the URL — computed in
   `src/app/sesh/index.tsx` from the raw param, not from the merged
   `preferredTrickId ?? lastSesh?.trickId` value, so a future link that sets
   `mode=practice` without `trickId` cannot accidentally fall back to
   `lastSesh` and enter quick-start.
2. `validatedPreferredTrickId` (already computed inside `Sesh`) resolves —
   i.e. the linked trick is actually in `practiceTricks`. If it's stale/
   removed, fall back to the full picker rather than showing a dead quick-
   start screen.

## Files and order

- Compute `const isQuickStartRequested = mode === 'practice' && typeof trickIdParam === 'string';` (keep the existing

Do this file first: it's the only place that knows about the raw URL, and the prop it produces is what step 2 gates on.

- Add the new `QuickStart` component near `TrickPicker` (after `EmptyState`, before `TrickPicker`, or right after
  `TrickPicker` — match existing file ordering conventions):
  ```tsx
  function QuickStart({
    trick,
    initialPlan,
    sessions,
    onStart,
  }: {
    readonly trick: PracticeTrick;
    readonly initialPlan?: SeshPlan;
    readonly sessions: readonly PracticeSessionRecord[];
    readonly onStart: (
      trick: PracticeTrick,
      plan: SeshPlan,
      personalBest: number | undefined,
      liveChallengeEnabled: boolean,
    ) => void;
  }) {
    const plan = initialPlan ?? createTimedSeshPlan(5);
    const personalBest = plan.kind === 'timed' ? getPersonalBest(sessions, trick.id, plan.durationMs) : undefined;

    return (
      <CenteredPanel>
        <Eyebrow>Ready when you are</Eyebrow>
        <DisplayTitle>{trick.name}</DisplayTitle>
        {trick.descriptor ? <BodyCopy>{trick.descriptor}</BodyCopy> : null}
        <SequenceSteps trick={trick} />
        {personalBest !== undefined ? (
          <ChoiceBest>
            Best at {formatDuration(plan.durationMs)} — {personalBest} {personalBest === 1 ? 'lace' : 'laces'}
          </ChoiceBest>
        ) : null}
        <PrimaryButton
          accessibilityLabel={`Start a sesh with ${trick.name}`}
          onPress={() => onStart(trick, plan, personalBest, false)}>
          Start sesh
        </PrimaryButton>
      </CenteredPanel>
    );
  }
  ```
  Notes on this component:
  - Reuses existing styled primitives (`CenteredPanel`, `Eyebrow`, `DisplayTitle`, `BodyCopy`, `SequenceSteps`,
    `ChoiceBest`, `PrimaryButton`) — no new styled-components needed.
  - `liveChallengeEnabled` is hardcoded `false` (the toggle is setup UI the exit criteria says to omit; "reveal at
    the end" is the existing default behavior anyway).
  - Default plan is `createTimedSeshPlan(5)` when there's no `initialPlan` (first-ever quick-start, no `lastSesh`,
    no `plannedDurationMs`) — mirrors `TrickPicker`'s own default (`durationMinutes` state initializes to `'5'`).
  - Keep the accessibility label text identical to `TrickPicker`'s per-trick button label — existing tests in
    `sesh.test.tsx` locate the picker's start button via
    `findByAccessibilityLabel(root, \`Start a sesh with ${TRICK.name}\`)`; those tests don't set `quickStart`, so
    they'll keep hitting `TrickPicker`, but keeping the label consistent means new quick-start tests can reuse the
    same helper.

## Risks / non-obvious things

- **Don't gate solely on `validatedPreferredTrickId`.** It's already true on every plain returning-user visit
  (that's the existing `lastSesh` behavior) — the `quickStart` boolean from the URL is the only thing that must
  distinguish "explicit practice entry point" from "plain tab visit," per the task notes. Get the AND order right:
  quick-start requires *both*.
- **`mode` must come from the raw param, not from a value already merged with `lastSesh`.** Computing
  `isQuickStartRequested` in `index.tsx` from `trickIdParam` directly (not from `preferredTrickId`) is what keeps
  this robust against a hypothetical future caller that sets `mode=practice` without `trickId`.
- Typed routes (`experiments.typedRoutes: true` in `app.json`) already tolerate the existing ad hoc `params` shapes
  (`plannedDurationMs` etc. aren't declared anywhere centrally), so adding `mode` to five `Link` params objects
  needs no route-type changes.
- T066 (goal → practice entry point, not in this task) is expected to reuse this same `quickStart` prop/param
  convention later — keep the naming (`mode=practice`, `quickStart` prop) unsurprising rather than bespoke to these
  five call sites, since another call site is coming.
