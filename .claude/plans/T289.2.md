## Method rules (lessons from T289.1)

1. Screenshots from the control tool lag actions. For every acceptance observation capture with `xcrun simctl io <udid> screenshot <scratchpad>/<name>.png` and Read that file. Name files `<device>-<row>-<step>.png` in the scratchpad dir only (never commit them).
2. One action, wait for any scroll/animation to settle (about 1 s, longer after inertial scroll), `simctl` screenshot, confirm state, then next action. Taps during inertial scroll are swallowed: after any swipe, take a screenshot before tapping and use short deliberate taps.
3. Do not chain more than one state-changing action between confirming screenshots. For text entry, type, screenshot, then tap Save.
4. Relaunch or navigate via `xcrun simctl openurl <udid> "dailydama://..."` only for orientation if lost; flows under test must be reached via real taps. Note in the record if a deep link was used.
5. Keyboard-visible layout acceptance belongs to T044: you must enter text, so the keyboard will appear; record only functional outcome, never judge keyboard overlap here. If the software keyboard is hidden by default on the simulator, toggle with Cmd+K only if needed for typing.
6. An automation failure (swallowed tap, tool crash, stale frame) is NOT a product finding. Retry once after settling; if still unreproducible record "blocked: <tool symptom>" for that row rather than a finding. A finding requires the symptom reproduced twice with simctl screenshots.
7. Never mark a row passed from source or unit tests.
