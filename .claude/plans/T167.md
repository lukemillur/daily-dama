# T167 -- Ask how long would you like to practice a day during onboarding

## Decision made during planning (not re-litigated by implementer)

"After Kentei rank assessment and before theme selection" is read as: after the rank-assessment and trick-selection phases (intro -> levelSelect -> assessing -> rankReveal -> selecting), immediately before themeSelect. Rationale: the duration question is orthogonal to which tricks you picked, and grouping the two functional questions (rank, then duration) before the purely cosmetic theme step keeps the onboarding flow ending on the "fun" step, matching the current UX shape (theme step is explicitly labelled "Last step"). Insert the new state as durationSelect, sitting strictly between selecting and themeSelect.

## Current state machine (src/features/onboarding/model/kentei-assessment.ts)

intro -> levelSelect -> assessing -> rankReveal -> selecting -> themeSelect

selecting transitions to themeSelect via the themeStepEntered action, fired by the Start practicing button in onboarding-selection-step.tsx (wired in kentei-onboarding.tsx's case 'selecting').

streakThresholdMs already exists on UserProfile (src/features/profile/model/user-profile.ts) with its own reducer action streakThresholdUpdated, provider action setStreakThresholdMs (src/features/profile/state/user-profile-provider.tsx), and full persistence support already in place. No persistence-layer changes are needed -- this task only adds a UI step that calls the existing action.

MIN_STREAK_THRESHOLD_MINUTES in user-profile.ts is 1 (Profile screen's own control allows 1-60 minutes as a post-onboarding edit affordance -- task notes say this stays as-is). The onboarding step needs a stricter 5-minute floor of its own. Do NOT change MIN_STREAK_THRESHOLD_MINUTES / isValidStreakThresholdMinutes in the shared model file -- that would tighten the Profile screen's control too, which is out of scope. Instead the new onboarding component enforces >= 5 as an additional local guard on top of the existing isValidStreakThresholdMinutes check (which still bounds it at 60 and requires an integer).

### 3. New component: src/features/onboarding/components/onboarding-duration-step.tsx

Model it directly on onboarding-level-step.tsx (layout/typography) and the StreakSettings sub-component in src/app/app/profile/index.tsx (duration input UI), but keep it a fully separate, self-contained file -- do not extract a shared component with the Profile screen; the task notes explicitly keep Profile's control as its own independent affordance.

Props: streakThresholdMs (optional number, current profile value, may be undefined) and onContinue: (thresholdMs: number) => void, which the parent uses to both save and advance.

Behavior:
- Local text state seeded from String((streakThresholdMs ?? DEFAULT_STREAK_THRESHOLD_MS) / 60000) (mirrors Profile's persistedMinutes calculation exactly, so a user who restarts onboarding after already customizing their threshold sees that value, not a hardcoded 5).
- parsedMinutes = Number(minutesText).
- A local constant MIN_ONBOARDING_STREAK_MINUTES = 5.
- hasValidMinutes = isValidStreakThresholdMinutes(parsedMinutes) AND parsedMinutes >= MIN_ONBOARDING_STREAK_MINUTES (import isValidStreakThresholdMinutes, createStreakThresholdMs, DEFAULT_STREAK_THRESHOLD_MS from @/features/profile/model/user-profile).
- Numeric input: same shape as Profile's DurationInput (inputMode numeric, keyboardType number-pad, maxLength 2, selectTextOnFocus), with a distinct accessibilityLabel, e.g. 'Practice minutes per day' (must differ from Profile's 'Streak threshold in minutes' so tests/automation never conflate the two screens, even though they never render simultaneously).
- Hint text mirrors Profile's pattern but with the 5-minute floor: valid text 'Choose any whole minute from 5 to 60.', invalid text 'Enter a whole number from 5 to 60.'
- One Continue button (accessibilityLabel 'Continue to theme selection', visible text 'Continue', disabled when not hasValidMinutes) that calls onContinue(createStreakThresholdMs(parsedMinutes)) -- do NOT call onContinue per keystroke; only on press, matching Profile's explicit-Save pattern (notes: 'this step only sets the initial value').
- Copy: title uses the literal question, e.g. broken across two lines: 'How long would you' newline 'like to practice a day?'; a short line of body copy noting it can be changed later from Profile (this is genuinely useful since Profile keeps its own editable copy of the same field -- surfacing that avoids the user feeling locked in).

## Risks / things to double check while implementing

- TypeScript exhaustiveness: KenteiOnboarding's switch(state.status) has no default case today, so adding durationSelect to the union without adding a matching case will surface as a tsc error (implicit undefined return), not a silent bug -- good, but don't skip the tsc pass expecting it to 'just work.'
- Don't let the new component's Continue button fire onContinue on mount or on every keystroke -- only on explicit press, otherwise a user typing '1' then '12' would transiently persist an invalid/mid-typing value.
- Keep the durationSelect state's field shape identical to selecting's (no new fields) -- the entered minutes value is transient local component state plus an immediate write to the profile provider on Continue, not part of the reducer's state, mirroring exactly how theme color selection already works.
