## Design

1. **Typed action list, a pure module** (new `src/features/tricks/model/trick-row-actions.ts`, or `components/` if it needs React types; prefer `model/` and keep it React-free):
   ```ts
   export type TrickRowActionId = 'practice' | 'notes' | 'goals' | 'edit' | 'delete';
   export interface TrickRowAction {
     readonly id: TrickRowActionId;
     readonly label: string;               // 'Practice' | 'Notes' | 'Goals' | 'Edit' | 'Delete'
     readonly accessibilityLabel: string;  // `Practice ${name}`, `Notes for ${name}`, `Goals for ${name}`, `Edit ${name}`, `Delete ${name}`
     readonly destructive: boolean;
     readonly side: 'leading' | 'trailing'; // practice = leading (swipe right); the rest trailing
     readonly onSelect: () => void;
   }
   export function buildTrickRowActions(trick, handlers: { onPractice?, onOpenNotes?, onOpenGoals?, onEdit?, onDelete? }): readonly TrickRowAction[]
   ```
   - Only include an action when its handler is defined. Edit and Delete are included together, only for custom tricks with `customActions` (same rule as today: `onEdit && onDelete`).
   - Fixed order: practice, notes, goals, edit, delete. Trailing swipe shows notes, goals, edit, delete, with Delete outermost so it is last and furthest from the thumb start. T312.5 reuses the same list.
   - Notes and Goals labels carry no counts (the counts are T312.4's concern). The inline web labels keep the count text exactly as now; do not change them.
   - Use this list for the native swipe AND `accessibilityActions`. Optionally the inline web path could also consume it, but do not refactor the web JSX unless it is trivial. The web DOM and test labels must stay byte-identical.
2. **Practice navigation without `Link`**: the swipe Practice needs an imperative handler. Add `onPractice` built in `TrickDirectory` from `useRouter()` (`router.push({ pathname: '/app/sesh', params: { trickId, mode: 'practice' } })`), or better, have the route pass a `practiceAction` handler. Keep it minimal: extend `practiceAction` from `true` to `true | { onPractice(trick) }`? Simpler: add a new optional prop `rowActionStyle?: 'inline' | 'swipe'` (default `'inline'`). When `'swipe'` and `practiceAction` is set, the directory calls `useRouter().push(...)`. Check that existing directory tests (which render `TrickDirectory` without a router) still pass. They already render `Link`, so expo-router works there. If `useRouter` throws without a navigation container in the test env, instead make `practiceAction` accept `{ onOpen(trick) }` like Notes and Goals and have the route do the push (preferred for consistency anyway). Decide by trying `useRouter` in a test first.
3. **Swipe wrapper** (new `src/features/tricks/components/trick-row-swipeable.tsx`, one purpose: wrap row content with `ReanimatedSwipeable`):
   - `import ReanimatedSwipeable, { type SwipeableMethods } from 'react-native-gesture-handler/ReanimatedSwipeable'`.
   - `renderLeftActions` renders the leading action (Practice). `renderRightActions` renders the trailing actions as a row of fixed-width (~84 px, min 44 pt tall) buttons: label text always shown, Delete uses the existing red `#d84929` with a light label, other actions a dark-green or neutral fill. Use `Pressable` with `accessibilityRole="button"` and the action's `accessibilityLabel`. Selecting an action calls `swipeable.close()` first, then `onSelect`.
   - Set `overshootLeft={false}`, `overshootRight={false}`, and `friction={2}`. Avoid full-swipe auto-trigger: do not set `onSwipeableOpen` to run an action. Delete must never fire on a long swipe.
   - Keep a vertical scroll guard: `activeOffsetX={[-12, 12]}` is not a Swipeable prop. Instead use `dragOffsetFromLeftEdge`/`dragOffsetFromRightEdge` (~20) and `failOffsetY`-style behaviour built into Swipeable, and verify on device that vertical scroll works. If scrolling conflicts, raise the drag offsets.
   - **One open row at a time**: the directory holds a `useRef<SwipeableMethods | null>` for the currently open row. Pass `onSwipeableWillOpen={() => { if (openRef.current && openRef.current !== thisRef) openRef.current.close(); openRef.current = thisRef; }}`. Hold the ref in the directory (ref, not state, so no re-render) and pass `registerOpen(methods)` down. Clear it on `onSwipeableClose` if it is the same ref. Also close on list scroll begin (`onScrollBeginDrag`) as a small extra if cheap; it is not required.
   - Row background: the swipeable child must have an opaque background (`#f8f1dd`, or the laced `#e5edcf`) so the action panels do not show through. `TrickRowContainer` already has it.
   - **Accessibility**: set on the row's focusable wrapper `accessibilityActions={actions.map(a => ({ name: a.id, label: a.label }))}` and `onAccessibilityAction={(e) => actions.find(a => a.id === e.nativeEvent.actionName)?.onSelect()}`. Use the plain `label` for the rotor (`Practice`, `Notes`, `Goals`, `Edit`, `Delete`). A custom action `name` must be a stable string. The inner checkbox and indicator controls are separately accessible elements today (`SelectableIdentity`, `SelectionIndicatorButton`); put the actions on the identity element (the one VoiceOver lands on for the row), not on the outer container. Swipe panels render only while swiped, so hidden off-screen buttons must not be reachable by VoiceOver. `ReanimatedSwipeable` does not mount the panels until a swipe begins, so this should hold. Verify.
4. **`TrickRow` integration**: when `rowActionStyle === 'swipe'`, skip rendering `rowActionsElement`, set `hasRowActions` false for layout purposes (the compact `CompactBody` padding then returns to symmetric `8px 0`), and wrap the row in the swipe wrapper. The selection checkbox and identity toggle stay on the row. Tapping a row still toggles focus. Check that Pressable taps inside the swipeable still work and a tap on an open row closes it.
5. **Root provider**: wrap the app tree in `GestureHandlerRootView style={{ flex: 1 }}` in `src/app/_layout.tsx`, outermost, around `ThemeProvider`. Update `root-layout*.test.tsx` only if snapshots or tree assertions break. On web, `GestureHandlerRootView` renders a plain View, so confirm there is no layout change at 390 px and wide widths. The dev-client native build already links gesture-handler because it has been in `package.json` since the initial commit. Confirm `ios/Pods` or `pod install` output lists `RNGestureHandler` and that the build does not need a rebuild. If it does not, report that a rebuild is required rather than assuming.
6. **Route**: `src/app/app/tricks/index.tsx` passes `rowActionStyle={usesNativeHeader ? 'swipe' : 'inline'}` (and the practice handler if item 2 goes that way). Nothing else changes in the route.

## Risks and non-obvious points

- No `GestureHandlerRootView` exists yet. Without it, swipes silently fail on iOS release/dev builds. Add it first and test before building anything else.
- `ReanimatedSwipeable` inside a `SectionList` with sticky headers: confirm that row recycling and `extraData` do not leave a row stuck open. Include `rowActionStyle` in `extraData`.
- The existing comment in `trick-directory.tsx` about `Link asChild` and `stopPropagation` applies to the inline path only. Leave it there.
- Do not rely on colour alone for Delete: label text stays `Delete`, plus the red fill. Contrast: white or cream text on `#d84929` is about 4.1:1; use the cream `#fff8e5` as the custom section header already does. Check it is acceptable for bold 14 px text or darken the fill via the existing token.
- Keep a swipe action's tap target at 44 pt or more.
- Persist nothing; no schema or domain changes. No durability concerns: Delete only navigates to the existing confirmation.
