# T286 plan: contain Sesh celebration banners on phone widths

Scope: portable layout fix in `src/features/sesh/components/sesh.tsx` only. Per AGENTS.md "Active platform scope" no iOS simulator, no iOS-specific code. Verify on web at 320, ~390 and desktop widths; record the simulator exit-criterion check as deferred.

## Findings (current code)

- `CelebrationBanner` (~line 861) renders `<Animated.View style={{ opacity, transform: [{ scale }] }}>` wrapping `CelebrationBannerCard`.
- `CelebrationBannerCard` (~line 1372) has `width: 100%; max-width: 500px`. Its parent is the unstyled Animated.View, which is a child of `ActiveContent` (`width:100%; max-width:680px; align-self:center; align-items:center`, ~line 1276). Because `ActiveContent` centres children, the wrapper shrink-wraps to its content. A percentage width inside a shrink-wrapped parent is circular. In React Native/Yoga the card then sizes to its intrinsic content width, so the unbroken text line is not constrained to the screen. Likeliest root cause: the wrapper has no bounded width. Titles use hard `\n` breaks, so a long line such as "Moshikame x10 or more, Spike for the first time" cannot wrap early.
- Scale spring (`damping: 9`) overshoots 1 slightly (~1.0x). Scale from 0.55 to roughly 1.1 cannot explain overflow on both sides by itself. Treat overshoot as a secondary contributor and verify it, as the task notes say.
- Same `CelebrationBanner` serves GoalCelebrationBanner, PersonalBestBanner and FirstLaceBanner, in both ActiveSesh (~line 703) and CompletedSesh (~line 1036) via `ActiveContent`. One fix covers every variant.

## Steps

1. Reproduce first (web, Expo dev server on an explicit free port, not a static export). Seed or create a custom sequence named "Moshikame x10 or more, Spike" (see `src/features/tricks/...` custom sequence creation). Resize to 320 and 390 px. Run a Sesh, press Laced once. Confirm that the first-lace banner overflows, and note the measured wrapper and card widths (devtools). Web may not reproduce Yoga's behaviour exactly, so if web does not overflow, still apply the fix and rely on the structural test; record that honestly. Also try a personal-best banner (needs a prior best, then beat it) and a goal banner.
2. Fix in `CelebrationBanner`:
   - Replace the inline wrapper with a styled wrapper, e.g. `CelebrationBannerFrame = styled(Animated.View)` with `width: 100%; max-width: 500px; align-self: center; min-width: 0;` (or keep the inline style object for animated values and add width style alongside: `style={[frameStyle, { opacity, transform: [{ scale }] }]}`). The wrapper, not the card, owns the bounded width.
   - Move `margin-bottom: 20px` to whichever element is the outer one, to preserve spacing (no layout shift versus now).
   - Card: keep `width: 100%` (now resolves against a bounded parent); drop its own `max-width` if redundant, or keep it, but only one place should own it.
   - Texts: add `flex-shrink: 1` and `max-width: 100%` on `CelebrationBannerTitle` and `CelebrationBannerEyebrow` so long unbroken lines wrap. Keep `text-align: center`. Consider `overflow-wrap`/`word-break` only if a single long word still overflows (web); do not add platform-specific code.
   - Overshoot: if the measured card at spring peak exceeds the parent, set `transform-origin` is not portable, so instead cap overshoot by switching the spring to `overshootClamping: true`, or keep the spring and accept sub-pixel overshoot after step 1 measurement shows containment. Decide from the measurement; prefer not changing the animation feel unless it clips. Do not change timers (`CELEBRATION_VISIBLE_MS`, fade) or `autoDismiss` logic.
3. Do not touch event eligibility (`showFirstLaceCelebration`, goal baselines, `isFirstLaceForTrick`), counters, reducers or Sesh transitions.
4. Tests in `src/features/sesh/components/sesh.test.tsx` (react-test-renderer; no layout engine, so assert structure/style contracts):

No export needed (no routing/config/deps change) unless styled-components usage of `styled(Animated.View)` raises concern; if used, `node .claude/scripts/verify.mjs --skip-export` is optional.

## Risks

- `styled(Animated.View)` with styled-components/native: simpler and safer to keep `Animated.View` with a combined style array including a plain style constant. Check the existing pattern in the file before choosing.
- Jest cannot prove on-device containment; the exit criterion's simulator check stays deferred and must be recorded as such rather than claimed.
- Changing `align-self`/width on the wrapper could alter centering in `ActiveContent` on wide screens; confirm in step 6.
