# T069.2 — Route the remaining nested Tricks screens

## Scope and convention

Apply T069.1's established convention to every remaining top-level Tricks
destination: each destination gets an Expo Router screen in the existing
headerless `src/app/tricks/` stack, and each route adapter owns an explicit
back action that replaces `/tricks`. Transient states inside a destination
remain local component state rather than becoming additional URLs. This keeps
unsaved form state out of the address bar while giving browser/native back
semantics to the actual screen-level destinations.

Use these route shapes:

- `/tricks/[trickId]/notes` for a trick's Notes screen.
- `/tricks/notes` for the all-notes archive.
- `/tricks/goals` for all trick goals.
- `/tricks/laced` for the laced-tricks grid.
- `/tricks/custom/new` for custom-trick choice plus standalone/sequence creation.
- `/tricks/custom/[trickId]/edit` and `/tricks/custom/[trickId]/delete` for the
  custom-trick edit and delete-confirm destinations.

The existing `/tricks/[trickId]/goals` route remains the reference adapter.
Static routes must remain distinct from the dynamic `[trickId]` segment, and
all route adapters should retain the existing onboarding guard, provider
lookups, and `Screen` edge treatment. Invalid or missing resource IDs should
replace the URL with `/tricks` rather than render an ambiguous screen.

## Ordered implementation plan

1. **Move all remaining top-level view selection out of the Tricks index.**
   In `src/app/tricks/index.tsx`, remove the local selector state and
   conditional branches for notes, all notes, all goals, laced tricks, custom
   creation, custom edit, and custom delete. Replace their directory/header
   actions and custom-row callbacks with typed `router.push` calls to the new
   route shapes. Keep the directory data derivations and the existing
   selection/count/action behavior in the index route. Once no pseudo-screen
   remains there, remove its parent-tab reset effect and let
   `src/app/tricks/_layout.tsx`'s already-mounted tab listener replace every
   nested route with `/tricks` on a Tricks-tab press.

2. **Add route adapters for the resource and archive screens.**
   Create `src/app/tricks/[trickId]/notes.tsx` using the goals-route lookup
   pattern to resolve standard or custom tricks and render `TrickNotesScreen`.
   Create `src/app/tricks/notes.tsx`, `goals.tsx`, and `laced.tsx` to assemble
   the same provider-derived props currently assembled by `index.tsx`, then
   render `AllNotesScreen`, `AllTrickGoalsScreen`, and `LacedTricksScreen`.
   Each adapter passes an explicit `onBack={() => router.replace('/tricks')}`
   and redirects invalid resource URLs to the index route where applicable.

3. **Add custom-trick create/edit/delete route adapters.**
   Extract or export the existing `ChoiceScreen`, `CustomTrickForm`, and
   `DeleteConfirmation` presentation pieces from `index.tsx` without changing
   their domain actions or draft validation. Add `src/app/tricks/custom/new.tsx`
   with the current `list`/`choose`/`standalone`/`sequence` state machine,
   `src/app/tricks/custom/[trickId]/edit.tsx` resolving only custom tricks, and
   `src/app/tricks/custom/[trickId]/delete.tsx` resolving only custom tricks.
   The edit/delete adapters should redirect missing, standard, or invalid IDs
   to `/tricks`; successful save/delete and explicit back/cancel actions should
   return to `/tricks` deterministically. Preserve focused-trick updates and
   deletion cleanup exactly as they work today.

4. **Replace Close contracts with route-owned Back contracts.**
   Rename the screen-level `onClose` props and controls in
   `trick-notes-screen.tsx`, `all-notes-screen.tsx`,
   `all-trick-goals-screen.tsx`, and `laced-tricks-screen.tsx` to `onBack`,
   using clear Back-to-Tricks copy and accessibility labels. Keep each
   screen's local list/add/picker/edit transitions local. For per-trick Notes,
   preserve add/edit as local steps, but wire the edit form's cancel/back action
   to the route-level `onBack` so abandoning an edit can exit directly to
   Tricks instead of requiring Cancel to list followed by a second former
   Close action. Add/save behavior should continue to return to the notes list
   where that is the existing successful workflow.

5. **Add focused route and component regression coverage.**
   Add route tests under `src/app/tricks/__tests__/` for each adapter's
   destination props, explicit `/tricks` back action, and invalid custom/trick
   IDs. Extend the layout test to establish that a Tricks-tab press replaces
   any child route with `/tricks` and ignores other tabs. Update component tests
   for Back labels and retained local transitions, including Notes add/edit and
   the direct edit-exit behavior. Add coverage for custom create/edit/delete
   route wiring where the current inline components have no route boundary.
   Keep domain/persistence contracts unchanged; tests should verify navigation
   and existing mutations rather than duplicate reducer coverage.

6. **Verify the web finish line.**
   Run focused tests first, then `node .claude/scripts/verify.mjs` (or the
   standard Yarn test/lint/typecheck/web-export sequence). Start Expo's web
   development server and manually visit every new URL from the Tricks
   directory: trick notes, all notes, all goals, laced, custom create (both
   kinds), custom edit, and custom delete. Confirm each has a real URL, its
   Back control returns to `/tricks`, local transitions remain usable, and the
   Tricks tab returns home from each route, including while a local form/edit
   state is open. Search the Tricks feature area for remaining rendered
   `Close` controls. Do not launch or claim iOS/Android validation; native
   validation is deferred by the active AGENTS.md scope.

## Non-goals and assumptions

- Do not route add/edit/picker substeps as separate URLs; T069.1's convention
  keeps transient destination state local.
- Do not change persistence schemas, domain reducers, practice-history
  snapshots, or custom-trick invariants.
- Do not alter the established T069.1 goals route beyond sharing its adapter
  and tab-reselect convention.
- A direct route to a deleted custom trick or an invalid trick ID returns to
  `/tricks`; no migration or route-history recovery mechanism is needed for
  this prototype.
