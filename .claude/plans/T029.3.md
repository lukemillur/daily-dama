# [T029.3] Hide the timer during an assessment — implementation plan

## Current shapes (confirmed against `task/T029.3-hide-timer-during-assessment`)

- `ActiveSesh` (`src/features/sesh/components/sesh.tsx:465-649`) renders the elapsed-time
  readout unconditionally as two styled components right after the trick notes panel:
  `<TimerLabel>{plan.kind === 'timed' ? 'Time remaining' : 'Elapsed time'}</TimerLabel>` and
  `<Timer accessibilityLabel="...">{formattedTime}</Timer>` (lines 588-592).
- `formattedTime`/`displayedTime`/`elapsedMs` all derive from `now`, which comes from the local
  `useNow(startedAt, isPaused)` hook (lines 516, 676-684). `useNow` runs a `setInterval` that
  ticks `now` every 250ms whenever the sesh isn't paused — independent of whether the timer UI
  is shown. `elapsedMs` also feeds `onTimerElapsed` (timed-plan auto-completion, line 566-568)
  and time-based goal-crossing detection (lines 533-545), so it must keep being computed
  regardless of display.
- Assessment mode has no explicit "isAssessment" flag anywhere. `AssessmentEntry`
  (`src/features/sesh/components/assessment-entry.tsx:49-57`) is the **only** caller that
  drives an assessment run, and it does so entirely through `MultiTrickSesh`, using the same
  established pattern this task should extend: opaque, single-purpose props that `MultiTrickSesh`
  and `ActiveSesh` forward without knowing what "assessment" means (`showAttemptsReminder`,
  `endActionLabel="End assessment"`, `skipTarget`, `skipCountdownBetweenTricks`). There is no
  generic `isAssessment` boolean to key off — and introducing one would be a bigger, unrequested
  refactor of an already-settled pattern.
- `MultiTrickSesh` (`src/features/sesh/components/multi-trick-sesh.tsx`) forwards these opaque
  props to `ActiveSesh` at its `active`-status render branch (lines 213-238).
- The single-trick `Sesh` component's own `ActiveSesh` call (`sesh.tsx:165-186`) never supplies
  any of these assessment-only props — regular seshes only ever go through `Sesh`, assessments
  only ever go through `MultiTrickSesh`. Confirmed via `grep` — `AssessmentEntry` is the sole
  consumer of `MultiTrickSesh` outside of the multi-trick entry screen and the sandbox route.
- `Countdown` (`sesh.tsx:409-463`) does **not** render a running timer at all — just a 3-2-1
  countdown and one line of copy referencing `plan.kind`. Nothing to hide there.
- No existing test anywhere asserts on `TimerLabel`/`Timer` presence — this is new coverage,
  not a change to existing assertions.

## Approach

Add one new opaque, single-purpose prop — `hideTimer?: boolean` — threaded the same way
`endActionLabel` already is: `AssessmentEntry` → `MultiTrickSesh` → `ActiveSesh`. `ActiveSesh`
gates only the JSX render of `TimerLabel`/`Timer` on it; every computation that currently feeds
those two elements (`useNow`, `elapsedMs`, `displayedTime`, `formattedTime`, the timed-plan
auto-complete effect, time-goal-crossing detection) stays exactly as-is and keeps running
unconditionally, per the task's Notes.

## Steps

1. **`src/features/sesh/components/sesh.tsx` — `ActiveSesh`**
   - Add `readonly hideTimer?: boolean;` to the `ActiveSesh` props interface, grouped near
     `endActionLabel` (same "opaque, forwarded as-is" category).
   - Destructure `hideTimer` in the function signature.
   - Wrap the existing `<TimerLabel>...</TimerLabel>` and `<Timer ...>...</Timer>` block
     (lines 588-592) in `{!hideTimer ? (<>...</>) : null}`. Do not touch `useNow`, `elapsedMs`,
     `displayedTime`, `formattedTime`, or either `useEffect` that reads `elapsedMs` — leave them
     computed unconditionally so `onTimerElapsed` and time-goal celebrations keep working
     identically, and so the eventual `seshEnded`/`timerElapsed` dispatch still carries a real
     elapsed time into the summary.

2. **`src/features/sesh/components/multi-trick-sesh.tsx` — `MultiTrickSesh`**
   - Add `readonly hideTimer?: boolean;` to `MultiTrickSeshProps`, with a doc comment matching
     the style of the adjacent `endActionLabel` comment (opaque, forwarded to `ActiveSesh`
     as-is, used by the assessment flow since a countdown implies pressure that doesn't apply to
     an assessment).
   - Destructure it in `MultiTrickSesh`'s params.
   - Pass it straight through on the `<ActiveSesh ... hideTimer={hideTimer} />` call in the
     `active`-status branch (~line 214-238). No other logic in this component needs to change —
     it never reads or reasons about the value itself, same as `endActionLabel`.

3. **`src/features/sesh/components/assessment-entry.tsx` — `AssessmentEntry`**
   - Add `hideTimer` (boolean shorthand, same style as `showAttemptsReminder`) to the
     `<MultiTrickSesh ... />` call inside the `step.kind === 'running'` branch (~lines 49-57).

   Order matters only in that steps 1-2 must land before step 3 can compile — `AssessmentEntry`
   passing an undeclared prop would still type-check silently otherwise (TS wouldn't catch an
   extra prop unless it's excess-property-checked at a literal call site, which this is, so
   doing 1→2→3 in order avoids a spurious TS error mid-edit).

4. **Tests — `src/features/sesh/components/sesh.test.tsx`**
   Add a new `describe('ActiveSesh timer visibility', ...)` block, modeled directly on the
   existing `describe('ActiveSesh end action label', ...)` block (lines 297-362), which already
   renders `ActiveSesh` standalone with `PLAN = createTimedSeshPlan(5)` and asserts via
   `JSON.stringify(root.toJSON())`:
   - `renders the timer and its label when hideTimer is omitted`: render `ActiveSesh` with the
     same minimal prop set the `endActionLabel` tests use (no `hideTimer`), assert
     `JSON.stringify(root.toJSON())` contains `'Time remaining'` (the label text for a timed
     plan).
   - `hides the timer and its label when hideTimer is set`: same render with `hideTimer`, assert
     the JSON does **not** contain `'Time remaining'` (covers both the `TimerLabel` text and the
     `Timer`'s accessibilityLabel, which is prefixed with the same string).
   - Needs `beforeEach(() => jest.useFakeTimers())` / `afterEach(() => jest.useRealTimers())`
     like the neighboring block, since `ActiveSesh` always runs `useNow`'s interval.

5. **Tests — `src/features/sesh/components/multi-trick-sesh.test.tsx`**
   This is the file that proves the actual exit criterion end-to-end (assessment path vs.
   regular path, and the recorded `durationMs`), since recording only happens through
   `MultiTrickSesh`'s `recordCompletedSesh` effect, not through standalone `ActiveSesh`.
   - Extend `mountMultiTrickSesh`'s props type and JSX (lines 81-109) with an optional
     `hideTimer?: boolean`, forwarded to `<MultiTrickSesh ... hideTimer={props.hideTimer} />`.
   - Extend the `SessionSummary` harness (lines 69-79) to also expose each recorded session's
     duration, e.g. add
     `<Text accessibilityLabel={`session-${index}-duration:${session.durationMs}`} />`
     alongside the existing `session-${index}-lace-count:...` label — same pattern already used
     for `laceCount`.
   - Add a small helper near the other `find*` helpers to read that number back out, e.g.:
     ```ts
     function findSessionDurationMs(root: ReactTestRenderer, index: number): number {
       const [match] = root.root.findAll(
         (node) =>
           typeof node.props.accessibilityLabel === 'string' &&
           node.props.accessibilityLabel.startsWith(`session-${index}-duration:`),
       );
       if (!match) throw new Error(`No duration label found for session ${index}`);
       return Number(match.props.accessibilityLabel.split(':')[1]);
     }
     ```
   - Add a new `describe('MultiTrickSesh hideTimer', ...)` block, modeled on the existing
     `describe('MultiTrickSesh endActionLabel', ...)` block (lines 180-203), with
     `beforeEach`/`afterEach` fake-timer setup matching the other blocks in this file:
     - `hides the timer during an assessment-style run`: mount with `hideTimer: true`,
       `advanceThroughCountdown()`, assert `findByText(root, 'Elapsed time').length === 0` (the
       default plan in `mountMultiTrickSesh` is `OPEN_ENDED_SESH_PLAN`, so the label would read
       "Elapsed time" if shown) and also `findByText(root, 'Time remaining').length === 0` for
       completeness.
     - `shows the timer during a regular run`: mount without `hideTimer`, `advanceThroughCountdown()`,
       assert `findByText(root, 'Elapsed time').length > 0`. This is the "present in a regular
       sesh" half of the exit criterion — `MultiTrickSesh` without `hideTimer` stands in for
       "regular sesh" here since that's the component actually under test in this file; the
       single-trick `Sesh`/`ActiveSesh` pairing already covers the same thing in step 4.
     - `still records a real, non-zero durationMs while the timer is hidden`: mount with
       `hideTimer: true`, `advanceThroughCountdown()`, then
       `act(() => { jest.advanceTimersByTime(2000); })` to accrue real elapsed time, press
       `'Laced'`, then press `'End Sesh'` (default `endActionLabel`). Assert
       `findSessionDurationMs(root, 0)` is greater than `0` (don't hardcode an exact millisecond
       value — assert the inequality so the test isn't coupled to incidental timing of
       intervening renders). This is the direct proof that hiding the display didn't touch
       `useNow` or the timestamp math the Notes call out as load-bearing for Stats.

6. **No changes needed to:**
   - `Countdown` — it never rendered a running timer, nothing to hide.
   - The single-trick `Sesh` component — it never reaches assessment mode, so it never passes
     `hideTimer` and its existing behavior (timer always shown) is unaffected by construction.
   - `useNow`, `formatDuration`, `formatRemainingDuration`, or any model code in
     `src/features/sesh/model/sesh.ts` — this is purely a display gate in the component layer.

## Non-obvious / risk notes for the implementer

- **Don't gate the computations, only the JSX.** It's tempting to short-circuit `useNow` or
  `elapsedMs` when `hideTimer` is true since they're "only for display" — but `elapsedMs` also
  drives `onTimerElapsed` (auto-completing timed plans) and time-goal celebration detection, and
  `now` feeds into the elapsed time captured at `seshEnded`. Skipping any of that when hidden
  would either break timed-plan auto-completion (moot for assessments today since they use
  `OPEN_ENDED_SESH_PLAN`, but this prop has no such guarantee for future callers) or, worse,
  reproduce exactly the bug the Notes warn against — zeroed-out assessment durations in Stats.
  Gate only the two JSX elements.
- **Copy inconsistency left alone, on purpose.** `Countdown`'s body copy still reads "The clock
  starts after the countdown." for an open-ended plan even during a `hideTimer` run, since
  `Countdown` never received a `hideTimer` prop and doesn't render a timer either way. The task's
  Notes scope this as "display-only" for the elapsed-time readout specifically, and the exit
  criteria only mention "the timer and its label" (i.e. `TimerLabel`/`Timer`), not this line of
  copy. Flagging it here rather than folding it in silently — worth a follow-up ticket if it
  reads as inconsistent once verified in-browser, but out of scope for this task as written.
- **`hideTimer` vs. reusing `showAttemptsReminder`.** These two props happen to always be set
  together today (both only ever `true` from `AssessmentEntry`), which might tempt collapsing
  them into one flag. Don't — they're separate concerns (the attempts reminder is copy about a
  landing-attempt cap; this is about the countdown-style time pressure), and the codebase's
  established pattern here (see the doc comments on `endActionLabel`, `skipCountdownBetweenTricks`,
  etc.) is deliberately one opaque prop per concern rather than a bundled `isAssessment` switch.
