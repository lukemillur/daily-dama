## Ground rules
- Evidence must come from a real Android emulator running the normal UI. No deep links, no deletion. Do NOT open `custom/[trickId]/delete` or any Delete/Discard flow. Removing a *draft* step in the form is fine; deleting saved records is not.
- Preserve existing data: record a baseline first (Big cup note/goal/practice records may exist). Prefer a NEW AVD/fixture or a fresh guest install for fixtures; never wipe/clear the existing emulator data or uninstall the app on it.
- Do not treat failed injected drags as product evidence (D033 superseded). Use real swipes via `adb shell input swipe` with a durable duration (>=300 ms) or the emulator UI; if a gesture tool is unreliable, say so and fall back to manual owner-style scroll or `uiautomator dump` + keyboard-driven scroll. A case that cannot be driven is a blocker, not a pass.
- Every listed case must be executed and pass. Any failure: write it up precisely, file a focused follow-up ticket in TASKS.md (allocate next free ID across TASKS*.md), mark T322 Blocked, do not mark Done.

## Risks
- Emulator instability (first audit's Pixel_10/API 37 exited with QEMU hangs); prefer `Pixel_10_API36` if responsive, and record which one.
- Emulator is a shared, possibly owner-populated instance: snapshot-free fixture creation only; never `pm clear`, uninstall, `-wipe-data`, or `Delete` flows.
- Android keyboard reachability may genuinely fail (no Android keyboard-inset handling in `KeyboardAwareScroll`; `windowSoftInputMode` default may be adjustResize under edge-to-edge which behaves differently). Report as a failure with a ticket, not a workaround.
- Rank-picker drags previously changed rank by accident during injected drags; use taps for rank, and swipes starting outside the picker.
