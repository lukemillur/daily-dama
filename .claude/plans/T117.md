## T117.2 - Render the visitor's platform-matched screenshot set

Depends on T117.1's four new files and their real dimensions existing.

1. In `src/features/landing/components/landing-page.tsx`, restructure the
   screenshot data to guarantee title/caption parity between the two sets
   instead of hand-duplicating four strings twice (duplication is exactly
   what the Notes warn against risking - "don't fork captions per platform
   unless the screens' content actually differs"):

   interface ScreenshotContent {
     readonly title: string;
     readonly caption: string;
   }
   interface PlatformScreenshotAsset {
     readonly source: number;
     readonly alt: string;
     readonly aspectRatio: number;
   }
   type Screenshot = ScreenshotContent & PlatformScreenshotAsset;

   const SCREENSHOT_CONTENT: readonly ScreenshotContent[] = [ four existing title/caption pairs, unchanged ];
   const MOBILE_SCREENSHOT_ASSETS: readonly PlatformScreenshotAsset[] = [ existing four require()s, alt text, aspectRatio 375/812 ];
   const WEB_SCREENSHOT_ASSETS: readonly PlatformScreenshotAsset[] = [ new four require()s, distinct alt text noting web layout, aspectRatio from step T117.1's measured dimensions ];

   export const MOBILE_SCREENSHOTS: readonly Screenshot[] =
     SCREENSHOT_CONTENT.map((content, i) => ({ ...content, ...MOBILE_SCREENSHOT_ASSETS[i] }));
   export const WEB_SCREENSHOTS: readonly Screenshot[] =
     SCREENSHOT_CONTENT.map((content, i) => ({ ...content, ...WEB_SCREENSHOT_ASSETS[i] }));

   Exporting the two arrays gives the test a direct, literal way to satisfy
   "an automated test confirms both the mobile and web SCREENSHOTS arrays are
   defined" without relying on fragile prop-inspection alone.
2. In `LandingPage()`, add a `const { width } = useWindowDimensions();`, then

   importing both from `react-native` (already importing `ScrollView` from

   `multi-trick-sesh-entry.tsx` and `onboarding-selection-step.tsx` - no new

   old `SCREENSHOTS` constant, and replace the hardcoded

4. Delete the old single `SCREENSHOTS` constant entirely - nothing should
   still reference it.

## Risks / non-obvious points to flag to the implementer

- The `Platform.OS` default under `jest-expo` is `'ios'`, not `'web'` - don't
  assume a bare `useWindowDimensions` mock is enough to reach the web
  branch in tests; verified this directly by running a throwaway test file.
- Picking the web-capture viewport width happens in T117.1 but the exact
  pixel dimensions feed directly into T117.2's `aspectRatio` values - do the
  capture step first and measure the real files rather than guessing a ratio
  up front.
- Keep `SCREENSHOT_CONTENT` (title/caption) structurally shared between both
  platform arrays rather than duplicated, so the Notes' "don't fork captions"
  constraint can't silently drift as a maintenance issue.
- Don't leave a local-only Playwright install or seed script behind; T112.3's
  own resolution was to reinstall dependencies afterward so the shipped
  dependency tree and lockfile stayed unaffected.
