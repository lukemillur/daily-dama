# T062.1 -- Tag practice-history records with their originating flow

## Approach

Do **not** thread origin through `SeshState`/`SeshSummary`/the sesh reducer. The
reducer is the authority for countdown/active/completed transitions and knows
nothing about which screen invoked it (AGENTS.md: keep timer/pure-transition
logic centralized and free of caller-specific concerns). Instead, thread the
origin as a plain prop from each entry component down to the existing
`recordCompletedSesh(summary)` call site in `Sesh`/`MultiTrickSesh`, add it as
an optional second argument there, and carry it through the `sessionRecorded`
action into `createPracticeSessionRecord`. This mirrors how `previousBest` is
already computed outside the reducer and passed alongside the summary.

Field name/type: add to `src/features/stats/model/practice-history.ts`

```ts
export type PracticeSessionOrigin = 'assessment';
```

`PracticeSessionRecord.origin?: PracticeSessionOrigin`. Absent means regular
practice (single-trick Sesh or ad hoc multi-trick) -- no separate "regular"
literal is needed, matching the exit criteria's "no value at all round-trips
as regular, no migration."

## Risks / non-obvious points

- Keep `origin` out of `SeshSummary`/`SeshState` -- resist the temptation to add it there "for completeness." The reducer has no legitimate use for it (it doesn't affect countdown/active/completed transitions), and doing so would mean threading it through `trickSelected`/`countdownCompleted` actions across every dispatch site in both `Sesh` and `MultiTrickSesh`, which is unnecessary churn for a field that only needs to reach the record-construction call site.
- `MultiTrickSesh` records one `PracticeSessionRecord` per trick in the run (see its `useEffect` on `state.status === 'completed'`), so a single `origin` prop applies uniformly across every trick in one assessment run -- this matches the task's intent (the whole flow is assessment-sourced) and needs no per-trick distinction.
- Double-check `isSessionRecord`'s destructuring doesn't accidentally require `origin` to be present as a key -- it must remain a true optional check (`origin === undefined || origin === 'assessment'`), or existing/older persisted records without the key will start failing validation, which would violate "no migration required."
- `createPracticeSessionRecord`'s existing convention of always including a key with value `undefined` (as `plannedDurationMs` does) relies on `JSON.stringify` dropping `undefined`-valued keys automatically -- confirm the persistence round-trip test (step 9) actually exercises `serializePracticeHistory` -> `AsyncStorage`-shaped string -> `deserializePracticeHistory`, not just the in-memory object, so this assumption is checked rather than assumed.
