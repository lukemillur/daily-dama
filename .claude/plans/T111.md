## Ordering rationale

Steps 1-2 must happen together (deleting the directory without updating `_layout.tsx` breaks the build; updating `_layout.tsx` first without deleting the directory leaves dead code) -- do them as one atomic change before running any verification. Docs (steps 3-7) have no build dependency on the code change and can be done in any order relative to each other, but doing them after the code deletion means you can grep the actual diff to make sure every doc reference was caught. Step 8 (TASKS.md bookkeeping) should be last among the edits since it records the outcome of steps 1-7 and the verification in step 9. Step 9 (verification) must run after all code and doc edits so its "no remaining references" check is meaningful. Steps 10-11 are final confirmation, not committed changes.
