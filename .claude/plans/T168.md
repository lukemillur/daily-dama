# T168 — Whole trick-card tappable in the goal-creation trick picker

## Context established by exploration

- `TrickRow` lives in `src/features/tricks/components/trick-directory.tsx` (function `TrickRow`, ~line 227). It is reused by every `TrickDirectory` consumer with different, mutually exclusive optional action props: `onToggle` (checkbox selection — Tricks screen, onboarding, multi-trick Sesh entry), `onEdit`/`onDelete` (custom-trick edit/delete — Tricks screen only), `onOpenNotes`/`onOpenGoals` (Tricks screen only), `showPracticeAction` (Tricks screen only, renders an `expo-router` `Link asChild` around the `RowAction`), and `onActivate` (row "Choose" button).
- **`onActivate` is used at exactly one call site today**: `GoalTrickPicker` inside `src/features/goals/components/all-trick-goals-screen.tsx` (the "New goal to Choose a trick" step). That call site passes `onActivate` alone — no `selection`, `customActions`, `notesAction`, `goalsAction`, or `practiceAction`. This is the "goal creation trick picker" the task refers to.
- Today, `onActivate` renders a small `RowAction` labelled `Choose ${trick.name}` inside `RowActions`, separate from the identity content (`Position` + `TrickIdentity`).
- T143's pattern (`GoalRow` in `src/features/goals/components/trick-goals-screen.tsx`, ~line 108) wraps the entire card in `styled(Pressable)` (`GoalCardPressable`), tracks local `pressed` state via `onPressIn`/`onPressOut`, dims to `opacity: 0.7` while pressed, and lets `onPress` fire the primary action. Its one nested interactive child (`GoalAction` "Delete") calls `event?.stopPropagation?.()` before running its own handler. Note: `react-test-renderer` does not simulate real event bubbling — nested `onPress` calls never actually invoke ancestor `onPress` in tests. The `stopPropagation()` call only matters for real (web) DOM bubbling; the existing T143 test for it (`trick-goals-screen.test.tsx` ~line 155) simply asserts that pressing the nested action's `onPress` does not itself invoke the ancestor's side effect (trivially true) — it does not (and cannot) verify bubbling suppression. Match this same level of test rigor here; do not over-engineer around test-renderer's lack of real bubbling.
- No existing `trick-directory.test.tsx` coverage exercises `onActivate`/"Choose" at all. Coverage for the "Choose" label currently lives only in `all-trick-goals-screen.test.tsx` (search for `'Choose Stall'` / `'Choose Big Cup'`), which finds nodes purely by `accessibilityLabel` and calls `.props.onPress()` directly — it does not care which element in the tree carries that label, so it will keep passing as long as something still exposes `accessibilityLabel="Choose ${name}"` with an `onPress` that fires the same callback.

2. **Extract the shared row layout into a `css` block**, following the file's existing `identityLayout` pattern (~line 421), so the new Pressable-based container doesn't duplicate `TrickRowContainer`'s CSS by hand:

```ts
const trickRowLayout = css<{ readonly $selected: boolean; readonly $laced: boolean }>`
  min-height: 66px;
  flex-direction: row;
  align-items: center;
  background-color: ${({ $selected, $laced }) => ($selected || $laced ? '#e5edcf' : '#f8f1dd')};
  border-left-width: ${({ $laced }) => ($laced ? '4px' : '0px')};
  border-left-color: ${({ $laced }) => ($laced ? '#274137' : 'transparent')};
`;
const TrickRowContainer = styled.View<{ readonly $selected: boolean; readonly $laced: boolean }>`
  ${trickRowLayout}
`;
const ActivatableTrickRowContainer = styled(Pressable)<{
  readonly $selected: boolean;
  readonly $laced: boolean;
  readonly $pressed: boolean;
}>`
  ${trickRowLayout}
  opacity: ${({ $pressed }) => ($pressed ? 0.7 : 1)};
`;
```

Keep `TrickRowContainer` as the unchanged `View` for every non-`onActivate` context — this is the key regression guard, since every other reuse (Tricks screen, onboarding, multi-trick Sesh entry) never sets `onActivate` and must render byte-for-byte as before.

3. **In `TrickRow`**, add local `pressed` state (`const [pressed, setPressed] = useState(false);`), then restructure the render:
   - Keep the `identity` JSX fragment (`Position` + `TrickIdentity`) unchanged.
   - Keep the `onToggle ? <SelectableIdentity>... : <IdentityContainer>...` branch unchanged in content, but wrap `SelectableIdentity`'s `onPress` to accept an event and call `event?.stopPropagation?.()` before `onToggle()` — defensive only; `onToggle` and `onActivate` never coexist at any current call site, but this keeps the row internally consistent if that ever changes.
   - Compute `const hasRowActions = Boolean(onEdit && onDelete) || Boolean(onOpenNotes) || Boolean(onOpenGoals) || showPracticeAction;` and only render `<RowActions>...</RowActions>` when `hasRowActions` is true. This avoids the empty `RowActions` view (with its `padding-right: 12px`) adding dead space to the now-fully-tappable goal-picker row, where none of these props are ever set.
   - Remove the `onActivate`-driven "Choose" `RowAction` block entirely from inside `RowActions` (lines ~311-315 today) — activation moves to the outer container (next step).
   - Wrap the remaining `RowAction` `onPress` handlers (Edit, Delete, Notes, Goals) to accept an event and call `event?.stopPropagation?.()` before running their existing callback, e.g.:

```tsx
<RowAction
  accessibilityLabel={`Edit ${trick.name}`}
  accessibilityRole="button"
  onPress={(event) => {
    event?.stopPropagation?.();
    onEdit();
  }}>
```

Apply the same to Delete, Notes, and Goals. **Leave the `showPracticeAction` / `Link asChild` block as-is** — `Link` injects its own `onPress` into the child `RowAction`, so there is no clean seam to intercept it for `stopPropagation` without restructuring navigation. `practiceAction` and `onActivate` never coexist at any current call site (`practiceAction` is Tricks-screen-only; `onActivate` is goal-picker-only), so this is an accepted, documented gap — leave an inline comment on the `Link` block noting that if a future call site ever combines `practiceAction` with `onActivate`, this seam needs revisiting.

   - Branch the outer container on `onActivate`:

```tsx
if (onActivate) {
  return (
    <ActivatableTrickRowContainer
      $selected={isSelected}
      $laced={isLaced}
      $pressed={pressed}
      accessibilityLabel={`Choose ${trick.name}`}
      accessibilityRole="button"
      onPress={onActivate}
      onPressIn={() => setPressed(true)}
      onPressOut={() => setPressed(false)}>
      {identityElement}
      {hasRowActions ? rowActionsElement : null}
    </ActivatableTrickRowContainer>
  );
}

return (
  <TrickRowContainer $selected={isSelected} $laced={isLaced}>
    {identityElement}
    {hasRowActions ? rowActionsElement : null}
  </TrickRowContainer>
);
```

(Factor `identityElement` and `rowActionsElement` as local `const`s built once above this branch, to avoid duplicating the JSX between the two return paths.)

Net effect for the one real `onActivate` call site: the whole row (badge + name + meta) becomes the Pressable, dims to 70% opacity while pressed (matching `GoalCardPressable`), and carries the same `Choose ${trick.name}` accessibility label and `onPress` callback the old small button had — so `all-trick-goals-screen.test.tsx`'s label-based lookups keep passing unmodified.
