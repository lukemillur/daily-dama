# T076.1 — Define the Sesh tab reset route contract

## Good enough for this iteration

Pressing the existing Sesh tab while any nested route under `/sesh` is active must resolve to the canonical `/sesh` index route and remount the index-owned Sesh UI, so the user sees the Sesh home picker rather than stale nested setup, active, or wrap-up state. The existing five-link tab order and all persistent providers remain unchanged.

## Findings and contract

1. The root layout renders `NativeTabs` through `src/components/app-tabs.tsx`; its declared route order is `index`, `sesh`, `tricks`, `stats`, `profile`. Do not add, reorder, or replace a trigger.
2. `src/app/sesh/_layout.tsx` owns a `Stack` for `/sesh/index` and `/sesh/multi-trick`, matching the nested-stack structure already used by `src/app/tricks/_layout.tsx`.
3. The existing Tricks layout is the local precedent: obtain the parent tab navigator with `useNavigation().getParent()`, resolve the declared tab key from the parent navigation state, subscribe to `tabPress`, ignore other targets, and clean up the listener from the effect.
4. Implement the Sesh contract in `src/app/sesh/_layout.tsx`: when the event target matches the Sesh trigger key, call `router.replace('/sesh')`. Replacing the nested route with the canonical index is the reset/remount boundary; it must not add a navigation handle, timer, or transient Sesh state to a persistent provider.
5. Keep the listener narrowly scoped to the Sesh tab key. Do not reset on arbitrary navigation events, change direct finish/cancel destinations, or move local state out of `Sesh`/`MultiTrickSeshEntry`.

## Ordered implementation plan

1. Update `src/app/sesh/_layout.tsx` to import `useNavigation`, `useRouter`, and `useEffect`, preserve the headerless `Stack`, and add the parent-tab `tabPress` subscription described above. Use the same narrow event typing/cast pattern as `TricksLayout` because Expo Router’s hook type does not expose the tab event map directly.
2. Add `src/app/sesh/__tests__/layout.test.tsx` based on `src/app/tricks/__tests__/layout.test.tsx`. Mock the parent tab navigator with `index`, `sesh`, and another tab; render `SeshLayout`; invoke the captured listener; assert a Sesh target calls `router.replace('/sesh')`, another target does not, and the effect cleanup unsubscribes. This verifies the route-level mapping without storing navigation state.
3. Add a focused route/render regression check (in the same test file or a colocated Sesh index test) that models navigation from `/sesh/multi-trick` to `/sesh`, then renders `src/app/sesh/index.tsx` and asserts the home picker is present while the nested route/wrap-up content is absent. Mock provider hooks and the heavy Sesh component only as needed to keep this test about the route boundary; do not duplicate the Sesh reducer tests.
4. Add or retain a small root-tab contract assertion that the `AppTabs` trigger labels/names remain exactly `Home`, `Sesh`, `Tricks`, `Stats`, `Profile` in that order. If the existing NativeTabs test surface cannot inspect children cleanly, document the source-level assertion in the focused test rather than changing the tab implementation solely to make it testable.
5. Run the focused Sesh layout/render tests, then the repository verification sequence: `yarn test --runInBand`, `yarn lint`, `yarn tsc --noEmit`, and `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export`. Native validation is deferred by the active project scope.
6. If the focused web/browser check is available, navigate to `/sesh/multi-trick`, press Sesh, and verify the URL is `/sesh` and the picker is rendered. Record any inability to perform this interactive check separately; automated route and render evidence must still cover the contract.

## Acceptance mapping

- Nested Sesh tab press resolves to `/sesh`: Sesh layout listener test and focused browser check.
- Subsequent render is Sesh home picker: route/render regression test and focused browser check.
- Existing web five-link order is unchanged: `AppTabs` source/test assertion plus web export.
- No persistent navigation handles or transient state: implementation review; only ephemeral effect subscription and route replacement are introduced.
