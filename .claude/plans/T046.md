# T046 — Fix transient timer glitch on Sesh pause/resume

## Confirmed root cause (matches task Notes)

`useNow` in `src/features/sesh/components/sesh.tsx` (around line 666):

```ts
function useNow(initialTime: number, isPaused: boolean) {
  const [now, setNow] = useState(initialTime);
  useEffect(() => {
    if (isPaused) return;
    const interval = setInterval(() => setNow(Date.now()), 250);
    return () => clearInterval(interval);
  }, [isPaused]);
  return now;
}
```

While `isPaused` is true, the effect returns early and no interval runs, so `now`
is frozen at whatever value the last tick before pause set. On resume, `isPaused`
flips to `false`, the effect re-runs, but `setNow(Date.now())` only happens on the
*next* interval tick (up to 250ms later) — not synchronously on the render where
`isPaused` becomes `false`.

Meanwhile in `ActiveSesh` (line ~519):

```ts
const now = useNow(startedAt, isPaused);
const totalPausedMs = pausedDurationMs + (isPaused ? Math.max(0, now - pausedAt) : 0);
const elapsedMs = now - startedAt - totalPausedMs;
```

`pausedDurationMs` comes from the reducer and is already fully updated (includes
the entire pause) as soon as `seshResumed` is dispatched. But `now` is still stale
(frozen at/near the pause instant). For that first post-resume render:
`elapsedMs = staleNow - startedAt - pausedDurationMs`, which under-counts by
exactly the pause duration — for open-ended sessions this renders a displayed time
equal to the pause duration; for timed sessions it renders `plan.durationMs -
(correctElapsed - pauseDuration)`, i.e. too much time remaining by the pause
duration. Both symptoms are the same stale-`now` bug.

The reducer (`seshPaused`/`seshResumed` in `src/features/sesh/model/sesh.ts`,
lines ~168-176) is correct and already covered by `sesh.test.ts`. Do not touch it.

## Fix

Replace the freeze/effect-only approach with a render-time correction using the
standard React "adjust state during render when a prop changes" pattern (see
https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes).
Updating state directly during render (guarded by comparison against a previous
value stored in state) causes React to immediately re-render with the corrected
value *before* committing to the screen/DOM — no visible stale frame, unlike doing
the correction in a `useEffect`, which runs after paint.

Edit `useNow` in `src/features/sesh/components/sesh.tsx`:

```ts
function useNow(initialTime: number, isPaused: boolean) {
  const [now, setNow] = useState(initialTime);
  const [prevIsPaused, setPrevIsPaused] = useState(isPaused);

  if (isPaused !== prevIsPaused) {
    setPrevIsPaused(isPaused);
    if (!isPaused) {
      // Resuming: force an immediate, synchronous refresh so this render (not
      // the next 250ms interval tick) already reflects the correct elapsed time.
      setNow(Date.now());
    }
  }

  useEffect(() => {
    if (isPaused) return;
    const interval = setInterval(() => setNow(Date.now()), 250);
    return () => clearInterval(interval);
  }, [isPaused]);

  return now;
}
```

Notes on this shape:
- No import changes needed; `useState` is already imported in this file.
- Keep `initialTime` as the initial `now` value (matches current behavior on
  mount — unrelated to this bug, don't change it).
- Only correct `now` on the `true → false` (resume) transition. Pausing
  (`false → true`) doesn't need a synchronous correction — `now` staying at its
  last pre-pause value is exactly what should happen while paused, since the
  reducer freezes elapsed time via `pausedAt` display math in `ActiveSesh`.
- This is a single self-contained function; no other component-level or reducer
  changes are needed. `ActiveSesh`'s `totalPausedMs`/`elapsedMs` math (lines
  ~519-520) is already correct once `now` is fresh.

## Risks / non-obvious things

- The render-time `setState` pattern (adjusting `now` inside the render body) is
  safe and React-documented, but it's easy to instead reach for a `useLayoutEffect`
  or a `useRef`-based "did I already resume" flag combined with a `useEffect`.
  A `useLayoutEffect` calling `setNow` would also work (it runs before paint),
  but the render-time-adjustment pattern above is simpler and avoids an extra
  discarded render pass — prefer it over `useLayoutEffect` here.
- Do not add a synchronous `setNow(Date.now())` inside the existing `useEffect`
  unconditionally on every `isPaused` change (including pause→pause-again
  no-ops or mount) — only correct on the `true → false` transition specifically,
  matching the task's Notes and avoiding an unnecessary extra render on mount/pause.
- `ActiveSesh` is exported and already tested directly (not just through `Sesh`),
  so the new tests should drive `ActiveSesh` directly with hand-constructed
  `pausedAt`/`pausedDurationMs` prop sequences rather than mounting the full
  `Sesh` component and pressing buttons — this matches every existing test in
  the file and avoids unrelated setup (providers, trick selection, etc.).
- Jest fake timers in this file are used in "modern" mode (default), which mocks
  `Date.now()` and advances it together with `advanceTimersByTime` — existing
  tests already rely on this (e.g. `startedAt={Date.now()}` in mounts), so no
  extra `jest.setSystemTime` call should be needed, but verify the first test
  run produces the expected `now` progression before trusting the exact
  millisecond numbers above.
