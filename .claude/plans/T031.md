# T031 — Accept paused Sesh records when restoring practice history

## Root cause (confirmed)

`src/features/sesh/model/sesh.ts` `completeSesh` (lines 192-212) computes:

```ts
durationMs: endedAt - state.startedAt - totalPausedMs
```

So any completed Sesh that was paused at least once produces a summary where
`durationMs < endedAt - startedAt` by design — `durationMs` is *active
practice time*, not wall-clock elapsed time. This is correct and does not
need to change.

`src/features/stats/persistence/practice-history-persistence.ts`
`isSessionRecord` (line 43) currently enforces:

```ts
durationMs === completedAt - startedAt &&
```

This exact-equality check rejects every valid paused-session record on
restore (`deserializePracticeHistory` returns `undefined`, and
`loadPracticeHistory` falls back to `status: 'recovered'`, silently wiping
practice history that contains any paused session). This is the one and
only place in production code that encodes this invariant — confirmed via
`grep -rn "completedAt - startedAt" src` (single non-test hit).

`src/features/stats/model/practice-history.ts` `createPracticeSessionRecord`
just copies `summary.durationMs` → `durationMs` and `summary.endedAt` →
`completedAt` verbatim — no change needed there either. The bug is isolated
to the validator's inequality.

## Plan

1. **Fix the validator** — `src/features/stats/persistence/practice-history-persistence.ts`,
   line 43. Change:
   ```ts
   durationMs === completedAt - startedAt &&
   ```
   to:
   ```ts
   durationMs <= completedAt - startedAt &&
   ```
   This is the entire functional fix. Keep it scoped to `isSessionRecord`;
   don't touch `serializePracticeHistory`/`deserializePracticeHistory` or
   the document version — per AGENTS.md this is schema-version-1 validation
   logic, not a document-shape change, so no version bump or migration is
   warranted.

2. **Add an integration-style restore test** in
   `src/features/stats/persistence/practice-history-persistence.test.ts`
   that exercises the real pipeline the exit criteria describes (Sesh →
   summary → history record → serialize → restore), rather than only
   hand-built fixtures:
   - Import `seshReducer`, `INITIAL_SESH_STATE`, and `OPEN_ENDED_SESH_PLAN`
     (or `createTimedSeshPlan`) from `@/features/sesh/model/sesh`, and
     `createPracticeSessionRecord` from
     `@/features/stats/model/practice-history`. A minimal `PracticeTrick`
     fixture will be needed (check `@/features/tricks/model/trick` for the
     shape — reuse whatever minimal shape existing sesh tests construct,
     e.g. `sesh.test.ts` around line 124, rather than inventing a new one).
   - Drive the reducer through the real transition sequence: `trickSelected`
     → `countdownCompleted` (`now: t0`) → `seshPaused` (`now: t0 + 10_000`)
     → `seshResumed` (`now: t0 + 40_000`) → `seshEnded`
     (`now: t0 + 70_000`). This yields a completed summary whose
     `durationMs` (40_000 active ms) is strictly less than
     `endedAt - startedAt` (70_000 wall-clock ms) — a genuine paused
     record, not a hand-crafted one.
   - Build a `PracticeSessionRecord` via `createPracticeSessionRecord(summary, undefined)`,
     wrap it in a `PracticeHistory`, run it through
     `serializePracticeHistory` → `deserializePracticeHistory`, and assert
     the round trip returns the same history (this is the test that fails
     today against `development` and must pass after step 1).
   - In the same test (or an adjacent one at the same boundary), assert the
     existing non-paused `HISTORY` fixture (already in this file, where
     `durationMs === completedAt - startedAt` exactly) still round-trips —
     the existing "loads valid completed sessions" test already covers
     this under the new `<=`, so just confirm it stays green; no new
     assertion strictly required, but a comment noting it covers the
     non-paused boundary is worth adding.
   - Add a rejection case to the existing `it.each([...])` malformed-record
     list (lines 85-93): a record shaped like `HISTORY.sessions[0]` but with
     `durationMs: HISTORY.sessions[0].durationMs + 1` (i.e.
     `durationMs > completedAt - startedAt`) — assert it still gets
     rejected (`status: 'recovered'`, empty history). This is the exit
     criteria's third boundary ("records whose active duration exceeds
     their total wall-clock span are rejected") and is the one case that
     must *not* start passing after the `<=` change.

3. No changes needed to `src/features/sesh/model/sesh.ts`,
   `src/features/sesh/model/sesh.test.ts`,
   `src/features/stats/model/practice-history.ts`, or
   `src/features/stats/state/practice-history-provider.tsx` — confirmed by
   reading `completeSesh`, `createPracticeSessionRecord`, and the provider's
   `sessionRecorded` dispatch call; none of them assume wall-clock equality.

## Order

Step 1 (validator fix) before step 2 (tests), since the new paused-record
round-trip test is expected to fail against the current `===` check and
pass only once the inequality is in place — write the fix first so the test
run in step 2 is a real green-bar confirmation, not a red-then-green you
have to hold in your head.
