# T077.2 — Allow direct-practice users to customize before starting

## Goal

When Sesh is opened through a direct-practice link (`trickId` plus
`mode=practice`), show the normal single-trick planning controls before the
run starts. Keep the linked trick selected/prioritized in the picker without
mutating the user's focused-trick list, and pass the user's validated timed or
open-ended plan into the existing countdown flow. Plain `/sesh` visits and the
T077.1 post-completion route reset must retain their current behavior.

## Ordered implementation plan

1. Update `src/features/sesh/components/sesh.tsx` to use the existing
   `TrickPicker` as the direct-practice pre-run surface.
   - Preserve the existing `selectSeshPracticeTricks` behavior and its
     `preferredTrickId` support: the linked practice trick should be included
     and rendered first even when it is not already in `selectedTrickIds`; do
     not mutate the focused-trick array or create a direct-entry-only list.
   - Replace the `QuickStart` choosing branch for a valid direct-practice
     entry with the same `TrickPicker` used by plain `/sesh`, passing the
     validated preferred ID and any existing `initialPlan`. This exposes the
     established timed/open-ended controls, duration input, optional target
     input, and their disabled/validation behavior without creating a second
     form.
   - Preserve the T077.1 entry-state boundary: direct practice may still be
     recognized as initial entry, but “Start another sesh” must continue to
     clear that entry context before `seshReset`, and the Sesh tab route reset
     must still land on canonical `/sesh`. If the quick-start flag becomes
     unnecessary after the branch change, remove it only if the resulting
     route/component behavior remains explicit and covered; do not alter the
     reducer, history records, or `lastSesh` contract.
   - Keep `QuickStart` only if another caller or fallback still needs it;
     otherwise remove the dead component and its tests rather than preserving a
     misleading locked-start abstraction.

2. Extend `src/features/sesh/components/sesh.test.tsx` with a focused direct
   practice planning flow.
   - Mount `Sesh` with `quickStart`, a preferred trick, and at least one other
     practiceable trick; assert the preferred trick is available and
     prioritized while the normal `Practice format`, `Timed`, and `Open-ended`
     controls are visible.
   - Exercise timed validation by editing the duration input to an invalid
     value and asserting the validation copy/disabled selection state, then
     enter a valid duration and select the linked trick. Assert the resulting
     countdown receives the chosen timed plan, including the selected duration.
   - Exercise the open-ended branch and optional target validation: switch to
     `Open-ended`, verify an invalid target prevents selection, then enter a
     valid target and assert the chosen plan carries that target into the
     countdown. Use the existing accessibility labels and renderer helpers so
     the test checks behavior rather than implementation details.
   - Retain or adjust the existing T077.1 completion test so it verifies that
     the post-completion “Start another sesh” state is still the canonical
     picker, and retain the plain-visit test to prove `/sesh` behavior is
     unchanged.

3. Update `src/app/sesh/__tests__/layout.test.tsx` only if route-level
   expectations need to reflect the new initial direct-practice surface.
   - Keep the existing `trickId`/`mode=practice` query harness and tab listener
     assertions, ensuring the route still resets to `/sesh` and renders the
     canonical picker rather than retaining a locked quick-start route.
   - Add assertions for the direct-entry picker only if the current mocked
     `Sesh` component needs a contract update; avoid duplicating the component
     interaction test at the layout level.

4. Verify the focused behavior and web baseline.
   - Run the focused Sesh component and Sesh layout Jest tests, then run
     `yarn lint` and `yarn tsc --noEmit`.
   - Run `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export`
     (or the repository verification wrapper if convenient) to confirm the
     route/query behavior remains exportable.
   - Do not perform iOS or Android validation; native hardening is explicitly
     deferred for this project iteration.

## Scope and assumptions

- No new route, persistence field, reducer state, or second plan model is
  needed. `SeshPlan` and `TrickPicker` are already the canonical planning
  boundary.
- The direct link's trick ID remains a preferred/prioritized selection, not an
  exclusive selection. Users can choose another listed trick after customizing
  the plan, consistent with the normal single-trick Sesh picker.
- `initialPlan` continues to seed the picker when supplied by route context or
  `lastSesh`; editing controls must produce a fresh validated plan that is
  passed through `handleTrickSelected` and the existing `trickSelected`
  reducer action.
- This iteration covers pre-run customization and regression protection. It
  does not redesign multi-trick entry, change post-completion navigation, or
  add mobile-platform validation.
