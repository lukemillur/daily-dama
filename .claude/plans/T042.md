# T042 plan: complete native tab iconography

Branch: `task/T042-complete-native-tab-iconography` (resume; already claimed).

## Findings (verified against current code)
- `src/components/app-tabs.tsx` (native only; web uses `app-tabs.web.tsx`, untouched) renders `NativeTabs` from `expo-router/unstable-native-tabs`. Only the Home trigger has `<NativeTabs.Trigger.Icon src={home.png} renderingMode="template" />`; Sesh/Tricks/Stats/Profile have only a Label.
- expo-router 57.0.29 `Trigger.Icon` supports `sf` (SF Symbol name, optionally `{ default, selected }`), typed by `sf-symbols-typescript` (already a transitive type dep). SF Symbols are system-tinted. Priority on iOS: `sf` > `xcasset` > `src`.
- `NativeTabs` already accepts `iconColor` (`{default, selected}`) and `tintColor`. Currently only `labelStyle.selected.color` is set, so icon color is system default, unlike label.
- Tab colors come from `Colors[scheme]` in `src/constants/theme.ts` (system scheme), not the saved/resolved profile theme (`useResolvedTheme`) used in screens. DESLOPPIFY.md flags this; the ticket says "check that tint/selected treatment remains legible with the current theme". Decision: keep `Colors` (system scheme); do NOT rewire to the resolved theme (that is scope beyond navigation polish). Only verify legibility; record any incoherence as a follow-up note.
