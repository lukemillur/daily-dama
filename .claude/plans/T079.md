# T079 implementation plan

## Good enough for this iteration

The custom-trick form keeps its primary save action pressable for every draft, reveals the existing validator's actionable field messages after a failed submit, and stays mounted when validation fails. Valid standalone and sequence creation continue to save once; editing continues to update the existing stable ID and preserve the existing focused-trick behavior. No persistence schema, provider boundary, mobile-specific behavior, or unrelated form polish is included.

## Ordered implementation steps

1. Update `src/app/tricks/index.tsx` to model transient submission state separately from the draft and validation result. Keep `validateCustomTrickDraft(draft)` as the only validation source of truth; derive the displayed `name`, `steps`, and `kenteiRank` messages only after a save attempt has returned an invalid result (and keep them current as the user corrects the draft). Remove the invalid-draft `disabled` prop from the primary save button. In `save()`, handle the provider's invalid result by marking the form submitted and returning without calling `onSaved`, changing selection, or causing any persistence dispatch; retain the existing saved-result path for add/edit behavior.

2. Add a focused component test file alongside the Tricks route tests, preferably `src/app/tricks/__tests__/custom-trick-form.test.tsx`, using the existing `react-test-renderer`/`act` patterns and hydrated custom-trick and user-profile providers (or a narrow equivalent harness). Make the save control discoverable by its visible label/accessibility role so the tests can assert its `disabled` state directly.

3. Cover invalid standalone submission: mount an empty standalone form, assert “Save custom trick” is enabled, press it, assert the form remains rendered, assert the name error is shown, and assert no saved callback or custom-trick record/persistence result was produced.

4. Cover invalid sequence submission: mount the default sequence draft, assert save is enabled, press it, and assert the sequence remains on the form with both the name and ordered-step errors displayed. Exercise the invalid-rank path as well (using a deliberately invalid edit/initial fixture or another testable boundary input) and assert the validator's concise rank message is rendered beside the rank picker.

5. Cover successful behavior: fill a valid standalone and a valid sequence draft, press save, and assert each invokes `onSaved` exactly once and creates exactly one record. Mount an existing custom trick for edit, change its name/rank or steps, save once, and assert the record keeps its original ID and updates in place; retain coverage that focused-trick selection follows the existing toggle behavior.

6. Run the focused form test first, then the standard web-targeted verification appropriate to the implementation (`yarn test --runInBand`, `yarn lint`, `yarn tsc --noEmit`, and `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export`). Do not launch native tooling; record iOS/Android validation as deferred under the project handoff.

## Files expected to change

- `src/app/tricks/index.tsx` — transient submit/error presentation and actionable save behavior.
- `src/app/tricks/__tests__/custom-trick-form.test.tsx` — component-level regression coverage for invalid submit, validation messages, creation, and editing.

## Constraints and implementation notes

- Do not alter `CustomTrickDraft`, the v1 persistence document, or the custom-trick provider's hydration/write queue.
- Keep the form open on invalid results by calling `onSaved` only for `{ status: 'saved' }`.
- Keep error copy owned by `validateCustomTrickDraft`; the component should only decide when errors become visible.
- Preserve stable custom-trick IDs, name snapshots for sequence steps, and the existing add/remove focused-trick behavior.
- Treat the invalid-rank test as validation-boundary coverage; the visual rank picker should continue to expose only the valid ranks 1–12 and unranked choice.
