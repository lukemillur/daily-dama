# T318 plan: native Kentei reveal pacing and responsive badge

Branch `task/T318-give-the-native-kentei-reveal-deliberate`. Presentation-only change. No rank rules, reducer, persistence or schema changes.

## Current facts (verified in code)
- Single shared component: `src/features/onboarding/components/onboarding-rank-reveal-step.tsx`. Used by onboarding (`kentei-onboarding.tsx`, state `rankReveal`, rendered inside Home when onboarding is incomplete) and by promotion (`src/features/profile/components/rank-up-celebration-modal.tsx`, mounted by `KenteiRankAutoPromotion`, absolute-fill overlay).
- Badge: `RankStage` is a fixed 220x220 circle, `RankNumber` a fixed 100px font, `Content` has `padding: 40px 22px 130px`, title fixed 40px/43px. Nothing responds to viewport height or font scale. Entrance is `ZoomIn.duration(650).springify().damping(11)`; per the task note `springify()` with no argument discards the duration, so it is an unbounded spring with visible overshoot.
- Text rows use `FadeIn` with 350/450/550 ms delays. The Continue button is mounted and pressable from the first frame (no gating). Continue calls `onContinue` once per tap; nothing navigates automatically. Keep that.
- `src/features/auth/components/new-account-welcome-overlay.tsx` copies the same ZoomIn/spring. Out of scope (different surface, auto-dismisses). Mention as a follow-up only.
- Tests: `kentei-onboarding.test.tsx` mocks reanimated with `react-native-reanimated/mock`; `kentei-rank-auto-promotion.test.tsx` covers promotion. Neither asserts motion config.
- Reanimated 4.5.1 layout animations default to `ReduceMotion.System`; verify on device, do not assume.

## Implementation steps (in order)
1. New pure module `src/features/onboarding/model/rank-reveal-motion.ts` (no React):
   - `selectRankRevealMotion(os)` returns a config. `web` reproduces today's values exactly (650 ms zoom spring damping 11, fades 400/350/450/550). `ios` and `android` return a timed entrance: badge opacity 0->1 and scale about 0.92->1 over 900 ms with an ease-out curve, no spring and no damping field; text rows fade with delays that keep the whole reveal settled by about 1000 ms.
   - `selectRankRevealLayout({ width, height })` returns `{ badgeSize, numeralSize, titleSize, bottomPadding }`: `badgeSize = clamp(min(width*0.58, height*0.30), 120, 220)`, `numeralSize = badgeSize*0.45`, title 30-40 derived from width, shorter bottom padding on viewports under about 700 dp high. At a 1280x800 web viewport it must resolve to 220 / 100 / 40 (accepted web look unchanged).
   Why a pure module: tests can assert the numbers without trusting the reanimated mock, and the web path stays byte-for-byte.
2. Edit `onboarding-rank-reveal-step.tsx` to use the config via `Platform.OS`. Native badge entrance: use reanimated `Keyframe` (opacity and scale in one object, `.duration(900)`, easing out) or `withTiming` on shared values; do not call `.springify()` natively. Put `.reduceMotion(ReduceMotion.System)` explicitly on each native entering builder. Build the builders as module-level constants (not recreated per render).
3. Keep Continue rendered and pressable from the first frame (reduced-motion and screen-reader users must not wait). Confirm no re-trigger of entrance on re-render.
4. Responsive layout in the same component: `useWindowDimensions()` feeds `selectRankRevealLayout`; pass sizes to styled components as transient props. Set `allowFontScaling={false}` on the numeral only (it is graphical inside a fixed circle; scaling is what clips it); title, copy and button stay scalable. Numeral `line-height` equals its size so "12" does not clip. Wrap the content in a `ScrollView` (`contentContainerStyle` `flexGrow: 1`, centered) so at the largest font scale on a small viewport the title/copy/button remain reachable. Keep `max-width: 620px`.
5. `rank-up-celebration-modal.tsx`: expected no logic change; confirm the absolute-fill overlay gives the new ScrollView a bounded height.
6. Tests:
   - `src/features/onboarding/model/rank-reveal-motion.test.ts`: native duration within 800-1000 ms for ios and android; no spring/damping in native config; web config equals the previous constants; layout cases 320x568 (font scale irrelevant to the numeral), 360x640, 393x852, 1280x800 (-> 220/100/40); every native builder carries ReduceMotion.System.
   - Extend `kentei-onboarding.test.tsx`: `rankReveal` for rank 1 and 12 renders the numeral; one press of Continue moves to selecting; no `router.replace` before it; a second press is a no-op.
   - Extend `kentei-rank-auto-promotion.test.tsx`: the overlay stays mounted after 10 s of fake-timer advance and unmounts only after "Nice!" is pressed once.
7. Static verification: the three test files, `yarn eslint <changed files>`, `yarn tsc --noEmit`. Web export only if a dependency changes (none expected).
