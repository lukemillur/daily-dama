# T305 plan: keep display headlines and active Sesh controls intact at accessibility text sizes

Branch: `task/T305-keep-display-headlines-and-active-sesh`. No persistence, schema or state-machine change; risk is purely layout, and the only real evidence is the iOS Simulator. Scoping decision from the task stands: cap display type, do not reflow it.

## Findings from reading the code

- `DisplayTitle` (`src/components/ui/typography.tsx`) is a plain `styled.Text`, 42px / line-height 44px. `HeroTitle` in `src/features/home/components/daily-home.tsx` extends it to 48px. Sesh re-wraps it (`styled(BaseDisplayTitle)`), so a cap on the base is inherited. Nothing in `src` sets `maxFontSizeMultiplier` today.
- Display-sized type that is NOT `DisplayTitle` (route/feature-local `styled.Text`):
  - Profile `RankNumber` 78px (`src/app/app/profile/index.tsx`).
  - Sesh (`src/features/sesh/components/sesh.tsx`, styles near line 1323): `CountdownNumber` 156px, `Timer` 78px, `LacedButtonText` 34px, `LacedCount` 40px, `ActiveTrick` 30px, `CountdownTrick` 26px.
  - Arrows: `ChoiceArrow` (sesh.tsx 1322, absolute, right 20; the trick card has `padding-right: 58px`) and `TypeArrow` (`src/app/app/tricks/index.tsx` 537). At 28px x ~3 the glyph is wider than the 58px reserve, so it overlaps the name. Confirm on the simulator which card (Sesh picker `TrickChoice` vs Tricks `TypeChoice`) shows the overlap and fix both if both do.
  - Optional: Stats `OverviewValue` (30px) and `HeroTitle`/`SectionTitle`; cap only if the simulator shows breakage.
- styled-components v6 supports `.attrs({ maxFontSizeMultiplier })` on `styled.Text` (the repo already uses `.attrs` on `TextInput` and `Button`). Body text, inputs, tab labels and button labels must stay uncapped.
- Active Sesh buttons: `SecondaryActions` is a row of `flex: 1` `PauseButton` / `EndButton` with `padding: 12px 24px`, labels 15px. At ~3x a half-width button has about 110pt of content width, narrower than the word "Pause", so words split. `LacedButton` is a row (`justify-content: space-between`, padding 22px 26px, min-height 108) with 34px label + 40px count and no wrap or shrink, so it clips.

## Steps

1. **Shared constant and base (typography.tsx).**
   - Export `DISPLAY_MAX_FONT_SIZE_MULTIPLIER` and a `DisplayText = styled.Text.attrs({ maxFontSizeMultiplier: DISPLAY_MAX_FONT_SIZE_MULTIPLIER })` base (no visual CSS).
   - Define `DisplayTitle` as `styled(DisplayText)` with the existing CSS unchanged (so default-size output is identical).
   - Choose the multiplier empirically, starting at 1.3 (task range 1.3-1.5): the longest single word of any headline (Home hero is 48px, the widest case) must fit one line in 375pt minus 22px side padding (~331pt) at the cap. Rough check: "What" at 48px is ~115pt, so cap x ~2.9 would still fit; the 1.3-1.5 range is therefore comfortably safe, and any longer headline word (check Stats, Tricks, Profile, Sesh titles, and the `You're` title) sets the real limit. Record the chosen value and the reason in a comment next to the constant (why, not chronology).
2. **Apply the cap to route/feature-local display styles.** Rebase these on `DisplayText` or add `.attrs({ maxFontSizeMultiplier: DISPLAY_MAX_FONT_SIZE_MULTIPLIER })`: Profile `RankNumber`; Sesh `CountdownNumber`, `Timer`, `LacedButtonText`, `LacedCount`, `ActiveTrick`, `CountdownTrick`; `ChoiceArrow` and `TypeArrow` (glyph size, so the reserved 58px stays sufficient; if not at the cap, widen `padding-right` and/or give the title `padding-right` equal to the arrow reserve). Keep CSS strings byte-identical otherwise. Profile `RankLine`: add `flex-shrink: 0` to `RankNumber` (and `numberOfLines={1}` is acceptable) so `03` never stacks, with `RankIdentity` (`flex: 1`) absorbing the squeeze.
3. **Active Sesh controls.**
   - `LacedButton`: add `gap` and `flex-wrap: wrap`, set `flex-shrink: 1; min-width: 0` on the label so it can wrap at word boundaries only as a last resort; with the cap the row should fit (34px x 1.3 label + 40px x 1.3 count is ~185pt in ~279pt). Keep `min-height: 108` (grows in height, never fixed height).
   - `Pause Sesh` / `End Sesh`: add `text-align: center` to both label styles. Make the row switch to a column (full-width buttons) when the user's font scale is large, using `useWindowDimensions().fontScale` (threshold around 1.5, tune on the simulator) via a small helper/hook near the Sesh active view; below the threshold the row, `flex: 1` and padding stay exactly as today, and web always reports 1 so web is unchanged. Alternative if the hook proves awkward: `flex-wrap: wrap` with reduced horizontal padding, but a pure wrap cannot switch at the right moment because basis-0 items do not exceed the row at 375pt, hence the fontScale switch. Labels keep full Dynamic Type scaling.
   - Check the same row in `multi-trick-sesh.tsx` and `endActionLabel` variants (`End Sesh` is a prop) use the same buttons; apply the fix wherever the pair is rendered rather than copying it (they share `ActiveSesh` in sesh.tsx; confirm with grep before touching multi-trick).
4. **Tests.**
   - Extend `src/components/ui/typography.test.tsx`: `DisplayTitle` renders `Text` with `maxFontSizeMultiplier === DISPLAY_MAX_FONT_SIZE_MULTIPLIER`; `BodyText` and `Eyebrow` have it `undefined` (guards "body keeps scaling"). Find the host `Text` node as the existing helpers do.
   - Add a Sesh active-view test (sesh.test.tsx pattern; mock `useWindowDimensions` per landing-page.test.tsx) asserting the column layout at `fontScale: 2` and unchanged row at `fontScale: 1`, plus the cap on `Laced.` and the count if reachable by test id/text. Do not add placeholder snapshot tests.
5. **Verify.** `yarn eslint` on changed files; `yarn jest` on typography, sesh, profile, tricks and home tests; full `yarn tsc --noEmit`. Then on the iPhone 17e (iOS 27.0) simulator: start Metro from this worktree on an explicit free port, confirm via `lsof` that the pinned bundle is this worktree, set `xcrun simctl ui <udid> content_size accessibility-extra-extra-extra-large`, terminate and cold-launch (the T304 live-change bug is out of scope, so always relaunch after changing size). Walk Home, Sesh, Tricks (incl. Define new trick card), Stats, Profile (rank `03` single line) and an active single-trick Sesh (`Laced.` and the count inside the button, `Pause Sesh` / `End Sesh` whole words, card arrow clear of the trick name). Then default size on iOS and on web (`yarn web` / Expo dev server, not the static export): visually unchanged, including the 320px nav width check is not needed since nav is untouched. Restore the simulator size to default afterwards.
6. **Docs/bookkeeping.** In the same commit: record the chosen multiplier and rationale in the task close-out; move T305 to `TASKS_DONE.md` per the TASKS.md protocol; add a brief note to DESLOPPIFY.md's Accessibility row only if that doc is normally updated by fix tickets (check T289.5 convention). Record Android and physical-device checks as not run.

## Risks

- Capping is the owner-overridable decision; do not widen scope to body text, inputs or tab labels.
- The fontScale threshold is the only new behaviour branch; keep it in one place so web and default iOS stay byte-identical.
- Recording evidence: a passing unit test does not prove layout; the exit criteria require simulator observation, so report each screen as observed or not run.
