# T075 — Allow users to skip every multi-trick countdown

## Goal

Let users in the casual multi-trick Sesh flow begin the current trick immediately from any countdown, including the initial countdown and countdowns between tricks, while preserving the existing single-trick cancel behavior, rank-skip behavior, and assessment-specific countdown behavior.

## Ordered implementation plan

1. Extend the shared `Countdown` presentation contract in `src/features/sesh/components/sesh.tsx`.
   - Add an optional callback for skipping the current countdown and render a clearly labeled, accessible `Skip` action only when that callback is supplied.
   - Keep the existing `onComplete`, `onCancel`, and `onSkipRank` controls and their meanings separate; the new action must not reuse “Skip this rank,” which changes the trick sequence.
   - Use the existing countdown button/link styling conventions or the smallest local secondary action treatment, maintaining an adequate press target and accessibility role/label. Do not pass the callback from the ordinary single-trick `Sesh` caller, so its countdown UI and cancel behavior remain unchanged.

2. Wire countdown skipping through `src/features/sesh/components/multi-trick-sesh.tsx` without changing the Sesh state model.
   - Pass the new callback from the multi-trick countdown render for casual runs only; assessment runs (`origin === 'assessment'`) must not receive it, preserving their assessment-specific first-countdown and inter-trick behavior.
   - On a countdown skip, mark the initial countdown as passed using the same `isFirstCountdown` bookkeeping as normal completion and dispatch `countdownCompleted` with `Date.now()` through the existing reducer transition. This enters the current trick’s `active` state, starts its elapsed-time clock at the skip moment, and records no landing or skipped trick.
   - Leave `skipCountdownBetweenTricks` intact: when it is enabled, later tricks still seed directly active and therefore have no countdown to skip; when it is disabled, each later countdown gets the same `Skip` action. Preserve the first-countdown-only `Cancel` scope and the existing “Skip this rank” sequence-jump flow.

3. Add focused component regression coverage in `src/features/sesh/components/multi-trick-sesh.test.tsx` and, if needed for the shared presentation contract, `src/features/sesh/components/sesh.test.tsx`.
   - Assert that casual multi-trick renders `Skip` during the first countdown, pressing it immediately renders the first trick’s active controls, and no session/landing record is created by the action.
   - Exercise a later trick with inter-trick countdowns enabled (the existing default behavior where `skipCountdownBetweenTricks` is omitted), assert `Skip` is present for that trick, press it, and verify the later trick becomes active rather than advancing or recording the preceding trick incorrectly.
   - Verify the recorded session duration uses the timestamp supplied at skip/start and remains valid, using fake timers or controlled `Date.now()` as appropriate. Also retain explicit compatibility assertions that `Cancel` remains first-countdown-only, ordinary single-trick countdowns do not gain `Skip`, and assessment countdowns do not gain the casual control.
   - Keep tests focused on observable state and accessibility text/labels; do not add persisted preference state or expand the control into a run-level setting.

4. Verify the implementation using the repository’s web-only workflow.
   - Run the focused Sesh component tests first, then `yarn lint`, `yarn tsc --noEmit`, and `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export` (or the equivalent project verification wrapper).
   - Do not launch native tooling or make native-specific changes; iOS and Android validation are deferred by the repository handoff.

## Scope and assumptions

- The shared countdown remains a presentational component with optional actions; no new reducer action or persisted state is required because `countdownCompleted` already defines the correct active-state and timestamp semantics.
- “Casual multi-trick” is identified by the existing absence of `origin === 'assessment'`, avoiding changes to the assessment API or its intentional automatic inter-trick advancement.
- This iteration covers the requested per-run action and regression protection only. Countdown preferences, alternate copy, and broader countdown UX polish remain deferred.
