# T029.5 — Assessment wrap-up screen

## Context / what's already true

`MultiTrickSesh` (`src/features/sesh/components/multi-trick-sesh.tsx`) already renders a
generic wrap-up (`MultiTrickWrapUp`, added in T028.4) once a run finishes: one row per
attempted trick with lace count and time, and a "Finish sesh" button that's the only place
`onFinished` fires. `AssessmentEntry` (`src/features/sesh/components/assessment-entry.tsx`)
already passes `onFinished={() => router.replace('/profile')}` to this same component, so an
assessment run **already shows this generic wrap-up before navigating away** — the task
description's "replacing the route to `/profile` with no summary" framing describes the
pre-T028.4 behavior, not current `main`. This task's real job, per its own Notes, is narrower:
add the two assessment-specific things the generic wrap-up doesn't do yet:

1. **Skip reporting.** `handleSkipRank` in `multi-trick-sesh.tsx` currently just jumps the
   trick sequence forward — skipped tricks produce no summary and are silently absent from the
   wrap-up (see the comment on `MultiTrickWrapUp` and the test
   `'excludes skipped tricks from the wrap-up, showing only the attempted trick'`). Nothing
   currently tracks *that* a skip happened. T013.2 already settled that skipping a rank is
   "unassessed", not "failed" — the wrap-up copy must say "skipped", not imply a fail state (no
   red, no "0 laces" framing on it).
2. **Resulting rank.** The wrap-up doesn't show the profile's current assessed Kentei rank at
   all right now.

`KenteiRankAutoPromotion` (`src/features/profile/state/kentei-rank-auto-promotion.tsx`) is
mounted once at the app root (`src/app/_layout.tsx`), as a sibling of everything else, and
already fires `RankUpCelebrationModal` on any promotion regardless of where the promoting
landings came from (T019 is Done — confirmed in `TASKS_DONE.md`). So no promotion banner needs
to be built or triggered here — the wrap-up only needs to *display* the resulting rank as a
fact, not celebrate it. That celebration modal already renders independently, on top of
whatever screen is up (including this wrap-up) when a promotion happens.

**No blocker found.** Both dependencies the Notes flag (T028.4, T019) are landed and their
current shape matches what the Notes assume.

## Design

Keep following the pattern every other T029.x sibling used: `MultiTrickSesh` stays opaque to
"what an assessment is" and only grows small, optional, additive props; `AssessmentEntry`
supplies assessment-flavored values through them. Concretely:

### 1. `src/features/sesh/components/multi-trick-sesh.tsx`

- Add two new optional props to `MultiTrickSeshProps`:
  - `readonly describeSkippedRange?: (startIndex: number, endIndex: number) => string;` —
    mirrors `skipTarget`'s existing `(currentIndex: number) => number` shape (index-based, no
    `PracticeTrick`/`TrickSummary` coupling needed here). When provided, called every time
    `handleSkipRank` fires, with the pre-jump index and the computed target index, and its
    return value is accumulated for display. Omitting it preserves today's behavior exactly
    (skipped tricks stay silently absent) — regular (non-assessment) callers of
    `MultiTrickSesh` never pass `skipTarget` today anyway, so this is a no-op for them.
  - `readonly wrapUpFooter?: React.ReactNode;` — rendered near the bottom of the wrap-up,
    above the "Finish sesh" button. `undefined` renders nothing (today's layout, byte-for-byte,
    for every existing caller).
- In `handleSkipRank`: capture `skipTarget(sequence.currentIndex)` into a local `targetIndex`
  once (currently it's inlined into the `advanceTrickSequenceToIndex` call — pull it out so it
  can be reused), then, if `describeSkippedRange` is set, push
  `describeSkippedRange(sequence.currentIndex, targetIndex)` into a new
  `const [skippedEntries, setSkippedEntries] = useState<string[]>([]);` (declared next to the
  existing `summaries` state). This mirrors exactly how `summaries` accumulates.
- Pass `skippedEntries` and `wrapUpFooter` through to `<MultiTrickWrapUp>` in the
  `isRunFinished` branch.
- In `MultiTrickWrapUp`: accept `skippedEntries: readonly string[]` and
  `footer?: React.ReactNode` props. After the existing `WrapUpList`, when
  `skippedEntries.length > 0`, render a second list of rows — reuse the existing
  `WrapUpRow`-style layout but label each row distinctly, e.g.
  `accessibilityLabel={`Wrap-up skipped: ${entry}`}` with visible text like "{entry}
  — Skipped". **Use a neutral/muted color token (`AppColors.textMuted` /
  `AppColors.borderMuted`), not `AppColors.red`** — red would visually contradict the
  "skipped ≠ failed" decision even if the copy is careful. Render `footer` (if provided) after
  that section, before `FinishButton`.
- No changes to `seshReducer`, `trick-sequence.ts`, or any other assessment-agnostic
  mechanics — this is presentation + one new accumulation, same shape as the existing
  `summaries` accumulation.

### 2. `src/features/sesh/components/assessment-entry.tsx`

- In the `step.kind === 'running'` branch, alongside the existing
  `skipTarget={isMultiRankFlow ? (index) => selectNextRankStartIndex(tricks, index) : undefined}`,
  add:
  ```
  describeSkippedRange={
    isMultiRankFlow
      ? (start, end) => {
          const count = end - start;
          return `Rank ${tricks[start].kenteiRank} — ${count} trick${count === 1 ? '' : 's'} skipped`;
        }
      : undefined
  }
  ```
  `tricks` here is already typed `readonly TrickSummary[]` (return type of
  `selectAssessmentTricks`), so `tricks[start].kenteiRank` needs no cast. This is guarded the
  same way `skipTarget` already is, so `currentRankOnly` runs (which never show a skip button)
  never populate this either.
- Add `wrapUpFooter` unconditionally (all three flow kinds should show the resulting rank),
  reading the already-destructured `kenteiRank` from `useUserProfile()`:
  ```
  wrapUpFooter={
    <ResultCopy accessibilityLabel="Assessment result">
      {kenteiRank !== undefined
        ? `You're assessed at Rank ${kenteiRank}.`
        : 'Keep practicing — you have not earned a rank yet.'}
    </ResultCopy>
  }
  ```
  Add a small `ResultCopy` styled component near the other `styled(...)` declarations at the
  bottom of the file (follow the existing `Copy`/`FlowHint` pattern).
  Because `AssessmentEntry` itself subscribes to `useUserProfile()`, this re-renders
  automatically if `KenteiRankAutoPromotion` advances the rank after the run's last landing is
  recorded — no extra plumbing needed. **Worth knowing, not a blocker:** the promotion chain
  (history record → `KenteiRankAutoPromotion` effect → profile update) settles across a couple
  of React effect passes, so there's a possible one-frame flicker where the footer briefly
  shows the pre-promotion rank before catching up to the post-promotion one. This already
  existed for T019's celebration modal timing and wasn't treated as a blocker there; no new
  risk is introduced here since the user has to read the wrap-up and press "Finish sesh"
  manually (not an auto-navigate), giving it a beat to settle. Flag it during in-browser
  verification (assess a run that ends on a full-rank landing and confirm the footer's rank
  matches the freshly-promoted one, not the stale one) but don't build extra synchronization
  machinery for it unless verification actually shows a stuck stale value.

### 3. Tests — `src/features/sesh/components/multi-trick-sesh.test.tsx`

No new test file, matching the established precedent for this umbrella (T029.1–T029.4 all
tested through the shared `MultiTrickSesh`/`multi-trick-sesh.test.tsx` rather than adding an
`assessment-entry.test.tsx`) — these new props are exercised at exactly the level
`AssessmentEntry` calls them, so testing them there proves the mechanism `AssessmentEntry`
relies on.

- Extend `mountMultiTrickSesh`'s prop type and JSX (around line 94–124) to forward
  `describeSkippedRange` and `wrapUpFooter`.
- Add two tests, either as new `it`s inside the existing `describe('MultiTrickSesh wrap-up', ...)`
  block or a new sibling `describe`:
  1. **Resulting-rank footer renders.** Mount with
     `wrapUpFooter={<Text accessibilityLabel="resulting-rank">Rank 5</Text>}`, run the full
     `TRICKS` sequence to completion (reuse the loop from the existing "renders one wrap-up
     entry per attempted trick..." test), and assert
     `findByAccessibilityLabel(root, 'resulting-rank')` is present once the wrap-up is showing,
     and absent before the run finishes (e.g. during the first trick's countdown) — proving
     it's wrap-up-only content, not always-mounted.
  2. **Skipped range reported as skipped, not failed.** Mount with
     `skipTarget: () => TRICKS.length` and
     `describeSkippedRange: (start, end) => `Skipped ${end - start} tricks`` — same setup as
     the existing `'excludes skipped tricks from the wrap-up...'` test (lace trick 0, "Next
     trick", then "Skip this rank" on trick 1). Assert a node with `accessibilityLabel`
     starting `Wrap-up skipped:` exists, and that no `Wrap-up entry:`-labeled row exists for
     `TRICKS[1]`/`TRICKS[2]` (the pre-existing assertion already does this second half — extend
     that same test rather than duplicating the run choreography). Explicitly assert the
     skipped label's text does not contain `'laces'` or `'0 laces'`, to lock in that it's
     rendered through the distinct skipped path, not accidentally reusing the attempted-row
     copy.
