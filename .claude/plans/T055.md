# T055 — Show current rank/class standing during a Kentei assessment run

## Context confirmed against current `development`

- `src/features/sesh/components/sesh.tsx` exports `Countdown` and `ActiveSesh`, both already taking optional, opaque, assessment-only props (`attemptsReminder`, `onSkipRank`) that regular Sesh never passes and that `MultiTrickSesh` forwards through unchanged. This task adds one more prop in the same shape — no architectural surprises from the recent T045–T054 batch.
- `PracticeTrick` (`src/features/tricks/model/trick.ts`) is `{ id, name, descriptor?, sequenceSteps? }`. `TrickSummary extends PracticeTrick` adds `kenteiRank: number`, `kenteiLevel: KenteiLevel`, `kenteiClass: KenteiClass`. `Countdown`/`ActiveSesh`/`MultiTrickSesh` all type their `trick`/`tricks` as `PracticeTrick`, but `AssessmentEntry` passes `selectAssessmentTricks(...)` output (typed `readonly TrickSummary[]`, from `KENDAMA_KENTEI_TRICKS`) straight in — the extra fields exist on the runtime object even though the prop type erases them. Confirmed no restructuring needed; a runtime narrow is enough.
- `MultiTrickSesh` is also used by `MultiTrickSeshEntry` (ad hoc multi-trick, tricks come from `selectSeshPracticeTricks(selectAvailablePracticeTricks(...))`, which mixes standard tricks — which *do* carry Kentei fields — and custom tricks, which don't) and by `src/app/stats/sesh-sequence-sandbox.tsx` (dev sandbox). Both must stay visually unchanged. Since gating will be an explicit boolean prop neither caller passes, this is satisfied by construction, not by hoping the field-presence check saves us — confirms the Notes' steer away from "render whenever the fields happen to exist."
- Existing format precedent for rank/class text: `src/features/tricks/components/trick-card.tsx` renders `Rank {trick.kenteiRank}` and `{trick.kenteiLevel} · {trick.kenteiClass}`. Reuse this wording rather than inventing new copy.
- `AssessmentEntry` (`src/features/sesh/components/assessment-entry.tsx`) already threads several opaque booleans/callbacks into `MultiTrickSesh` (`showAttemptsReminder`, `skipTarget`, `endActionLabel`, `skipCountdownBetweenTricks`, `hideTimer`, `advanceOnFirstLace`, `describeSkippedRange`, `wrapUpFooter`) for its one `running` branch. Adding one more prop there is the established pattern.
- All three assessment flows (`fullBottomToTop`, `fromRank`, `currentRankOnly`) produce `TrickSummary[]` via `selectAssessmentTricks`, so all three have full Kentei metadata on every trick — no need to special-case `currentRankOnly` the way `skipTarget`/`describeSkippedRange` do (those are gated on `isMultiRankFlow` for a different reason: skipping is meaningless with only one rank in the run). Rank/class standing is still useful information even when it won't change mid-run.

## Approach

Gate via an explicit boolean prop threaded top-down: `AssessmentEntry` → `MultiTrickSesh` → `Countdown`/`ActiveSesh`. Inside `Countdown`/`ActiveSesh`, narrow the already-present `trick: PracticeTrick` to `TrickSummary` at render time via a small type guard, and render nothing if narrowing fails (defensive, but should never happen when the flag is set correctly).

## Steps

1. **`src/features/tricks/model/trick.ts`** — add two small, generally-useful exports (not assessment-specific, so this is the right home, consistent with `trick-card.tsx` importing its rank/class fields from this module):
   - `export function isTrickSummary(trick: PracticeTrick): trick is TrickSummary` — checks `'kenteiRank' in trick && 'kenteiLevel' in trick && 'kenteiClass' in trick`.
   - `export function formatKenteiStanding(trick: TrickSummary): string` — returns `` `Rank ${trick.kenteiRank} · ${trick.kenteiClass} · ${trick.kenteiLevel}` `` (reuses `trick-card.tsx`'s existing field order/wording conventions, just collapsed to one line for the sesh screens' more minimal text style).

   Order note: do this first since both `sesh.tsx` and its tests import from here.

2. **`src/features/sesh/components/sesh.tsx`**:
   - Add `readonly showRankStanding?: boolean` to `CountdownProps` and to the `ActiveSesh` props interface, alongside the existing `attemptsReminder?`/`onSkipRank?` (same optionality/opaqueness convention — undefined by default, never inferred from data).
   - In both `Countdown` and `ActiveSesh`, compute:
     ```ts
     const rankStanding = showRankStanding && isTrickSummary(trick) ? formatKenteiStanding(trick) : undefined;
     ```
   - Render `{rankStanding ? <RankStandingLabel>{rankStanding}</RankStandingLabel> : null}` directly after the `<Eyebrow>` line in both components (before `CountdownTrick`/`ActiveTrick`). Placing it in the same spot in both keeps countdown → active visually continuous as the trick changes.
   - Add a new styled component `RankStandingLabel` near the other small-caps label styles (e.g. next to `AttemptsReminder`'s definition) — same visual weight class (`AppColors.textMuted`, bold, uppercase, small size) so it reads as secondary chrome, not a headline; do not reuse `AttemptsReminder` itself since accessibility/semantic meaning differs (this isn't a reminder, don't conflate them if a test ever asserts on `AttemptsReminder`'s specific text).
   - Import `isTrickSummary` and `formatKenteiStanding` from `@/features/tricks/model/trick` (that module is already imported for `PracticeTrick`).

3. **`src/features/sesh/components/multi-trick-sesh.tsx`**:

   - Do **not** touch `MultiTrickSeshEntry` or `sesh-sequence-sandbox.tsx` — leaving the prop unpassed there is the correct "unchanged" behavior per the exit criteria, verify by construction rather than adding new conditionals.

4. **`src/features/sesh/components/assessment-entry.tsx`**:

## Order rationale

Step 1 before 2 (component code imports the model helpers). Steps 2–4 must land together before verification since `multi-trick-sesh.tsx`/`assessment-entry.tsx` reference the new `Countdown`/`ActiveSesh` prop — but they're mechanical enough to do in one pass. Tests can be written interleaved with 1–4 rather than strictly after, per normal practice.

## Risks / non-obvious things

- Don't be tempted to compute `rankStanding` from `MultiTrickSesh`/`AssessmentEntry` and pass a precomputed *string* down instead of a boolean + trick — `Countdown`/`ActiveSesh` already receive the full `trick` object every render, so a boolean flag is the minimal addition and keeps the formatting logic in one place (`trick.ts`) rather than duplicated at each call site.
- Do not render this unconditionally based on `isTrickSummary(trick)` alone anywhere — the Notes are explicit that this must be gated on assessment context via a threaded prop, not on field presence, precisely because `MultiTrickSeshEntry`'s ad hoc runs can mix standard tricks (which do have the fields) with custom tricks (which don't) in the same run, and even the standard-trick tricks there should stay unchanged.
- Keep the visual insertion point identical between `Countdown` and `ActiveSesh` (right after `<Eyebrow>`) so there's no jarring layout shift at the countdown→active transition.
- `formatKenteiStanding`'s exact wording is a judgment call (this plan proposes `Rank 5 · 3rd Class · Basic`); if it reads awkwardly once rendered, adjusting the string is low-risk and doesn't ripple anywhere else since it's the single source used by both `Countdown` and `ActiveSesh`.
