# T157.1 — Define durable outbox and mutation-identity contracts

## Scope for this iteration

Pure contract/persistence definition: plain-data types, runtime validation, and
persistence adapters for a durable per-domain sync outbox, plus jest unit
tests proving every exit criterion. **No** wiring into `UserProfileProvider` /
`CustomTrickProvider` / `GoalProvider` / `NoteProvider` / `PracticeHistoryProvider`,
no sync coordinator, no network calls, no Supabase client usage. That is
T157.2–T157.9. Nothing in this ticket may import from `src/features/*`
(architecture layering: `src/shared/*` sits below `src/features/*`) or from
`src/shared/supabase/*` (repository contracts are consumed by outbox
*integrations* later, not by the outbox contract itself).

## Confirmed context (do not re-derive)

- Five identity-scoped domains already exist end-to-end: profile, custom
  tricks, practice history, goals, notes — each with its own reducer,
  persistence adapter (`load*`/`save*` against `KeyValueStorage`), and
  provider built on `useIdentityScopedDomain`
  (`src/shared/persistence/use-identity-scoped-domain.ts`). That hook already
  owns hydration-per-generation, write-queue composition via
  `createWriteQueue`, and discarding stale writes/loads after an identity
  switch. This ticket does not touch or duplicate that hook.
- Identity primitives live in `src/shared/persistence/identity.ts`
  (`Identity`, `identityNamespace`, `GUEST_IDENTITY`,
  `isValidVerifiedUserId`). Physical key namespacing lives in
  `src/shared/persistence/scoped-storage.ts` (`physicalKey`,
  `createScopedKeyValueStorage`, `createGuestMigratingStorage`). Generation
  guarding lives in `src/shared/persistence/identity-context.ts`.
- `createWriteQueue<T>` (`src/shared/persistence/storage.ts`) serializes
  writes of one value type so an older, slower write can never clobber a
  newer one. `PersistenceLoadResult<T>` / `PersistenceSaveResult` are the
  existing load/save result vocabulary every domain persistence file already
  returns.
- The existing provisional-v1 pattern (`CUSTOM_TRICKS_SCHEMA_VERSION`,
  `custom-trick-persistence.ts`) is the template for "versioned document,
  malformed input recovers to an empty/initial value rather than throwing."
- T155.9's cloud-repository vocabulary (`src/shared/supabase/cloud-repository.ts`)
  already defines `CloudPage<T>.nextCursor: string | null` as an **opaque**
  cursor string. Per-domain mapping layers (T155.10–13, e.g.
  `mapCustomTrickToUpsertInput`) already produce the exact plain-record
  "upsert input" shapes a future outbox operation's `payload` will carry —
  this ticket's `payload` type must be structurally compatible with those
  (a plain JSON-serializable record) without importing them.
- Database rows already carry `revision` and, for goals/notes,
  `deleted_at`/tombstone columns (`src/shared/supabase/database-types.ts`).
  Revision/conflict semantics are explicitly **out of scope** here (T157.3);
  this ticket only needs to give a future push/pull transport something to
  iterate over (`outbox: readonly OutboxOperation[]`) and somewhere to record
  pull progress (`cursor`).

## Design decision: one envelope per domain, not one shared cross-domain structure

The task's phrase "per-domain cursors" and "atomic versioned envelopes that
own local domain state and its outbox together" could be read as one big
structure holding all five domains' state + a cursor map. That would violate
the existing hard rule in `AGENTS.md`/domain boundaries ("do not combine
these domains into a global store merely because they are all persistent").
Instead: **`SyncEnvelope<State>` is generic and instantiated once per
domain**, each with its own storage key, its own single `cursor: string |
null` field, and its own outbox array. "Per-domain cursors" falls out for
free because each of the five domains gets its own envelope instance later
(T157.4–T157.8) — no separate multi-domain cursor map is needed. Flag this
choice to the user/reviewer as a deliberate deviation from the most literal
reading, justified by the existing domain-independence rule.

### 2. `src/shared/sync/outbox-operation.ts`

```ts
import { isSyncDomain, type SyncDomain } from '@/shared/sync/domain';

export type OutboxOperationType = 'upsert' | 'delete';

export interface OutboxOperation {
  readonly operationId: string;      // stable across retries; the idempotency key
  readonly domain: SyncDomain;
  readonly operationType: OutboxOperationType;
  readonly recordId: string;          // the domain row's stable id (trick id, goal id, session id, ...)
  readonly payload: Record<string, unknown> | null; // non-null iff operationType === 'upsert'
  readonly createdAt: number;         // caller-supplied timestamp; never Date.now() inside this module
  readonly attemptCount: number;      // starts at 0, incremented by recordOutboxOperationAttempt
  readonly lastAttemptedAt: number | null;
  readonly lastErrorMessage: string | null; // plain string only -- never an Error/exception object
}

export interface NewOutboxOperationInput {
  readonly domain: SyncDomain;
  readonly operationType: OutboxOperationType;
  readonly recordId: string;
  readonly payload: Record<string, unknown> | null;
}

// Same deterministic-injectable-id pattern as createCustomTrickId/createGoalId
// (src/features/custom-tricks/model/custom-trick.ts, src/features/goals/model/goal.ts):
// timestamp+random base36, no crypto.randomUUID dependency, fully unit-testable.
export function createOutboxOperationId(now = Date.now(), random = Math.random()): string {
  return `op-${now.toString(36)}-${Math.floor(random * 0x100000000).toString(36)}`;
}

export function createOutboxOperation(
  operationId: string,
  input: NewOutboxOperationInput,
  createdAt: number,
): OutboxOperation {
  return {
    operationId,
    domain: input.domain,
    operationType: input.operationType,
    recordId: input.recordId,
    payload: input.payload,
    createdAt,
    attemptCount: 0,
    lastAttemptedAt: null,
    lastErrorMessage: null,
  };
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

function isNonEmptyTrimmedString(value: unknown): value is string {
  return typeof value === 'string' && value.length > 0 && value === value.trim();
}

export function isOutboxOperation(value: unknown): value is OutboxOperation {
  if (!isRecord(value)) return false;
  const {
    operationId, domain, operationType, recordId, payload,
    createdAt, attemptCount, lastAttemptedAt, lastErrorMessage,
  } = value;

  if (!isNonEmptyTrimmedString(operationId)) return false;
  if (!isSyncDomain(domain)) return false;
  if (operationType !== 'upsert' && operationType !== 'delete') return false;
  if (!isNonEmptyTrimmedString(recordId)) return false;
  if (operationType === 'upsert' && !isRecord(payload)) return false;
  if (operationType === 'delete' && payload !== null) return false;
  if (typeof createdAt !== 'number' || !Number.isFinite(createdAt)) return false;
  if (!Number.isInteger(attemptCount) || attemptCount < 0) return false;
  if (lastAttemptedAt !== null && (typeof lastAttemptedAt !== 'number' || !Number.isFinite(lastAttemptedAt))) return false;
  if (lastErrorMessage !== null && typeof lastErrorMessage !== 'string') return false;
  return true;
}
```

`payload` is intentionally a plain `Record<string, unknown>`, not an imported
`CustomTrickInsert`/`GoalInsert`/etc. — that keeps `shared/sync` decoupled
from `features/*`. Document in a comment that future integration tickets
(T157.4+) are expected to pass the already-mapped `*Insert` shape from each
domain's `*-cloud-mapping.ts` as `payload`.

### 3. `src/shared/sync/sync-envelope.ts`

```ts
import { isOutboxOperation, type NewOutboxOperationInput, type OutboxOperation, createOutboxOperation, createOutboxOperationId } from '@/shared/sync/outbox-operation';
import type { SyncDomain } from '@/shared/sync/domain';
import { identityNamespace, type Identity } from '@/shared/persistence/identity';
import type { KeyValueStorage, PersistenceLoadResult, PersistenceSaveResult } from '@/shared/persistence/storage';

export const SYNC_ENVELOPE_SCHEMA_VERSION = 1;

export interface SyncEnvelope<State> {
  readonly version: typeof SYNC_ENVELOPE_SCHEMA_VERSION;
  readonly domain: SyncDomain;
  readonly identityNamespace: string;   // identityNamespace(identity) baked in at write time -- see "why not rely on storage scoping alone" below
  readonly state: State;
  readonly outbox: readonly OutboxOperation[]; // FIFO: index 0 is oldest/next-to-send
  readonly cursor: string | null;
  readonly cursorUpdatedAt: number | null;
}

export interface SyncEnvelopeCodec<State> {
  readonly isState: (value: unknown) => value is State;
}

export type SyncEnvelopeRejectionReason = 'identityMismatch' | 'domainMismatch' | 'notFound';

export type SyncEnvelopeMutationResult<State> =
  | { readonly status: 'applied'; readonly envelope: SyncEnvelope<State> }
  | { readonly status: 'rejected'; readonly reason: SyncEnvelopeRejectionReason };

function checkIdentity<State>(envelope: SyncEnvelope<State>, identity: Identity): boolean {
  return envelope.identityNamespace === identityNamespace(identity);
}

export function createInitialSyncEnvelope<State>(
  domain: SyncDomain,
  identity: Identity,
  initialState: State,
): SyncEnvelope<State> {
  return {
    version: SYNC_ENVELOPE_SCHEMA_VERSION,
    domain,
    identityNamespace: identityNamespace(identity),
    state: initialState,
    outbox: [],
    cursor: null,
    cursorUpdatedAt: null,
  };
}

// THE atomic pairing: appends one outbox operation and swaps in the new
// domain state in a single new envelope object. Callers must persist the
// *returned* envelope via one saveSyncEnvelope call -- never save `state`
// and the outbox separately -- so a state change and its operation can never
// land on only one side of a crash/reload boundary.
export function applyLocalMutation<State>(
  envelope: SyncEnvelope<State>,
  identity: Identity,
  nextState: State,
  operationInput: NewOutboxOperationInput,
  createdAt: number,
  operationId: string = createOutboxOperationId(createdAt),
): SyncEnvelopeMutationResult<State> {
  if (!checkIdentity(envelope, identity)) return { status: 'rejected', reason: 'identityMismatch' };
  if (operationInput.domain !== envelope.domain) return { status: 'rejected', reason: 'domainMismatch' };

  const operation = createOutboxOperation(operationId, operationInput, createdAt);
  return {
    status: 'applied',
    envelope: { ...envelope, state: nextState, outbox: [...envelope.outbox, operation] },
  };
}

// Acknowledging removes the operation from the outbox entirely -- there is
// no persisted "acknowledged" status to accumulate forever. "Distinct from
// pending" per the task description means: while present in `outbox`, an
// operation is pending; once a server ack is applied here, it is gone.
export function acknowledgeOutboxOperation<State>(
  envelope: SyncEnvelope<State>,
  identity: Identity,
  operationId: string,
): SyncEnvelopeMutationResult<State> {
  if (!checkIdentity(envelope, identity)) return { status: 'rejected', reason: 'identityMismatch' };
  if (!envelope.outbox.some((op) => op.operationId === operationId)) {
    return { status: 'rejected', reason: 'notFound' };
  }
  return {
    status: 'applied',
    envelope: { ...envelope, outbox: envelope.outbox.filter((op) => op.operationId !== operationId) },
  };
}

// operationId is preserved untouched -- this is what makes retries
// idempotent from the server's point of view.
export function recordOutboxOperationAttempt<State>(
  envelope: SyncEnvelope<State>,
  identity: Identity,
  operationId: string,
  attemptedAt: number,
  errorMessage: string | null,
): SyncEnvelopeMutationResult<State> {
  if (!checkIdentity(envelope, identity)) return { status: 'rejected', reason: 'identityMismatch' };
  const index = envelope.outbox.findIndex((op) => op.operationId === operationId);
  if (index === -1) return { status: 'rejected', reason: 'notFound' };

  const outbox = envelope.outbox.slice();
  outbox[index] = {
    ...outbox[index],
    attemptCount: outbox[index].attemptCount + 1,
    lastAttemptedAt: attemptedAt,
    lastErrorMessage: errorMessage,
  };
  return { status: 'applied', envelope: { ...envelope, outbox } };
}

export function updateSyncCursor<State>(
  envelope: SyncEnvelope<State>,
  identity: Identity,
  cursor: string | null,
  updatedAt: number,
): SyncEnvelopeMutationResult<State> {
  if (!checkIdentity(envelope, identity)) return { status: 'rejected', reason: 'identityMismatch' };
  return { status: 'applied', envelope: { ...envelope, cursor, cursorUpdatedAt: updatedAt } };
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

function isValidSyncEnvelopeShape<State>(
  value: unknown,
  domain: SyncDomain,
  codec: SyncEnvelopeCodec<State>,
): value is SyncEnvelope<State> {
  if (!isRecord(value)) return false;
  if (value.version !== SYNC_ENVELOPE_SCHEMA_VERSION) return false;
  if (value.domain !== domain) return false;
  if (typeof value.identityNamespace !== 'string' || value.identityNamespace.length === 0) return false;
  if (!codec.isState(value.state)) return false;
  if (!Array.isArray(value.outbox) || !value.outbox.every(isOutboxOperation)) return false;

  const outbox = value.outbox as OutboxOperation[];
  if (!outbox.every((op) => op.domain === domain)) return false;
  const ids = outbox.map((op) => op.operationId);
  if (new Set(ids).size !== ids.length) return false; // duplicate operationId => corrupted envelope

  if (value.cursor !== null && typeof value.cursor !== 'string') return false;
  if (value.cursorUpdatedAt !== null && typeof value.cursorUpdatedAt !== 'number') return false;
  return true;
}

export function serializeSyncEnvelope<State>(envelope: SyncEnvelope<State>): string {
  return JSON.stringify(envelope);
}

export function deserializeSyncEnvelope<State>(
  serialized: string,
  domain: SyncDomain,
  codec: SyncEnvelopeCodec<State>,
): SyncEnvelope<State> | undefined {
  let parsed: unknown;
  try {
    parsed = JSON.parse(serialized);
  } catch {
    return undefined;
  }
  return isValidSyncEnvelopeShape(parsed, domain, codec) ? parsed : undefined;
}

export async function loadSyncEnvelope<State>(
  storage: KeyValueStorage,
  storageKey: string,
  domain: SyncDomain,
  codec: SyncEnvelopeCodec<State>,
  identity: Identity,
  initialState: State,
): Promise<PersistenceLoadResult<SyncEnvelope<State>>> {
  try {
    const serialized = await storage.getItem(storageKey);
    if (serialized === null) {
      return { status: 'empty', value: createInitialSyncEnvelope(domain, identity, initialState) };
    }

    const envelope = deserializeSyncEnvelope(serialized, domain, codec);
    if (!envelope) {
      return {
        status: 'recovered',
        value: createInitialSyncEnvelope(domain, identity, initialState),
        error: new Error('The persisted sync envelope is malformed or uses an unsupported version.'),
      };
    }

    // Defense in depth on top of physical key namespacing (scoped-storage.ts):
    // even if `storage` were ever misconfigured/shared, an envelope tagged
    // for a different identity must never be treated as loaded.
    if (!checkIdentity(envelope, identity)) {
      return {
        status: 'recovered',
        value: createInitialSyncEnvelope(domain, identity, initialState),
        error: new Error('The persisted sync envelope belongs to a different identity.'),
      };
    }

    return { status: 'loaded', value: envelope };
  } catch (error) {
    return { status: 'recovered', value: createInitialSyncEnvelope(domain, identity, initialState), error };
  }
}

export async function saveSyncEnvelope<State>(
  storage: KeyValueStorage,
  storageKey: string,
  envelope: SyncEnvelope<State>,
): Promise<PersistenceSaveResult> {
  try {
    await storage.setItem(storageKey, serializeSyncEnvelope(envelope));
    return { status: 'saved' };
  } catch (error) {
    return { status: 'failed', error };
  }
}
```

Note the `load`/`save` signatures deliberately match the shape
`useIdentityScopedDomain` already expects (`load: (storage) => Promise<PersistenceLoadResult<State>>`,
`save: (storage, value) => Promise<PersistenceSaveResult>`) modulo the extra
fixed arguments (`domain`, `codec`, `identity`, `initialState`) that a future
integration ticket will partially-apply per domain — confirms this slots into
the existing hook later without changing the hook itself.

## Test plan

### `src/shared/sync/outbox-operation.test.ts`

- `createOutboxOperation` builds the expected shape with `attemptCount: 0`,
  both attempt fields `null`.
- `createOutboxOperationId` is deterministic given injected `now`/`random`
  (mirrors existing `createCustomTrickId`/`createGoalId` tests) and differs
  for different inputs.
- `isOutboxOperation` table-test of malformed shapes, each independently
  invalidating: non-object, missing/blank `operationId`, unknown `domain`,
  invalid `operationType`, blank `recordId`, `upsert` with `payload: null`,
  `delete` with non-null `payload`, non-finite `createdAt`, negative/
  non-integer `attemptCount`, non-null-non-number `lastAttemptedAt`,
  non-null-non-string `lastErrorMessage` — plus one fully valid control case
  that must pass.

### `src/shared/sync/sync-envelope.test.ts`

Use a small fixture `State` type, e.g. `{ readonly items: readonly string[] }`,
with a trivial `isState` codec, so the test doesn't need any real domain
model. Use `GUEST_IDENTITY` and one `createUserIdentity(...)`-built identity
(reuse the same fixed UUID pattern already used in
`identity-isolation-matrix.test.tsx`) for the two-identity cases.

1. **Atomic pairing (state + operation persist together in one write).**
   Build a `jest.fn()`-backed fake `KeyValueStorage`. Call
   `applyLocalMutation` then `saveSyncEnvelope` once. Assert
   `storage.setItem` was called **exactly once**, and that the single
   persisted JSON blob contains both the new `state` and the new outbox
   entry. This is the concrete proof technique for "atomic" without a real
   storage-crash harness — one write call carries both concerns or the test
   fails.

2. **Survives reload.** Use the real `@react-native-async-storage/async-storage`
   jest mock (`jest.mock('@react-native-async-storage/async-storage', ...)`
   as already done in `identity-isolation-matrix.test.tsx`). `saveSyncEnvelope`
   against one storage key, then simulate "reload" by calling `loadSyncEnvelope`
   again with a **fresh** `KeyValueStorage` wrapper around the same
   `AsyncStorage` module (new closures, no shared in-memory JS reference) and
   assert the round-tripped envelope (`state`, `outbox`, `cursor`) equals what
   was saved.

3. **Stable operation IDs across retries.** `applyLocalMutation` once, then
   call `recordOutboxOperationAttempt` twice with different
   `attemptedAt`/`errorMessage`. Assert `operationId` is unchanged across
   both calls, `attemptCount` goes 0→1→2, and `lastAttemptedAt`/
   `lastErrorMessage` reflect only the most recent attempt.

4. **FIFO order preserved.**
   - Apply three mutations in sequence; assert `outbox` order matches
     insertion order (by `recordId` or a distinguishing payload field).
   - Save and reload; assert order survives serialization.
   - Acknowledge the middle operation; assert the remaining two keep their
     original relative order.
   - Call `recordOutboxOperationAttempt` on the first remaining operation;
     assert order is unchanged (only that entry's fields mutate in place).
   - Compose `saveSyncEnvelope` through `createWriteQueue` (same pattern as
     `storage.test.ts`'s "prevents a slower older write from overtaking newer
     state" test): enqueue an envelope-with-operation-A save that resolves
     slowly, then enqueue an envelope-with-operation-A-and-B save that
     resolves fast; assert the storage's final persisted value is the
     later-enqueued one (A+B), not the earlier one overwriting it out of
     order — proving this contract composes correctly with the existing
     write-queue ordering guarantee rather than needing its own.

5. **Rejects malformed envelopes.** Via `deserializeSyncEnvelope` (each case
   must return `undefined`) and via `loadSyncEnvelope` (each case must return
   `status: 'recovered'` with an initial/empty envelope, never `'loaded'`):
   wrong `version`, wrong `domain` (envelope tagged for a different domain
   than requested), non-string `identityNamespace`, state failing the
   codec, non-array `outbox`, one malformed operation inside an otherwise
   valid `outbox`, an operation whose `domain` doesn't match the envelope's
   `domain`, two operations sharing the same `operationId`, non-string/
   non-null `cursor`, unparseable JSON.

6. **Cannot be loaded under another identity.** Persist an envelope tagged
   for identity A (`identityNamespace: identityNamespace(USER_A_IDENTITY)`)
   directly into the fake storage. Call `loadSyncEnvelope(..., identity: USER_B_IDENTITY, ...)`
   against that same storage/key; assert `status: 'recovered'` (not
   `'loaded'`) with an error, and that the returned envelope's `state` is the
   caller's `initialState`, not A's persisted state. Repeat for
   guest-vs-user and user-vs-guest.

7. **Cannot be acknowledged under another identity.** Build an envelope
   tagged for identity A with one pending operation. Call
   `acknowledgeOutboxOperation(envelope, USER_B_IDENTITY, operationId)` and
   `recordOutboxOperationAttempt(envelope, USER_B_IDENTITY, ...)` and
   `applyLocalMutation(envelope, USER_B_IDENTITY, ...)` and
   `updateSyncCursor(envelope, USER_B_IDENTITY, ...)`; assert every one
   returns `{ status: 'rejected', reason: 'identityMismatch' }` and, in the
   acknowledge case specifically, that the operation is still present in
   `envelope.outbox` afterward (i.e. the rejection is a true no-op, not a
   partial removal).

## Risks / non-obvious points for the implementer

- Do not let `sync-envelope.ts` or `outbox-operation.ts` import anything from
  `src/features/*` or `src/shared/supabase/*` — grep for `@/features` and
  `@/shared/supabase` in both new files before finishing; a violation would
  quietly break the shared/features layering this repo relies on.
- `createdAt`/`attemptedAt` timestamps are **always caller-supplied
  parameters**, never `Date.now()` calls inside `outbox-operation.ts` or
  `sync-envelope.ts` (`createOutboxOperationId`'s default parameter is the
  one sanctioned exception, exactly mirroring `createCustomTrickId`/
  `createGoalId`'s existing default-parameter pattern) — this is what the
  task's "keep timers/Date.now() out of persisted-state logic" instruction
  cashes out to concretely, and it's what keeps the whole module unit-testable
  without fake timers.
- `acknowledgeOutboxOperation` removing the operation (rather than flagging a
  status and keeping it forever) is a deliberate simplicity choice for this
  ticket. If a future ticket needs an audit trail of acknowledged operations,
  that is new scope, not an oversight here.
- The two-layer identity defense (physical key namespacing in
  `scoped-storage.ts`, independently re-checked via `identityNamespace` baked
  into the envelope) is intentional, not redundant — it directly produces the
  "cannot be loaded/acknowledged under another identity" tests without
  depending on `scoped-storage.ts` being wired correctly by every future
  caller.
