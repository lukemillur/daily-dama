# T078 — Reuse the trick directory in all-trick goal creation

## Goal

Replace the all-trick goal screen's bespoke alphabetized picker with the shared `TrickDirectory` presentation, while preserving the existing goal form, goal-domain persistence, and per-trick goal route. The picker must use the same standard/custom sectioning and styling as the main Tricks directory, including an explicitly supplied persisted focused-trick list.

## Ordered implementation plan

1. Extend `src/features/tricks/components/trick-directory.tsx` with the smallest optional picker capabilities needed by this flow.
   - Add an optional search configuration/query surface that filters `DirectoryTrick` values by name before calling `createTrickSections`; keep the default directory behavior unchanged for Tricks, onboarding, Sesh, and laced-trick callers.
   - Add an optional single-trick activation callback (or equivalent action prop) that receives the complete `DirectoryTrick`, renders the existing shared row identity/custom metadata, and exposes an accessible “Choose …” action. Do not reinterpret the existing checkbox `selection` contract, since that represents multi-selection and is used by focused-practice flows.
   - Ensure the filtered list still passes `showFocusedSection` and `focusedTrickIds` to the existing focused-section contract. Focused items must remain first and retain the source directory order; an empty focused section should retain the shared empty-state treatment.
   - Keep the shared row, section-header, custom-trick labeling, and search styling coherent with the existing directory rather than recreating `TrickOption` styles in Goals.

2. Refactor `src/features/goals/components/all-trick-goals-screen.tsx` to use `TrickDirectory` for the `select-trick` step.
   - Remove the local `TrickPicker`, `TrickOption`, and bespoke filtered/sorted list implementation.
   - Preserve the current `ScreenStep` discriminated union and transition: activating a directory trick stores its ID/name snapshot and renders the existing `GoalForm`; cancel returns to the goal list.
   - Supply the picker-specific header copy, search affordance, and single-trick activation callback to `TrickDirectory`; do not alter the existing goal list, `GoalForm`, validation, or `addGoal` call.
   - Add an explicit `focusedTrickIds` prop to `AllTrickGoalsScreen` if needed to keep profile focus separate from picker interaction state. Do not make the directory infer focus from transient picker state.

3. Update `src/app/tricks/goals.tsx` and its route/test fixtures to pass the persisted profile focus list explicitly.
   - Read `selectedTrickIds` from the user-profile provider and pass it to the all-trick goals screen as the focused-section input alongside the existing standard/custom directory values.
   - Keep `createProfileDirectoryTricks(KENDAMA_KENTEI_TRICKS, tricks)` as the authoritative directory input and retain the current onboarding guard and `/tricks` back route.
   - Do not change goal persistence, profile persistence, or the existing `src/app/tricks/[trickId]/goals.tsx` per-trick goal screen.

4. Expand `src/features/goals/components/all-trick-goals-screen.test.tsx` (and route coverage where necessary) around the ticket's behavior.
   - Use standard and custom `DirectoryTrick` fixtures plus an explicit focused-ID list, and assert that the picker renders shared directory section headers/row treatment, custom labeling, and the focused section before ranked/custom sections in expected directory order.
   - Assert search narrows the shared directory rows and that activating a matching standard or custom row opens the existing goal form with the correct trick ID/name.
   - Complete the form for a selected trick and await the provider's queued write; assert the serialized AsyncStorage goals document contains that selected trick ID/name and target, proving the existing persistence path remains intact.
   - Preserve existing coverage for list progress, empty state, practice links, and deletion; update accessibility labels only where the shared directory contract intentionally changes them.
   - Add or adjust route-level coverage to prove `selectedTrickIds` is passed as the focused-section input without changing direct per-trick goal resolution.

5. Verify the focused behavior and repository-required web-safe checks.
   - Run the focused all-trick goal and route tests first, then `yarn test --runInBand`, `yarn lint`, `yarn tsc --noEmit`, and `yarn expo export --platform web --output-dir /tmp/daily-dama-web-export` (or the repository verification wrapper with the same checks).
   - If manually checking in a browser, use the Expo development server and verify the Add goal picker at the existing web route, including search, focused ordering, standard/custom activation, and saved goal return to the list.
   - Do not launch native tooling; iOS and Android validation remain deferred by the repository handoff.

## Scope and assumptions

- `createTrickSections` and its focused-section ordering are already the source of truth; this task should consume that contract rather than add a second ordering algorithm.
- The shared directory search/activation API is intentionally optional so existing directory consumers retain their current behavior and semantics.
- Goal records continue to store the selected trick's ID/name snapshot through `GoalForm` and `useGoalActions`; no goal schema or persistence adapter changes are planned.
- Browser/mobile visual polish beyond matching the shared directory treatment, and native verification, are deferred to later work.
