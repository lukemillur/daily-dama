# T155.10 — Map profile and trick-state rows at the runtime boundary

## Scope guardrail

Pure mapping + runtime validation only. No provider/reducer wiring, no
`getSupabaseClient()`/auth-session calls, no sync/diff logic (deciding which
trick-state rows to delete when a trick is deselected is future work,
T157.3). Everything here operates on already-fetched rows and already-built
`UserProfile` values passed in as plain arguments.

## What already exists (read, don't re-derive)

- `src/shared/supabase/cloud-repository.ts` — `CloudMutationResult`,
  `CloudReadResult`, `CloudRepositoryError` (kind: notFound/authorization/
  validation/network/unknown). This is a *transport*-layer error vocabulary
  (Postgrest/network failures). Do not reuse `CloudRepositoryErrorKind` for
  mapping-layer validation issues — they're a different failure mode (shape
  problems in already-successfully-fetched data), so this task defines its
  own issue type instead of overloading that one.
- `src/features/profile/persistence/profile-cloud-repository.ts` — exports
  `ProfileRow`, `ProfileUpsertInput`, `UserTrickStateRow`,
  `UserTrickStateUpsertInput` (all derived from `Database['api']['Tables']`).
  `getProfile()` already returns `CloudReadResult<ProfileRow | null>` — the
  `ProfileRow | null` is exactly the "explicit absence" input this task's
  row→domain mapping must accept.
- `supabase/migrations/20260822193659_add_profiles_and_user_trick_states.sql`
  — the CHECK constraints this task's row→domain validation must mirror:
  - `profiles_kentei_rank_range`: `kentei_rank` null or 1–12.
  - `profiles_kentei_rank_requires_onboarding`: `kentei_rank` is non-null
    iff `has_completed_onboarding` is true.
  - `profiles_streak_threshold_range`: null, or a multiple of 60000 in
    [60000, 3600000].
  - `profiles_theme_*_color_format`: null or `^#[0-9a-fA-F]{6}$`.
  - `profiles_last_sesh_shape`: null, or `{trickId: string, plan: {...}}`
    with `plan.kind` `'openEnded'` (optional `targetLandingCount` integer
    1–999) or `'timed'` (`durationMinutes` integer 1–60), no extra keys.
  - `user_trick_states_unique_per_user`: unique `(user_id, trick_id)`.
  - `user_trick_states_has_state`: `is_selected OR is_manually_unlocked`
    (a row with both false is invalid — mirror this defensively even though
    the DB rejects it at the source).
- `src/features/profile/model/user-profile.ts` — `UserProfile`, `LastSesh`,
  `isValidThemeHexColor` (already exported, reuse directly).
- `src/features/profile/persistence/user-profile-persistence.ts` — has
  `isKenteiRank`, `isLastSesh`, `isStreakThresholdMs` as **unexported**
  local helpers whose logic is already bit-for-bit aligned with the CHECK
  constraints above (same ranges, same LastSesh JSON shape). Reuse these
  rather than re-deriving equivalent logic in the new mapping file — a
  second hand-written copy of "what is a valid LastSesh JSON blob" is a
  drift risk the codebase doesn't need.
- `src/shared/supabase/cloud-repository.type-check.ts` — the established
  pattern for compile-time-only proofs: a `*.type-check.ts` file (not
  `*.test.ts`, not under `__tests__/`) so jest never collects it but
  `tsc --noEmit` still checks it, using local `Equal`/`Expect` helpers.

## Key design decisions (resolved here so the implementer doesn't re-litigate)

1. **Direction asymmetry is intentional.** Row→domain (data arriving from
   the untrusted cloud boundary) returns a discriminated `Result`-style
   type covering absent/invalid/valid. Domain→row (data leaving our own
   reducer-validated `UserProfile`) is a **total, non-`Result` pure
   function** — `UserProfile` is already a trusted, reducer-constructed
   shape by the time anything calls these mappers, and validating it again
   here would just be dead code paths with no way to reach them from
   real app state. Don't add a `Result` wrapper to the domain→row
   direction; it makes the call sites clunkier for no defensive value.

2. **The domain model is split across two cloud tables.** `UserProfile`'s
   `selectedTrickIds`/`manuallyUnlockedTrickIds` arrays don't exist as
   columns on `profiles` — they're normalized into one `user_trick_states`
   row per trick (`is_selected`, `is_manually_unlocked` booleans). So this
   task needs three row→domain-ish functions, not one:
   - `mapProfileRowToDomainFields` — the scalar fields only (everything on
     `UserProfile` except the two trick-id arrays).
   - `mapTrickStateRowsToDomainFields` — reconstructs both trick-id arrays
     from a list of `UserTrickStateRow`.
   - `composeUserProfileFromCloudRows` — combines both into a full
     `UserProfile`, and is where the "partial" case lives (trick-state rows
     exist but the profile row is absent — shouldn't happen given the FK
     cascade, but is exactly the kind of defensive case the exit criteria
     ask for and is cheap to test).

3. **Row `id` (the `user_trick_states` UUID primary key) is not part of
   this mapping's surface.** The local domain has no field for it, and
   `profile-cloud-repository.ts`'s `upsertTrickState` already preserves row
   identity server-side via its insert-then-update-on-conflict pattern
   keyed on `(user_id, trick_id)` — the mapping layer never needs to read
   or round-trip the row `id`. "Preserve stable trick-state identity" in
   the exit criteria means `trick_id` (standard or custom trick IDs) must
   pass through unmodified, not that this task must track the row UUID.

4. **Empty trick-id collections are canonicalized to `[]`, not
   `undefined`, on the way back out of `composeUserProfileFromCloudRows`.**
   `UserProfile.manuallyUnlockedTrickIds` is optional and can legitimately
   be `undefined` (never touched) or `[]` (touched then fully cleared) in
   live reducer state — cloud storage can't distinguish those two cases
   (zero matching rows either way), so this is a genuine, inherent,
   acceptable lossy conversion. Pick `[]` as the canonical reconstructed
   value and document it inline. Round-trip tests must build their
   "before" fixture with `manuallyUnlockedTrickIds: []` (not `undefined`)
   when asserting exact round-trip equality on that field, or normalize
   both sides with `?? []` before comparing. Getting this backwards
   produces a confusing, not-obviously-related test failure — call it out
   if you see one.

5. **Runtime type validation, not just business-rule validation.** Treat
   incoming row fields as effectively `unknown` at this boundary (the task
   description says "runtime response validation"): check `typeof`/shape,
   not just range/format, so a hand-malformed fixture cast through
   `as ProfileRow` in a test is actually caught. Don't rely on the
   generated `ProfileRow`/`UserTrickStateRow` TS types alone to prove
   correctness at runtime.

6. **"TypeScript compilation prevents ambiguous empty-object fallbacks"**
   is satisfied structurally by the discriminated-union `Result` types
   (no branch has an optional/defaultable field standing in for absence)
   plus a couple of `@ts-expect-error` compile-time proofs in a
   `.type-check.ts` file, following the `cloud-repository.type-check.ts`
   pattern. No new runtime code is needed to satisfy this bullet — it's a
   types-only proof.

### 2. `src/features/profile/persistence/profile-cloud-mapping.ts` (new)

```ts
import type { LastSesh, UserProfile } from '@/features/profile/model/user-profile';
import { isValidThemeHexColor } from '@/features/profile/model/user-profile';
import {
  isKenteiRank,
  isLastSesh,
  isStreakThresholdMs,
} from '@/features/profile/persistence/user-profile-persistence';
import type {
  ProfileRow,
  ProfileUpsertInput,
  UserTrickStateRow,
  UserTrickStateUpsertInput,
} from '@/features/profile/persistence/profile-cloud-repository';

export type ProfileMappingIssueReason =
  | 'missingField'
  | 'wrongType'
  | 'outOfRange'
  | 'malformedShape'
  | 'foreignUser'
  | 'duplicateTrickId'
  | 'invariantViolation';

export interface ProfileMappingIssue {
  readonly path: string;    // e.g. 'kentei_rank', 'last_sesh.plan.durationMinutes', 'rows[1].user_id'
  readonly reason: ProfileMappingIssueReason;
  readonly message: string; // human-readable, safe to log
}

export type ProfileScalarFields = Omit<UserProfile, 'selectedTrickIds' | 'manuallyUnlockedTrickIds'>;
export type TrickStateFields = Pick<UserProfile, 'selectedTrickIds' | 'manuallyUnlockedTrickIds'>;

export type ProfileRowMappingResult =
  | { readonly status: 'absent' }
  | { readonly status: 'invalid'; readonly issues: readonly ProfileMappingIssue[] }
  | { readonly status: 'valid'; readonly fields: ProfileScalarFields };

export type TrickStateRowsMappingResult =
  | { readonly status: 'invalid'; readonly issues: readonly ProfileMappingIssue[] }
  | { readonly status: 'valid'; readonly fields: TrickStateFields };

export type UserProfileCompositionResult =
  | { readonly status: 'absent' }
  | { readonly status: 'invalid'; readonly issues: readonly ProfileMappingIssue[] }
  | { readonly status: 'valid'; readonly profile: UserProfile };

export function mapProfileRowToDomainFields(
  row: ProfileRow | null,
  expectedUserId: string,
): ProfileRowMappingResult;

export function mapTrickStateRowsToDomainFields(
  rows: readonly UserTrickStateRow[],
  expectedUserId: string,
): TrickStateRowsMappingResult;

export function composeUserProfileFromCloudRows(
  profileRow: ProfileRow | null,
  trickStateRows: readonly UserTrickStateRow[],
  expectedUserId: string,
): UserProfileCompositionResult;

export function mapUserProfileToProfileUpsertInput(
  profile: UserProfile,
  userId: string,
): ProfileUpsertInput;

export function mapUserProfileToTrickStateUpsertInputs(
  profile: UserProfile,
  userId: string,
): readonly UserTrickStateUpsertInput[];
```

**`mapProfileRowToDomainFields` behavior:**
- `row === null` → `{ status: 'absent' }`.
- `row.user_id !== expectedUserId` → `invalid`, one issue
  `{ path: 'user_id', reason: 'foreignUser', ... }` (short-circuit: don't
  also run field validation against a row that isn't this user's).
- Otherwise validate every field, **collecting all issues** (don't
  fail-fast) so a single malformed row surfaces every problem at once:
  - `has_completed_onboarding`: must be `boolean` (`wrongType` else).
  - `kentei_rank` vs `has_completed_onboarding`: onboarding true requires
    `isKenteiRank(kentei_rank)`; onboarding false requires
    `kentei_rank === null`. Mismatches → `invariantViolation` or
    `outOfRange`/`wrongType` as appropriate.
  - `last_sesh`: null is fine; otherwise `isLastSesh(last_sesh)` must hold
    (`malformedShape` else).
  - `streak_threshold_ms`: null is fine; otherwise
    `isStreakThresholdMs(...)` must hold (`outOfRange` else).
  - `theme_background_color`/`theme_accent_color`/`theme_text_color`: null
    is fine; otherwise `isValidThemeHexColor(...)` must hold
    (`malformedShape` else).
  - If any issues collected → `invalid`. Otherwise → `valid`, with
    `null → undefined` translation applied per optional field (this is the
    row's "absent" encoding vs. the domain's).

**`mapTrickStateRowsToDomainFields` behavior:**
- For each row, check (accumulating issues across all rows, not just the
  first bad one): `user_id === expectedUserId` (`foreignUser` else),
  `trick_id` is a non-empty string (`malformedShape` else), `is_selected`/
  `is_manually_unlocked` are booleans (`wrongType` else), and
  `is_selected || is_manually_unlocked` (`invariantViolation` else,
  mirroring `user_trick_states_has_state`).
- Separately check for duplicate `trick_id` across the whole row list
  (`duplicateTrickId`) — defense against a data anomaly the DB's unique
  constraint should already prevent.
- Any issues anywhere → `invalid` with the full aggregated issue list (a
  batch containing one bad row must not silently drop that row and return
  a partial success — this is deliberate: partial success here would mean
  silently wrong trick-selection state for the user).
- Otherwise → `valid`, with `selectedTrickIds` = ids of rows where
  `is_selected`, `manuallyUnlockedTrickIds` = ids of rows where
  `is_manually_unlocked`, in the order given (mapping doesn't reorder —
  ordering is the caller/repository's concern, e.g.
  `listTrickStates`'s `created_at desc, id asc`).

**`composeUserProfileFromCloudRows` behavior:**
- `mapProfileRowToDomainFields(profileRow, expectedUserId)`:
  - `absent` and `trickStateRows.length === 0` → `{ status: 'absent' }`.
  - `absent` and `trickStateRows.length > 0` → `invalid`, one issue
    `{ path: 'profile', reason: 'malformedShape', message: 'trick-state rows exist without an owning profile row' }`
    (the "partial row" case named in the exit criteria).
  - `invalid` → propagate its issues as-is.
  - `valid` → proceed.
- `mapTrickStateRowsToDomainFields(trickStateRows, expectedUserId)`:
  - `invalid` → propagate its issues.
  - `valid` → `{ status: 'valid', profile: { ...scalarFields, ...trickStateFields } }`.

**`mapUserProfileToProfileUpsertInput` behavior:** build a fresh object
literal — never spread-then-mutate `profile` — mapping
`hasCompletedOnboarding → has_completed_onboarding`,
`kenteiRank ?? null → kentei_rank`, `lastSesh ?? null → last_sesh` (cast
through `Json` — passing the same object reference is fine, it's not
mutated, see mutation-test notes below), `streakThresholdMs ?? null`,
`themeBackgroundColor ?? null`, `themeAccentColor ?? null`,
`themeTextColor ?? null`, plus `user_id: userId`. Deliberately **omit**
`created_at`/`updated_at`/`revision` — those are server-owned
(`ProfileUpsertInput`'s generated `Insert` type already makes them
optional), don't invent client-side values for them.

**`mapUserProfileToTrickStateUpsertInputs` behavior:** build the set
`allTrickIds = [...selectedTrickIds, ...(manuallyUnlockedTrickIds ?? [])]`
deduplicated preserving first-seen order (selected ids first, then any
manually-unlocked-only ids), and for each id emit
`{ user_id: userId, trick_id: id, is_selected: selectedTrickIds.includes(id), is_manually_unlocked: (manuallyUnlockedTrickIds ?? []).includes(id) }`.
Every emitted row automatically satisfies `is_selected || is_manually_unlocked`
since `id` only appears in `allTrickIds` because it was in at least one
source array — call this out as a one-line comment, it's a real invariant
worth being explicit about rather than leaving it implicit. Note in a
comment: this function does **not** compute deletions for trick ids that
were previously selected/unlocked and no longer are — that diff belongs to
the future sync layer (T157.3), not this mapping.

### 4. `src/features/profile/persistence/profile-cloud-mapping.test.ts` (new)

Use `@jest/globals` (`describe`/`it`/`expect`), matching
`cloud-repository.test.ts`'s style. No mocked Supabase client needed —
everything is hand-constructed row/`UserProfile` fixtures.

**Round-trip (domain → rows → domain), one `it` per variant:**
- `INITIAL_USER_PROFILE`-shaped: `hasCompletedOnboarding: false`, empty
  `selectedTrickIds`, everything else undefined.
- Fully onboarded, minimal: `hasCompletedOnboarding: true`,
  `kenteiRank: 1`, one selected trick, nothing else.
- Fully onboarded with every optional field populated: `kenteiRank: 12`,
  `lastSesh` = open-ended with no target, streak threshold at both
  boundaries (separate cases), theme colors (mixed-case hex), several
  selected and several manually-unlocked trick ids with partial overlap.
- `lastSesh` = open-ended **with** `targetLandingCount` (boundary 1 and
  999 as separate cases).
- `lastSesh` = timed (boundary `durationMinutes` 1 and 60 as separate
  cases).
- `selectedTrickIds` non-empty, `manuallyUnlockedTrickIds: []` (canonical
  empty form per design decision 4 above) — asserts round-trip exactness
  on this specific field.
- `manuallyUnlockedTrickIds` non-empty, `selectedTrickIds: []`.
- Standard-trick-id and custom-trick-id-shaped strings both present in the
  same profile (proves "stable trick-state identity" isn't accidentally
  scoped to one id format).

For each: call `mapUserProfileToProfileUpsertInput` +
`mapUserProfileToTrickStateUpsertInputs`, splice the upsert inputs into
full `ProfileRow`/`UserTrickStateRow[]` fixtures by filling in
`id`/`created_at`/`updated_at`/`revision` defaults, call
`composeUserProfileFromCloudRows`, and assert
`{ status: 'valid', profile: <expected> }` — where `<expected>` normalizes
`manuallyUnlockedTrickIds` with `?? []` per design decision 4 if the source
fixture used `undefined`.

**Reject malformed rows** (`mapProfileRowToDomainFields` /
`composeUserProfileFromCloudRows`):
- `kentei_rank` = 0, 13, and 1.5 (three cases).
- `has_completed_onboarding: true`, `kentei_rank: null`.
- `has_completed_onboarding: false`, `kentei_rank: 5`.
- `has_completed_onboarding` as a non-boolean (e.g. `1`), via
  `as unknown as ProfileRow` cast.
- `streak_threshold_ms` not a multiple of 60000 (e.g. `90000`), and out of
  range (e.g. `30000`, `3660000`).
- Each theme color field individually malformed (missing `#`, wrong
  length, non-hex characters) — three cases.
- `last_sesh` malformed: missing `trickId`, `plan.kind` missing/unknown,
  `plan` with an extra unrecognized key, `targetLandingCount` out of
  range/non-integer, `durationMinutes` out of range.
- Assert the returned issue list is non-empty and includes an issue with
  the expected `path`/`reason` for at least one representative case per
  bullet (don't over-assert exact message text everywhere).
- One case with **multiple** simultaneous problems (e.g. bad `kentei_rank`
  *and* bad `streak_threshold_ms`) asserting the issue list has an entry
  for each — proves issues are collected, not fail-fast.

**Reject partial rows:**
- `profileRow: null`, `trickStateRows: [<one row>]` →
  `composeUserProfileFromCloudRows` returns `invalid` with a `path: 'profile'` issue.
- A `UserTrickStateRow` with `is_selected: false, is_manually_unlocked: false`
  → `invariantViolation`.
- A `UserTrickStateRow` with `trick_id: ''` → `malformedShape`.

**Reject foreign-user rows:**
- `profileRow.user_id !== expectedUserId` → `invalid`, `foreignUser`
  issue, and assert `composeUserProfileFromCloudRows` does **not** fall
  through to processing trick-state rows for that mismatched profile.
- `trickStateRows` = two rows, one matching `expectedUserId` and one not →
  `invalid` for the whole batch (not a partial success dropping the bad
  row) — assert this explicitly, it's the "batch rejection, not silent
  drop" decision from above.

**Duplicate trick-state identity:**
- Two `UserTrickStateRow`s with the same `trick_id` (different `id`) →
  `duplicateTrickId`.

**Explicit absence:**
- `profileRow: null`, `trickStateRows: []` →
  `{ status: 'absent' }` from `composeUserProfileFromCloudRows`.
- `mapProfileRowToDomainFields(null, ...)` alone →
  `{ status: 'absent' }`.

**No input mutation** (both directions):
- Deep-freeze (write a small local `deepFreeze` helper, recursing into
  `lastSesh`/`plan` too) a representative `UserProfile` fixture, call both
  `mapUserProfileToProfileUpsertInput` and
  `mapUserProfileToTrickStateUpsertInputs` on it, and assert no throw (a
  frozen-object write attempt throws in strict mode/jest) **and** that a
  `JSON.stringify`-based snapshot taken before the calls still matches one
  taken after.
- Deep-freeze a `ProfileRow` and a `UserTrickStateRow[]` fixture, call
  `composeUserProfileFromCloudRows`, same no-throw + before/after snapshot
  assertion.
