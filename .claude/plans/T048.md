# T048 — Persist open-ended sesh target laces across sessions

## Current state (verified in code)

- `src/features/sesh/model/sesh.ts` already models an optional target on the *runtime* `SeshPlan`: `{ kind: 'openEnded'; target?: SeshTarget }` where `SeshTarget = { landingCount: number }`, plus `createOpenEndedSeshPlan(landingCount?)`, `isValidSeshTargetLandingCount`, `MIN_SESH_TARGET_LANDING_COUNT` / `MAX_SESH_TARGET_LANDING_COUNT`. Nothing here needs to change.
- `src/features/sesh/components/sesh.tsx` already pre-fills `targetLandingCount` state from `initialPlan.target.landingCount` when present (line ~262). So once `initialPlan` correctly carries a target, the UI pre-fill "just works" — no UI change needed.
- The persisted `LastSeshPlan` (`src/features/profile/model/user-profile.ts`) has no target field at all today:
  ```ts
  export type LastSeshPlan =
    | { readonly kind: 'openEnded' }
    | { readonly kind: 'timed'; readonly durationMinutes: number };
  ```
- `createLastSesh(trickId, plan)` (same file) unconditionally maps any non-timed plan to `{ kind: 'openEnded' }`, discarding `plan.target`.
- `src/app/sesh/index.tsx`'s `initialPlan` derivation unconditionally falls back to the bare `OPEN_ENDED_SESH_PLAN` constant for any non-timed `lastSesh`, discarding whatever `lastSesh.plan` might carry.
- `setLastSesh(trickId, plan)` (in `src/features/profile/state/user-profile-provider.tsx`) is called from two places in `sesh.tsx`: once when a sesh starts (`trickSelected`, using the plan the user just configured) and once on "Repeat sesh" (using `state.summary.plan`, the plan that was actually run). Both funnel through `createLastSesh`, so fixing `createLastSesh` fixes both call sites for free — no changes needed in `sesh.tsx` or the provider itself.
- Runtime validation for the persisted document lives in `src/features/profile/persistence/user-profile-persistence.ts`, specifically `isLastSesh`, which currently does a strict key-count check (`Object.keys(plan).length === 1` for `openEnded`, `=== 2` for `timed`) — this will reject a document with an added key unless updated.

This confirms the Notes' two-gap framing is accurate and complete; no additional gaps found.

## Field shape decision

Add an **optional** field to the `openEnded` variant of `LastSeshPlan`, named `targetLandingCount` (a bare number, not a nested `{ landingCount }` object — the persisted shape doesn't need to mirror the runtime `SeshTarget` wrapper, and a flat field keeps the validator's `Object.keys(plan).length` checks simple):

```ts
export type LastSeshPlan =
  | { readonly kind: 'openEnded'; readonly targetLandingCount?: number }
  | { readonly kind: 'timed'; readonly durationMinutes: number };
```

Rationale:
- Optional field on an already-optional (`lastSesh?`) structure is backward compatible by construction: old documents simply lack the key, `targetLandingCount` reads as `undefined`, and every existing code path treats "no target" as the current default behavior. No migration needed, consistent with how `lastSesh` and `streakThresholdMs` are already handled as optional.
- Reuses the existing `isValidSeshTargetLandingCount` from `src/features/sesh/model/sesh.ts` for validation, rather than inventing a second validity rule for the persisted shape.

## Implementation steps

Do the model/persistence change first (steps 1–3), then the two call sites that consume it (steps 4–5), in this order because 4–5 depend on the new field existing and typechecking.

1. **`src/features/profile/model/user-profile.ts`**
   - Update `LastSeshPlan`'s `openEnded` variant to add `readonly targetLandingCount?: number` as shown above.
   - Update `createLastSesh`:
     ```ts
     export function createLastSesh(trickId: string, plan: SeshPlan): LastSesh {
       return {
         trickId,
         plan:
           plan.kind === 'timed'
             ? { kind: 'timed', durationMinutes: plan.durationMs / 60_000 }
             : plan.target
               ? { kind: 'openEnded', targetLandingCount: plan.target.landingCount }
               : { kind: 'openEnded' },
       };
     }
     ```
     (Keep emitting a bare `{ kind: 'openEnded' }` — no `targetLandingCount: undefined` key — when there's no target, so serialized output for untargeted seshes is byte-for-byte what it is today and existing equality-based tests keep passing.)

2. **`src/features/profile/persistence/user-profile-persistence.ts`**
   - Import `isValidSeshTargetLandingCount` alongside the existing `isValidTimedSeshMinutes` import from `@/features/sesh/model/sesh`.
   - Update `isLastSesh` to accept the new optional key while still rejecting anything malformed:
     ```ts
     function isLastSesh(value: unknown): value is LastSesh {
       if (!isRecord(value)) return false;

       const { trickId, plan } = value;
       if (typeof trickId !== 'string' || trickId.length === 0 || !isRecord(plan)) return false;

       if (plan.kind === 'openEnded') {
         const keys = Object.keys(plan);
         if (keys.length === 1) return true;
         return (
           keys.length === 2 &&
           'targetLandingCount' in plan &&
           isValidSeshTargetLandingCount(Number(plan.targetLandingCount))
         );
       }
       if (plan.kind === 'timed') {
         return isValidTimedSeshMinutes(Number(plan.durationMinutes)) && Object.keys(plan).length === 2;
       }
       return false;
     }
     ```
   - This keeps the validator strict (rejects extra/unknown keys, rejects out-of-range or non-integer targets) while accepting both the old 1-key `openEnded` shape and the new 2-key shape — satisfying "a profile with no persisted target ... behaves exactly as today."

3. **Tests for steps 1–2** (update alongside, not deferred):
   - `src/features/profile/persistence/user-profile-persistence.test.ts`: add a round-trip test for an `openEnded` plan with `targetLandingCount` set (mirroring the existing timed/openEnded round-trip tests around lines 38–56), and extend the `it.each` malformed-last-sesh table (~line 108) with cases like `{ trickId: 'big-cup', plan: { kind: 'openEnded', targetLandingCount: 0 } }` and `{ trickId: 'big-cup', plan: { kind: 'openEnded', targetLandingCount: 1000 } }` (out of `MIN_SESH_TARGET_LANDING_COUNT`/`MAX_SESH_TARGET_LANDING_COUNT` range) to confirm the validator rejects bad targets.
   - `src/features/profile/model/user-profile.test.ts` doesn't strictly need new cases (the reducer just stores whatever `LastSesh` it's given verbatim), but if there's an existing direct test of `createLastSesh` add/extend one there; grep confirmed there isn't one today — worth adding one covering `createLastSesh(trickId, createOpenEndedSeshPlan(10))` producing `{ trickId, plan: { kind: 'openEnded', targetLandingCount: 10 } }`, and `createLastSesh(trickId, OPEN_ENDED_SESH_PLAN)` producing `{ trickId, plan: { kind: 'openEnded' } }` (no key), to lock in the "omit when absent" behavior from step 1.

4. **`src/app/sesh/index.tsx`**
   - Import `createOpenEndedSeshPlan` from `@/features/sesh/model/sesh` (alongside the existing `createTimedSeshPlan`, `OPEN_ENDED_SESH_PLAN`, `SeshPlan` import — `OPEN_ENDED_SESH_PLAN` itself becomes unused after this change and should be removed from the import).
   - Change the `initialPlan` derivation's open-ended branch from the bare constant to a call that forwards the persisted target:
     ```ts
     const initialPlan: SeshPlan | undefined = challengeDurationMs
       ? createTimedSeshPlan(challengeDurationMs / 60_000)
       : lastSesh
         ? lastSesh.plan.kind === 'timed'

     ```
   - `createOpenEndedSeshPlan(undefined)` returns the same `OPEN_ENDED_SESH_PLAN` constant as before, so untargeted `lastSesh` values behave identically to today.

5. No changes needed in `src/features/sesh/components/sesh.tsx` or `src/features/profile/state/user-profile-provider.tsx` — verified both already do the right thing once `initialPlan` and `createLastSesh` carry the target correctly (see "Current state" above).

## Risk notes

- Low risk overall: this is an additive optional field on an already-optional structure, with existing runtime code (`sesh.tsx`'s pre-fill, `createOpenEndedSeshPlan`'s undefined-handling) already built to accommodate it. The two production edits are each a few lines.
- The one thing to get right precisely is the validator's key-count logic in `isLastSesh` — it must accept exactly the old 1-key shape and the new 2-key shape and reject everything else (3+ keys, wrong key name, out-of-range value, non-integer value), matching the existing strictness pattern used for the `timed` variant a few lines below it.
- Keep `createLastSesh` emitting the bare `{ kind: 'openEnded' }` (no explicit `targetLandingCount: undefined`) when there's no target — this avoids `JSON.stringify` differences that could otherwise fail the existing round-trip-equality tests (`toEqual` on a deserialized object; `undefined`-valued keys are dropped by `JSON.stringify` so this is likely fine either way, but omitting the key at construction time is cleaner and avoids relying on that stringify detail).
