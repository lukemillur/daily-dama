## Design decisions for this task

1. Step placement: insert a new themeSelect reducer status between selecting and
   completion. selectings existing Start practicing button (already guarded by
   selectedTrickIds.length greater than 0) now transitions to themeSelect instead of
   finishing onboarding directly. completeOnboarding and router.replace to the sesh
   route move to the new steps handlers.
2. Interaction model: tapping a preset swatch on the new step both applies the theme
   via setThemeColors AND immediately finishes onboarding -- mirrors the one tap sets
   both colors swatch semantics from Profile, and avoids adding a second Continue button
   plus extra reducer state to track a pending preset. A separate Skip for now button
   finishes onboarding without touching theme colors (default theme stays in effect, per
   the tasks note that skipping the step leaves the app on its default theme).
3. Swatch reuse: extract the presentational swatch-grid piece out of
   rainbow-theme-presets.tsx into a shared component so onboarding and Profile render
   pixel-identical swatches from one implementation, rather than duplicating the styled
   markup. Both call sites keep their own copy and wrapper text and their own
   onSelectPreset and setThemeColors wiring.

## Risks and non-obvious points

- The reducer no-op branch (themeStepEntered from a non-selecting status) matters because
  dispatch calls are static closures capturing state -- get the guard right (state.status
  equals selecting) or a stale dispatch could silently produce a broken themeSelect-shaped
  object with no valid prior state. Existing branches all follow this same return-state-
  unchanged-if-the-precondition-does-not-hold pattern; match it.
- Do not let ThemePresetGrids extraction change rainbow-theme-presets.tsxs rendered output
  -- rainbow-theme-presets.test.tsx asserts on exact accessibilityLabel and selection
  state and must keep passing without edits. If it needs edits, the extraction changed
  behavior and thats a signal to stop and re-check steps 2 and 3.
- OnboardingAssessmentSteps land or not-land flow is the slowest part of driving a test
  through to selecting; prefer entering at the Basic level (rank 1) and failing the very
  first trick to reach rankReveal fast without needing to lace multiple tricks --
  failing the very first trick at rank 1 still routes to rankReveal (see the reducers
  floors at rank 1 test) and is the fastest path to selecting without asserting anything
  about rank correctness (Case A and Case B do not need to test rank behavior, only the
  new theme step). Note this path still requires toggling at least one trick in selecting
  before Start practicing is enabled.
- Keep the theme steps presets non-animated (no react-native-reanimated import) -- this
  avoids a second reanimated-mock dependency surface in a component whose whole purpose is
  a simple tap-to-select grid, and matches OnboardingSelectionSteps existing choice not to
  animate its own list-heavy step.
