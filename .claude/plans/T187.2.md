# T187.2 — Wire automatic most-recent-wins conflict resolution

## Confirmed starting state

`development` (merged as `2cd5639`, present on this branch) already threads a
client-side `updatedAt` through:
- `UserProfile.updatedAt` — one document-level clock for the whole
  profile object (bumped by every reducer action, including trick-selection
  toggles). There is no separate per-trick-state timestamp.
- `Goal.updatedAt`, `CustomTrick`/`SequenceCustomTrick.updatedAt`,
  `Note.updatedAt` — per-record clocks (goals/custom-tricks/notes are
  collections of individually addressable records).

All four cloud-mapping files (`profile-cloud-mapping.ts`,
`goal-cloud-mapping.ts`, `custom-trick-cloud-mapping.ts`,
`note-cloud-mapping.ts`) already parse a server row's `updated_at` string
column into a domain `updatedAt` on pull. `SyncConflict<Row>.serverRow`
(`src/shared/sync/transport.ts`) is populated by every production adapter
(confirmed in `goal-sync-transport.ts`) but NOT by the hand-written fake
transports in the four `use-*-domain-sync.test.tsx` files or the two
integration tests -- those fakes only return
`{ operationId, recordId, expectedRevision, serverRevision }` on conflict.
Task-required test updates must add a realistic `serverRow` (with a
deliberately-chosen `updated_at`) to every conflict branch they touch.

Timestamp trap for the test rewrites: the shared fixture constant
`TIMESTAMP = '2026-01-01T00:00:00.000Z'` in
`cross-domain-conflict-fault-injection.integration.test.tsx` and
`two-browser-convergence.integration.test.tsx` is a fixed past date, while
local record `updatedAt` values come from real `Date.now()` at test-run
time (no fake timers in these files). Reusing `TIMESTAMP` verbatim as a
conflict's `serverRow.updated_at` will make local win every time (it's
always later), which silently defeats any scenario intending to exercise
the server-wins or tie branches. Each touched scenario must set its
`serverRow.updated_at` deliberately, relative to real time, to pin down
which branch it exercises.

## Chosen design

### 1. New shared module: src/shared/sync/conflict-resolution.ts

Replaces src/shared/sync/conflict.ts (which is deleted -- see step 2).
Exports two functions:

- resolveUpdatedAtConflict(localUpdatedAt: number, serverUpdatedAt: number | undefined): 'local' | 'server'
  Returns 'server' whenever serverUpdatedAt is undefined; otherwise returns
  'local' only when localUpdatedAt is strictly greater than serverUpdatedAt,
  else 'server'. Document inline that this single rule covers both the
  documented tie-break (exact tie keeps server) and the unknown-server-clock
  fallback (also keeps server) -- local only wins when it can prove it is
  newer.
- parseServerRowUpdatedAt(row: unknown): number | undefined
  Reads the `updated_at` string property off an untrusted conflict.serverRow
  (row-shaped JSON already returned by the transport, not yet mapped through
  a domain's own validator) and Date.parse()s it, returning undefined for
  anything not a finite-parseable string.

Add src/shared/sync/conflict-resolution.test.ts covering: local later wins,
server later wins, exact tie wins server, serverRow null/undefined/malformed
wins server, non-string updated_at wins server.

Do this file first -- every other change depends on it and it has zero
dependents to break while it's being written.

### 2. Remove the manual-conflict envelope machinery

Delete: src/shared/sync/conflict.ts, src/shared/sync/conflict.test.ts.

Edit src/shared/sync/sync-envelope.ts:
- Remove the SyncConflictRecord import and the `conflicts` field from
  SyncEnvelope<State>.
- Remove conflictRecorded / conflictRemoved / conflictResolved from
  SyncEnvelopeAction<State> and their three reducer cases.
- Remove the `conflicts: []` initializer from createInitialSyncEnvelope.
- Remove the conflicts-array validation branch from
  isValidSyncEnvelopeShape, and the `conflicts: parsed.conflicts ?? []`
  merge in deserializeSyncEnvelope (just return parsed -- it already
  satisfies the narrowed type once `conflicts` is gone).

Why this is safe to remove outright, not just stop populating: the two
transitions manual resolution needed are both already covered by existing,
still-used generic actions -- no new envelope action type is needed for
auto-resolution either:
- "keep local, retry against the fresh server revision" is exactly what
  localMutationApplied (via replacePendingOperationForRecord) already does:
  drop any pending op for recordId, append a replacement, swap in the
  snapshot. Auto-resolution dispatches it with one synthesized
  NewOutboxOperationInput built from the conflicting op's own
  operationType/payload.
- "keep server" is exactly operationAcknowledged (drops the losing pending
  op with no replacement) followed by revisionRecorded (writes the
  server-merged local mirror plus refreshed revision cache) -- the same two
  actions the push-success path already uses every run.

Backward compatibility: any envelope already persisted to AsyncStorage with
a non-empty `conflicts` array from before this change is unaffected --
`conflicts` simply becomes an ignored extra JSON key (never read), the
`outbox` array (a sibling field) is untouched, so that record's operation
still exists and will re-attempt on the next sync, now via the automatic
path. No migration needed, consistent with this repo's no-migration-infra
default for provisional sync-layer shapes.

Update src/shared/sync/sync-envelope.test.ts: delete the two `it` blocks at
the end ("removes one conflict without touching sibling outbox work" and
"requires the conflicted operation identity and preserves a
revision-aware replacement", roughly lines 729-753) -- they test the
actions just removed.

### 3. Rewire each of the four domain sync hooks

Files: src/features/profile/state/use-profile-domain-sync.ts,
src/features/custom-tricks/state/use-custom-trick-domain-sync.ts,
src/features/goals/state/use-goal-domain-sync.ts,
src/features/notes/state/use-note-domain-sync.ts. All four are
structurally near-identical (confirmed) -- do profile first since it's the
one document-level-clock oddball, then use it as the template with the
per-record lookup swapped in for the other three.

In each hook's runSyncImpl, in the per-outcome loop, the 'conflict' branch
currently records the attempt and dispatches conflictRecorded with a
SyncConflictRecord built from op.payload and outcome.result.conflict.serverRow.

Replace it with inline automatic resolution. Drop the
operationAttemptRecorded dispatch for this branch entirely -- the op is
fully resolved this same run, so there is no pending attempt/error state
left to record; keep operationAttemptRecorded only for the sibling 'failed'
branch, unchanged. The new branch:

1. Reads serverRow = outcome.result.conflict.serverRow ?? null and computes
   serverUpdatedAt = parseServerRowUpdatedAt(serverRow).
2. Computes localUpdatedAt using the domain-specific lookup described below.
3. Calls winner = resolveUpdatedAtConflict(localUpdatedAt, serverUpdatedAt).
4. If winner is 'local': dispatch a localMutationApplied envelope action
   with one synthesized operationInput (same domain, operationType, and
   payload as the conflicting op, but recordId = outcome.recordId), a fresh
   operationId, and a nextSnapshot whose revision cache is bumped to
   outcome.result.conflict.serverRevision for that recordId -- mirroring
   exactly what the old resolveConflict('local') branch built as its
   "replacement" operation and revisionSnapshot, just triggered here instead
   of from a later user tap.
5. If winner is 'server': set suppressNextDiffRef.current = true, dispatch
   the primary reducer's own *Restored action merged with serverRow (the
   exact merge logic the domain's existing resolveConflict('server') branch
   already implements, including its serverRow === null / "deleted on
   server" special case), then dispatch operationAcknowledged for the
   conflicting op's operationId, then dispatch revisionRecorded with the
   mirror/revision-cache updated (or cleared) for that recordId.
6. continue the loop either way.

Domain-specific localUpdatedAt lookup (the one place the four hooks
genuinely diverge, because profile has one document clock and the other
three have per-record clocks):

- profile (use-profile-domain-sync.ts): localUpdatedAt =
  envelopeAtPushStart.state.profile.updatedAt, falling back to op.createdAt
  if that is somehow undefined. This is correct for both the scalar-row
  conflict (recordId === userId) and any trick-state-row conflict, because
  UserProfile has no per-trick clock -- every local profile mutation
  (including trick selection) bumps the same document-level updatedAt.
- custom-tricks / goals / notes: look up the record by outcome.recordId in
  the envelope's local collection mirror (envelopeAtPushStart.state's
  collection field). If op.operationType is 'upsert' and the record is
  still present, use its updatedAt. If op.operationType is 'delete' (or,
  defensively, the record is already gone from the mirror), there is no
  residual updatedAt to read -- fall back to op.createdAt (the outbox
  operation's own timestamp, the closest available proxy for "when this
  device last touched the record").

Once the 'server' merge logic has been moved inline, delete each hook's
standalone resolveConflict function -- nothing calls it anymore (see step 4).

Also in each hook:
- Remove conflictCount, conflicts, resolveConflict from the
  Use*DomainSyncResult interface and the returned useMemo object (and its
  dependency array).
- Remove the SyncConflictRecord import; add resolveUpdatedAtConflict and
  parseServerRowUpdatedAt from the new conflict-resolution module.
