# T066 — Add a practice entry point from a rendered goal

## Context established by exploration

`GoalRow` (in `src/features/goals/components/trick-goals-screen.tsx`, exported and
re-imported by `all-trick-goals-screen.tsx`) is the **single** shared component that
renders every goal, on both the per-trick screen (`TrickGoalsScreen`) and the
all-tricks screen (`AllTrickGoalsScreen`). There is exactly one row-rendering call
site to change, not two.

`GoalRow`'s `progress: GoalProgress` prop already carries `progress.goal.trickId` and
`progress.goal.trickName` (the immutable snapshot fields on `GoalBase`, see
`src/features/goals/model/goal.ts`), so no new prop needs to be threaded in from
either screen — everything needed to build the Sesh link already reaches `GoalRow`.

T063's quick-start pattern, confirmed identical at all five existing call sites
(`src/features/tricks/components/trick-directory.tsx`,
`src/features/stats/components/neglected-tricks-section.tsx`,
`src/features/home/components/daily-home.tsx` ×2,
`src/app/stats/[trickId].tsx`):

```tsx
<Link asChild href={{ pathname: '/sesh', params: { trickId, mode: 'practice' } }}>
  <SomePressable accessibilityLabel={`Practice ${trickName}`} accessibilityRole="button" /* or "link" */>
    <SomeText>Practice</SomeText>
  </SomePressable>
</Link>
```

`src/app/sesh/index.tsx` reads `trickId` + `mode=practice` from search params and
passes `preferredTrickId`/`quickStart` into `<Sesh>`. `Sesh` (in
`src/features/sesh/components/sesh.tsx`) independently validates `preferredTrickId`
against the tricks actually available (`validatedPreferredTrickId`) and falls back
to the full picker if the trick no longer resolves — this fallback is centralized in
`Sesh`, so `GoalRow` does not need to pre-check trick availability itself (four of
the five existing call sites don't either; only `daily-home.tsx`'s hero button does,
because it also needs different fallback *copy*, which goals don't need here).

No new test file exists for `trick-goals-screen.tsx` yet; `GoalRow` is currently only
exercised indirectly through `all-trick-goals-screen.test.tsx`. That test file is the
natural place to add coverage since it already sets up `GoalProvider` +
`PracticeHistoryProvider` and mounts real goals without a router context (confirmed
via `neglected-tricks-section.test.tsx`, which asserts `link.props.href` directly on
an `expo-router` `Link` with no router mounted — that pattern works standalone).

## Implementation steps

1. **`src/features/goals/components/trick-goals-screen.tsx` — add the practice action to `GoalRow`.**
   - Import `Link` from `expo-router`.
   - In `GoalRow`'s non-delete-confirmation render branch, add a new action inside
     `GoalActionsRow`, alongside the existing Delete action:
     ```tsx
     <Link asChild href={{ pathname: '/sesh', params: { trickId: goal.trickId, mode: 'practice' } }}>
       <GoalAction accessibilityLabel={`Practice ${goal.trickName}`} accessibilityRole="link">
         <PracticeActionText>Practice toward this goal</PracticeActionText>
       </GoalAction>
     </Link>
     ```
     Place it **before** the Delete action (positive/primary action first, destructive
     action last — matches the ordering convention in `trick-directory.tsx`'s
     `RowActions`, where Practice is the last positive action before nothing more
     destructive follows, and keeps Delete as the trailing, easy-to-avoid action).
   - Do **not** add this action inside the `confirmingDelete` branch — that view is a
     destructive-confirmation dead end and shouldn't offer new navigation.
   - Copy: use "Practice toward this goal" as the visible label (goal-oriented per the
     task notes, not generic "Practice"). Reuse `GoalActionText`/style tokens already
     defined for `GoalAction` children — add a new styled text if the existing
     `GoalActionText`/`DeleteActionText` styling doesn't fit visually (e.g. you may
     want this one in `AppColors.ink` or a distinct accent to visually lead the
     action row); this is a minor styling call, use judgment.
   - `accessibilityRole="link"`: confirmed 4 of the 5 existing Link-wrapped Practice
     actions use `"link"` (`neglected-tricks-section.tsx`, both `daily-home.tsx`
     sites, `stats/[trickId].tsx`'s Challenge button). Only
     `trick-directory.tsx`'s Practice action uses `"button"` despite also being
     `Link`-wrapped — an existing inconsistency, not something to resolve here. Use
     `"link"` for the new goal action, matching the majority.

2. **No changes needed to `all-trick-goals-screen.tsx`.** It already passes
   `progress` straight through to `GoalRow`; the new action rides along
   automatically since it only needs data already in `progress.goal`.

3. **No changes needed to `src/app/sesh/index.tsx` or `Sesh`.** The preselected
   quick-start plumbing (T063) already handles an arbitrary `trickId` + `mode=practice`
   pair generically, including graceful fallback if the trick isn't resolvable.

4. **Tests — extend `src/features/goals/components/all-trick-goals-screen.test.tsx`.**
   Add a test (or extend the existing "lists goals..." test) that:
   - Adds a goal via the existing `add-goal-a` harness Pressable.
   - Locates the new practice link, e.g.
     `root.root.findByProps({ accessibilityLabel: 'Practice Big Cup' })`.
   - Asserts `link.props.href` equals
     `'/sesh?trickId=big-cup&mode=practice'` — mirroring
     `neglected-tricks-section.test.tsx`'s
     `'links each Practice action to /sesh with the correct trickId param'` test
     exactly, since the URL-encoding behavior of `Link`'s object-form `href` is
     already proven to serialize this way in this codebase.
   - Because `GoalRow` is shared, this single test file's coverage validates the
     behavior for both `TrickGoalsScreen` and `AllTrickGoalsScreen` renders. Do not
     also add a redundant `trick-goals-screen.test.tsx` solely to re-prove the same
     `GoalRow` logic — that would test the same code path twice for no incremental
     confidence. (If you find a reason `TrickGoalsScreen`'s own render path needs
     separate coverage beyond what's already implicit, note it, but it isn't
     expected here.)
   - Also confirm the Delete action's existing accessibility label/behavior is
     unaffected by the new sibling row (the existing "removes a goal from the list
     once deleted" test already exercises `Delete goal` — just rerun it, don't
     rewrite it, to catch any accidental prop/label collision from the new action).

5. **Verify.** Run `node .claude/scripts/verify.mjs` (full sequence, including web
   export — this is a rendered-UI change) from the repo root.

## Risks / non-obvious things to check while implementing

- `accessibilityRole` across existing Practice actions is inconsistent
  (`"button"` in `trick-directory.tsx` vs. `"link"` everywhere else) — this plan
  follows the majority (`"link"`) rather than treating the outlier as canonical;
  no need to fix the outlier as part of this task.
- `GoalRow`'s existing `GoalAction` styled component is `Pressable`-based with
  `min-height: 36px; justify-content: center;` and no built-in visited/pressed
  affordance beyond text color — adding a third action to `GoalActionsRow` (which is
  `flex-direction: row; gap: 14px`) should still fit comfortably in the existing
  `GoalCard` (`padding: 16px`, no fixed width) on a 320px viewport since `GoalCard`
  stacks vertically inside a `ScrollView`, not a fixed-width row layout like the
  five-link nav — but do a quick visual check at 320px width per `AGENTS.md`'s web
  navigation note if the row visually crowds.
- `goal.trickId`/`goal.trickName` are immutable snapshots (per `AGENTS.md`'s
  custom-trick invariants and `GoalBase`) — this is exactly why no trick lookup is
  needed here, but it also means if a custom trick was since deleted, the Link still
  fires with a `trickId` that resolves to nothing in `availableTricks`, and `Sesh`'s
  existing fallback-to-full-picker behavior (already centralized, not goal-specific)
  is the correct, already-implemented behavior for that case — do not add
  goal-specific "trick no longer exists" handling, that would duplicate logic `Sesh`
  already owns.
