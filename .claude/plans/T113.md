# T113 -- Give the landing CTA a more distinctive, playful visual treatment

## Context established from the current code

`src/features/landing/components/landing-cta.tsx` is a single flat-fill bordered
panel (`AppColors.yellow` / `AppColors.sage`) with a tag/headline/body/button
stack. The rejection was specifically about flatness, not structure, copy, or
behavior -- none of `useUserProfile()`, `useRouter()`, or the copy objects
(`FIRST_TIME_COPY` / `RETURNING_COPY`) should change.

The app already has an established "playful sticker card" visual language,
used and (implicitly) already approved elsewhere, that this task should reuse
rather than invent something new:

- `src/features/tricks/components/trick-card.tsx` -- a bordered card with a
  hard offset drop shadow, set via `styled.View.attrs({ style: { boxShadow:
  '8px 8px 0 #18382e' } })` -- NOT the CSS `box-shadow` shorthand. See the
  comment at trick-card.tsx lines 30-33: `css-to-react-native` lowers the
  shorthand to deprecated `shadow*` RN props and triggers RNW deprecation
  warnings. The card also has an oversized decorative background glyph
  (`RankWatermark`, a huge `Text` positioned `absolute`, bled off the card
  edge, low-contrast tint, declared *before* the foreground content in JSX so
  it paints behind it) and a bold solid-color pill badge (`RankBadge`, red
  background, cream text, uppercase, letter-spacing).
- `src/features/onboarding/components/onboarding-rank-reveal-step.tsx` and
  `src/components/animated-icon.tsx` already use `react-native-reanimated`
  (`Animated.View`, `entering={FadeIn/ZoomIn...}`, `Keyframe`) for playful
  motion, including `styled(Animated.View)` directly as a styled-components
  base (see `RankStage` in onboarding-rank-reveal-step.tsx). `reanimated` is
  already a dependency (package.json: `react-native-reanimated: 4.5.1`) and
  is already exercised through Jest (`kentei-rank-auto-promotion.test.tsx`
  renders `OnboardingRankRevealStep`), so entrance animations are known to be
  test-renderer-safe without extra mocking.
- No external image/illustration assets are needed -- trick-card and
  animated-icon both build their "illustration" purely from `Text`/`View`
  primitives and CSS-ish styling, avoiding the licensing concern the task's
  Notes flag.

Reusing these exact patterns means the CTA becomes visually consistent with a
part of the app that already reads as polished, rather than a one-off new
style. That is the recommended direction.

## Target treatment

Layered "stamped sticker" card, built from three additions on top of the
existing `CtaPanel` shape, plus one motion touch:

1. Layered shape / depth -- give `CtaPanel` the same hard offset `boxShadow`
   treatment as `Card` in trick-card.tsx (via `.attrs({ style: { boxShadow:
   ... } })`, same reasoning as the existing code comment). Keep the existing
   `border: 2px solid ink` and `border-radius`. This alone turns the flat
   rectangle into a "sticker sitting on a shadow layer."
2. Illustration/texture -- add an oversized decorative glyph (`CtaMotif`),
   modeled directly on `RankWatermark`: a large `Text` (e.g. a single bold
   circle glyph, standing in for the kendama ball -- avoid emoji for
   cross-platform font consistency), `position: absolute`, bled off one
   corner of the panel via negative offsets, tinted low-contrast (e.g. an
   `rgba` over `AppColors.ink` at roughly 10-15% opacity, or a lighter
   `AppColors.paperStrong`-family tint -- pick something legible against both
   `yellow` and `sage` backgrounds since the same motif renders in both
   variants). Declare it first in `CtaPanel`'s JSX children so later content
   paints on top of it (matches trick-card's DOM ordering -- RN's default
   `position: relative` on the parent means no explicit `position: relative`
   is needed, same as `Card`). Give `CtaPanel` `overflow: hidden` so the bleed
   is clipped at the panel edge -- note `overflow: hidden` on the *same*
   element as its own `boxShadow` does NOT clip that shadow (box-shadow
   paints outside the box independent of the element's own overflow), which
   is exactly why trick-card.tsx already combines both safely.
3. Bold color pop / "stamp" -- replace the current plain uppercase `CtaTag`
   styling with a wrapping pill badge (`CtaBadge`), modeled on trick-card's
   `RankBadge` (solid `AppColors.red` background, cream text, uppercase,
   letter-spacing, rounded pill), but rotated a few degrees (`transform:
   rotate(-3deg)`) so it reads as a stamped label rather than a plain chip.
   The existing `CtaTag` text node stays as the child inside this badge --
   do not remove or rename it, since the returning-visitor test already
   asserts on that copy (`'Welcome back'`).
4. Motion -- change `CtaPanel` (or wrap it) to animate in with
   `react-native-reanimated`'s `entering` prop, following the
   `styled(Animated.View)` + `entering={...}` pattern from `RankStage` in
   onboarding-rank-reveal-step.tsx (e.g. `FadeInUp.duration(450).springify()`
   -- confirm the exact export name against the installed reanimated version
   during implementation; `FadeIn`/`ZoomIn` are the confirmed-available
   precedents if `FadeInUp` is not exported). This is a small, low-risk,
   already-proven-testable addition, not a new animation system.

Keep the variant color distinction (`yellow` vs `sage` background) exactly as
it is today -- only the *treatment* changes, not the variant logic.

## Ordered implementation steps

1. `src/features/landing/components/landing-cta.tsx` -- do all visual
   changes here first, since the test file changes depend on the final
   structure:
   - Add `import Animated, { FadeInUp } from 'react-native-reanimated';` (or
     whichever entering animation is confirmed available).
   - Change `CtaPanel` from `styled.View<{...}>` to a `styled(Animated.View)`
     base with `.attrs(() => ({ style: { boxShadow: \`8px 8px 0
     ${AppColors.ink}\` } }))` (the callback form is needed since
     `AppColors.ink` is not a literal). Verify this combination -- generic
     `$variant` prop, `.attrs`, and an `Animated.View` base all together --
     compiles cleanly under `yarn tsc --noEmit`; trick-card's own example has
     no generic prop and no `Animated.View` base to cross-check against, so
     do not assume it "just works." If it fights the typing, fall back to
     applying `boxShadow` via a plain inline `style` prop at the JSX call
     site instead of baking it into `.attrs`.
   - Add `overflow: hidden;` to `CtaPanel`'s template (it does not have it
     today).
   - Add `entering={FadeInUp.duration(450).springify()}` on the `<CtaPanel>`
     JSX usage (not baked into the styled-component itself, matching how
     `RankStage` receives `entering` as a prop at the call site).
   - Add a new `CtaMotif` styled `Text` (oversized glyph, absolute, bled
     off-edge, low-contrast tint) and render it as the *first* child inside
     `<CtaPanel>`, before `CtaTag`/badge.
   - Add a new `CtaBadge` styled `View` (red pill, rotated) and wrap the
     existing `<CtaTag>{copy.tag}</CtaTag>` in it:
     `<CtaBadge><CtaTag>{copy.tag}</CtaTag></CtaBadge>`. Keep `CtaTag`'s own
     styling reasonable against the new red pill background (likely switch
     its color to `AppColors.cream` to match trick-card's `RankBadge` text
     color, since `AppColors.inkSoft` will not contrast against red).
   - Leave `CtaHeadline`, `CtaBody`, `CtaButton`, and the `LandingCta()`
     function body (copy selection, `onPress`) untouched.
2. Manual browser check -- run the Expo web dev server (not a static export
   server, per AGENTS.md) and check the landing page at a <=480px width and a
   desktop width, for both a fresh profile (first-time copy) and an onboarded
   profile (returning copy -- reload with `hasCompletedOnboarding: true` via
   existing dev affordances or by completing onboarding once). Confirm:
   - The shadow/border sticker effect renders correctly on web (RNW must
     honor `boxShadow` as a real inline style the way trick-card already
     proves it does elsewhere in the app).
   - The bled-off glyph does not overflow the panel's rounded corners oddly
     at either width, and does not visually collide with the button/text at
     narrow widths.
   - The rotated red badge does not clip against the panel's padding at
     narrow widths.
   - The entrance animation plays once on load without jank and does not
     delay the button becoming pressable (reanimated `entering` is a paint
     effect, not a gate on interactivity, but confirm visually).
3. `src/features/landing/components/landing-cta.test.tsx` -- extend, do not
   rewrite:
   - Keep both existing `it(...)` blocks and their assertions unchanged
     (press -> `router.push('/app/home')` for both variants; returning-visitor
     copy swap). These must keep passing exactly as written.
   - Add assertions (either appended into the existing two `it` blocks or as
     a new `it('renders the sticker-card treatment for both variants', ...)`
     that mounts both variants) proving the new visual elements are actually
     in the render tree, using the file's existing `findAll`-based idiom
     rather than introducing `testID` (no `testID` convention exists anywhere
     else in the codebase today -- do not be the first to add one for this

     - The oversized motif glyph is present: reuse the existing

## Risks / non-obvious things to watch

- `.attrs` + generic styled props + `styled(Animated.View)` together:
  trick-card.tsx's `.attrs({ style: {...} })` example is on a plain
  `styled.View` with no generic type parameter and no `Animated.View` base.
  `CtaPanel` needs `.attrs(...)`, a `$variant` generic prop, and
  `Animated.View` as the base simultaneously -- confirm this compiles
  cleanly under `yarn tsc --noEmit` early, and fall back to an inline
  `style` prop at the call site if it does not.
- Reanimated `entering` under Jest: confirmed test-renderer-safe via
  `kentei-rank-auto-promotion.test.tsx` today, but that test does not assert
  anything about the animation itself -- it just proves the component
  mounts. If `act(async () => ...)` in `mount()` does not flush the entering
  animation fully, that is fine; the new test assertions target static
  resolved styles (rotate, boxShadow), not animation state, so they should
  not be animation-timing-sensitive. Do not try to assert anything about
  animation progress/frame state.
- Contrast: the red badge's cream text, and the low-contrast bled motif
  glyph, both need to work against both `AppColors.yellow` and
  `AppColors.sage` panel backgrounds since the same treatment renders for
  both variants -- check both, not just one, during the manual browser pass.
- Do not touch `landing-page.tsx`, `useUserProfile()`, `useRouter()`, or the
  copy objects -- this task is scoped to `landing-cta.tsx`'s visual treatment
  only. T114 (CTA reposition) is separate and explicitly fine to land before
  or after this in either order.
