# T037 — Refresh Home time-based summaries while the app remains open

## Root cause

`src/app/index.tsx` computes the `now` passed into `createHomeSummary` like this:

```ts
const [mountedAt] = useState(Date.now);
const summaryNow = sessions.reduce(
  (latest, session) => Math.max(latest, session.completedAt),
  mountedAt,
);
```

`mountedAt` is captured once via `useState(Date.now)` and never changes. `summaryNow` only
advances when `sessions` changes (a new completed Sesh). All the pure summary math already takes
an explicit `now` (`createHomeSummary`, `calculateTimeLogged`, `calculateStreak` in
`src/features/home/model/home-summary.ts`, `src/features/stats/model/time-logged.ts`,
`src/features/stats/model/streak.ts` — confirmed, no changes needed there). The bug is entirely
that the *caller* never re-supplies a fresher `now` while Home stays mounted. This is a
presentation-layer fix only.

## Design

Add a small hook that ticks a `now` value on an interval and refreshes immediately when the app
returns to the foreground, then use it in `src/app/index.tsx` instead of the frozen `mountedAt`.
No reducer, provider, or persisted state is touched — everything here is local component state,
consistent with the existing `useNow` pattern already in `src/features/sesh/components/sesh.tsx:681-689`
(interval + `useState`/`useEffect`, cleaned up on unmount), extended with an `AppState` listener.

Keep the existing `Math.max(tickedNow, latestSessionCompletedAt)` clamp. It's not just a workaround
for the old frozen clock — it's a correctness guard: a session can complete and update
`sessions` via context in between clock ticks, and `createHomeSummary`/`calculateTimeLogged` filter
on `completedAt <= now`. Dropping the clamp risks a session momentarily falling outside every
window right after it's recorded, whenever the last tick is more than an instant stale. Keep it.

### 1. New hook: `src/features/home/hooks/use-live-clock.ts`

Feature-scoped (Home is the only current consumer; don't generalize into `src/hooks/` yet — no
second caller exists, and AGENTS.md's per-concern pattern favors deferring shared extraction until
there's a real second use).

```ts
import { useEffect, useState } from 'react';
import { AppState } from 'react-native';

export function useLiveClock(intervalMs: number): number {
  const [now, setNow] = useState(Date.now);

  useEffect(() => {
    const interval = setInterval(() => setNow(Date.now()), intervalMs);
    const subscription = AppState.addEventListener('change', (state) => {
      if (state === 'active') setNow(Date.now());
    });
    return () => {
      clearInterval(interval);
      subscription.remove();
    };
  }, [intervalMs]);

  return now;
}
```

Export a named constant for the interval alongside it (or in the same file), e.g.
`export const HOME_CLOCK_INTERVAL_MS = 60_000;` — one minute. Rationale: the summary windows this
feeds are 24h/7d/30d/365d rolling windows and local-day streak boundaries; sub-second precision
(like Sesh's 250ms countdown tick) isn't needed and would cause pointless re-renders of the whole
Home tree. A minute-level tick means the 24h/local-day boundary is reflected within at most a
minute of it passing, which is more than good enough for a dashboard. Do not reuse Sesh's 250ms
`useNow` — different concern, different file, don't couple them.

Note: `AppState.addEventListener('change', ...)` fires on *any* transition, not just entry to
`active` (it also fires for `inactive`/`background`). The `if (state === 'active')` guard is
required — without it you'd call `setNow` (and re-render) on backgrounding too, which is harmless
but wasteful and not what "foreground" refresh means.

### 2. Update `src/app/index.tsx`

Replace:

```ts
const [mountedAt] = useState(Date.now);
const summaryNow = sessions.reduce(
  (latest, session) => Math.max(latest, session.completedAt),
  mountedAt,
);
```

with:

```ts
const liveNow = useLiveClock(HOME_CLOCK_INTERVAL_MS);
const summaryNow = sessions.reduce(
  (latest, session) => Math.max(latest, session.completedAt),
  liveNow,
);
```

Drop the now-unused `useState` import if nothing else in the file needs it (check — `useMemo` stays).
Add the import for `useLiveClock`/`HOME_CLOCK_INTERVAL_MS` from
`@/features/home/hooks/use-live-clock`.

The existing `useMemo(() => createHomeSummary(...), [customTricks, profile, sessions, summaryNow])`
dependency array already includes `summaryNow`, so no change needed there — it will now actually
recompute on each clock tick and on foreground, instead of only when `sessions`/`profile`/`customTricks`
change.

## Implementation order

1. Write `src/features/home/hooks/use-live-clock.ts` (new file, no dependents yet — safe first step).
2. Write `src/features/home/hooks/use-live-clock.test.ts` (see Testing below) against the hook in

3. Wire the hook into `src/app/index.tsx`.
4. Write/extend a Home-screen-level fake-time test exercising the two exit-criteria scenarios

   hook in isolation.
5. Run the standard verification sequence (`node .claude/scripts/verify.mjs`).

## Testing

### Hook unit test — `src/features/home/hooks/use-live-clock.test.ts`

Follow the `sesh.tsx` `useNow`-style pattern already used in `sesh.test.tsx` (`jest.useFakeTimers()`,
mount a tiny host component via `react-test-renderer`, `act(() => jest.advanceTimersByTime(...))`).

- Mount a trivial component that renders `String(useLiveClock(60_000))`.
- Assert the initial rendered value equals the mocked `Date.now()` at mount.
- Advance fake timers by 60_000ms inside `act`; assert the rendered value advanced.
- Foreground case: `AppState.addEventListener` is auto-mocked repo-wide by
  `@react-native/jest-preset` (confirmed at
  `node_modules/@react-native/jest-preset/jest/mocks/AppState.js` — `addEventListener` is a
  `jest.fn()` returning `{ remove: jest.fn() }`, wired in via that preset's `setup.js` module
  mapping). Grab the registered handler via
  `(AppState.addEventListener as jest.Mock).mock.calls[0][1]`, call it with `'active'` after
  advancing `Date.now` (e.g. via `jest.setSystemTime`), and assert the render updates *without*
  advancing the interval timer. Also call it with `'background'` and assert no unexpected extra
  update semantics beyond what the guard implies (optional, but cheap to cover the `!== 'active'`
  branch explicitly since it's easy to get backwards).
- Unmount and assert `clearInterval`/`subscription.remove()` both ran (spy on `clearInterval`
  and on the mock's returned `remove` fn) — this is the "no leaked timers/handles" half of the
  exit criteria, worth asserting explicitly rather than trusting the `useEffect` cleanup by
  inspection alone.

Mock `expo-router`'s `Link`/`useRouter` only if `DailyHome`/`HomeScreen` actually invoke router

If mounting the full three-provider screen turns out to be significantly more friction than

## Non-goals / explicitly out of scope

- Stats screen (`src/app/stats/index.tsx`) uses `aggregatePracticeStats`, which is not
  time-windowed (no `now` param) — not touched by this task.
- No changes to `createHomeSummary`, `calculateTimeLogged`, or `calculateStreak` — all three
  already take `now` as a plain argument. Confirmed while planning.
- No new shared/global hook under `src/hooks/` — keep `useLiveClock` feature-scoped under
  `src/features/home/hooks/` unless a second real consumer shows up later.
- Don't widen the clamp logic or touch `WEEK_MS`/momentum's own windowing beyond passing the same
  refreshed `now` through — momentum already derives from `summaryNow` via `createHomeSummary`.

## Risks / non-obvious things

- `AppState.addEventListener('change', ...)` fires on every transition, not just entering
  `'active'` — the `state === 'active'` guard is required, not optional polish.
- The `Math.max(liveNow, latestSessionCompletedAt)` clamp must be kept, not removed as "no longer
  needed now that the clock ticks" — see Design section above for why removing it is a regression
  risk (a just-completed session's `completedAt` could exceed a stale tick's `now` between ticks).
- `jest.setSystemTime` vs `jest.advanceTimersByTime`: use `setSystemTime` to pin exact boundary
  crossings for the local-day and 24h assertions; use `advanceTimersByTime` to actually fire the
  `setInterval` callback (setting system time alone does not invoke pending timers early).
- Verify the actual provider import paths/names in `src/app/_layout.tsx` before writing the
  screen test — do not assume `CustomTricksProvider`'s export name without checking, since the
  plan above infers it from `useCustomTricks` usage in `src/app/index.tsx` rather than reading the
  provider file directly.
