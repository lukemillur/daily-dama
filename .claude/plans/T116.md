# T116 — Landing screenshot showcase: titles + designed container

## Current state (verified in code)

`src/features/landing/components/landing-page.tsx`:
- `Screenshot` interface: `{ source, alt, caption }`. `SCREENSHOTS` has exactly 4 entries (home screen, sesh first lace, custom trick form, trick goals).
- `ScreenshotSection` renders a `ScreenshotHeading` ("What you're signing up for") then maps `SCREENSHOTS` into `ScreenshotItem` (`styled.View`, no background/border — sits directly on the page's `AppColors.paper` background), each containing an `Image` and a `ScreenshotCaption` (`styled(BodyText)`).
- No existing test file for `landing-page.tsx`.

Established visual language elsewhere on the page:
- `landing-cta.tsx`: `CtaPanel` uses `border: 2px solid ${AppColors.ink}`, `border-radius: ${Radii.panel}px` (6px), and a solid background color (`AppColors.sage` / `AppColors.yellow`) — no boxShadow.
- `trick-card.tsx` (different feature, not landing): adds a hard-offset `boxShadow: '8px 8px 0 #18382e'` on top of the same border/radius idiom, via `.attrs({ style: { boxShadow: ... } })` (chosen deliberately over the CSS `box-shadow` shorthand because css-to-react-native lowers that shorthand to deprecated RN `shadow*` props).
- `AppColors` tokens available: `paper` (page bg), `paperStrong` (`#f6efd9`, slightly deeper cream), `cream` (`#fffaf0`), `sage`, `yellow`, `ink`, `inkSoft`, `borderMuted`.
- `Radii.panel` = 6.

Decision: give each `ScreenshotItem` a card treatment consistent with `CtaPanel` (2px `ink` border, `Radii.panel` radius, solid background) plus the `trick-card.tsx` hard-offset boxShadow, since the showcase is presenting discrete "proof" items much like trick cards, and the offset shadow is the one distinctive "playful sticker" touch not yet reused on the landing page itself. Use `AppColors.paperStrong` as the card background — it's a real, currently-unused-on-this-page token that's a visible but subtle step off `AppColors.paper`, avoiding introducing a new color. Titles use a distinct scale/weight from `BodyText` — a bold, larger styled.Text (similar treatment to `FeatureHeading`/`ScreenshotHeading` at 17px/900, but slightly larger, e.g. 19px, to read as a per-item title above the smaller caption).

## Four draft titles (matching existing voice — short, second-person/imperative-ish, punchy)

1. Home screen → **"Your practice loop, at a glance"**
2. Sesh first lace → **"First lace, first cheer"**
3. Custom trick form → **"Your move, your rank"**
4. Trick goals → **"Progress you can point to"**

(Alternates considered and rejected: generic "Home," "Sesh," "Custom Tricks," "Goals" — too flat/label-like next to the existing caption voice, which is full-sentence and conversational.)

## Order rationale

Steps 1–3 must happen together in one edit pass (data shape, new styled component, and container styling are all in the same file and interdependent — e.g. the test in step 4 depends on the final title strings from step 1). Test (step 4) after implementation so it can assert against real rendered output. Browser check (step 5) after test passes, since it's the harder-to-automate half of the exit criteria. Verification (step 6) last, as always.

## Risks / non-obvious notes

- **`Radii` import**: file currently imports only `AppColors` from `@/constants/theme` — must add `Radii` to that import line, easy to forget and would fail `tsc`.
- **`boxShadow` via `.attrs`, not template CSS**: replicate the exact `trick-card.tsx` pattern (`styled.View.attrs({ style: { boxShadow: '...' } })`) — writing `box-shadow: ...;` inside the styled-components template literal will silently get lowered to deprecated RN shadow props and likely won't render the same way on web (this was a discovered pitfall in `trick-card.tsx`'s existing code comment).
- **Test needs both mocks** (`expo-router` and `user-profile-provider`) because `LandingPage` unconditionally renders `LandingCta`, which needs both — omitting either will throw at render time, not just produce a wrong assertion.
- **Titles are new copy** — this task owns exact wording per the task Notes; the 4 drafts above are the implementer's-call output of this planning pass, but the implementer may adjust wording during implementation if a better phrase becomes obvious, as long as voice/tone stays consistent with existing captions.
- Do not touch `SCREENSHOTS`' `source`/`alt`/which-screenshots-are-shown — that's explicitly out of scope (T117).
