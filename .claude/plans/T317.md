## Findings (installed expo-symbols 57.0.3, read from node_modules)

- `SymbolView` `name` accepts `SFSymbol | { ios?: SFSymbol; android?: AndroidSymbol; web?: AndroidSymbol }`. A string name resolves to `null` on Android, so only `fallback` renders: today the tab icons are blank on Android. Cause confirmed.
- `AndroidSymbol` is `keyof symbols.json` (Material Symbols names). Exported from `expo-symbols` as a type.
- Android `SymbolView.js` loads a font through `expo-font` `loadAsync` in an effect with `[]` deps and `.catch(() => {})`. Until it loads, or forever if it fails, it renders an empty `View` of `size`x`size`. No error is surfaced, so the "indefinitely empty placeholder" risk in the exit criteria is real, and the fallback prop is NOT used in that state (it is used only when no name exists for the platform).
- The Android font is chosen by `weight` (`{ ios, android: AndroidSymbolWeight }`, weights imported from `expo-symbols/androidWeights/<weight>`). There is no FILL axis. Because the font effect has `[]` deps, changing `weight` after mount does NOT load the new font file. Do not signal selected state through a weight change (it would render missing glyphs). Use a different glyph name per state instead, plus tint (already derived).
- Candidate Material names all exist in symbols.json: `home`, `home_filled`, `timer`, `list_alt`, `format_list_bulleted`, `bar_chart`, `leaderboard`, `person`, `person_outline`, `account_circle`. Verify each chosen name (and any `_filled`/outline variant) with grep on `node_modules/expo-symbols/build/android/symbols.json` before using it; the type check will also reject unknown names.
