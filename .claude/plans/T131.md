# T131 — Apply the CTA's entrance animation to the screenshot showcase

## Current state (verified on this branch)

`src/features/landing/components/landing-page.tsx`:
- `ScreenshotItem` (line 240) is `styled.View<{ $isWebLayout: boolean }>` — a plain View, no entrance animation.
- It's rendered in a `.map()` over `screenshots` (line 152) with a `boxShadow` style prop already passed at the call site (same pattern `CtaPanel` uses).
- The `.map()` callback currently only destructures `screenshot`, no `index`.
- `landing-page.tsx` does not currently import anything from `react-native-reanimated`.

`src/features/landing/components/landing-cta.tsx` (T130 already merged):
- Imports `Animated, { FadeInUp } from 'react-native-reanimated'`.
- `CtaPanel = styled(Animated.View)<{...}>` — the styled wrapper is built on `Animated.View`, not `styled.View`.
- Applied at the JSX call site: `entering={FadeInUp.duration(900).springify()}` (line 40), alongside the `boxShadow` style prop.

Precedent for staggering multiple entrance animations in a list already exists in `src/features/onboarding/components/onboarding-rank-reveal-step.tsx`, which staggers sibling `FadeIn` entrances via `.delay(...)` in 100ms increments (350, 450, 550).

Tests (`landing-page.test.tsx`) locate `ScreenshotItem` nodes via `testID="screenshot-item"` and check flattened `style` (maxWidth, boxShadow presence via `findNodeWithStyleIncluding`) — they don't assert on `entering`/animation props, so no test changes are required for this change to pass, though I'll re-run the suite to confirm `testID`, `style` merging (array + styled CSS), and text queries still resolve correctly against a `styled(Animated.View)`.

## Implementation steps

1. **`src/features/landing/components/landing-page.tsx` — import.**
   Add `import Animated, { FadeInUp } from 'react-native-reanimated';` near the other component imports (grouped with the `expo-image`/`react-native` imports at the top, matching import ordering already used in `landing-cta.tsx`).

2. **Convert `ScreenshotItem` to an animated styled component.**
   Change:
   ```ts
   const ScreenshotItem = styled.View<{ readonly $isWebLayout: boolean }>`
   ```
   to:
   ```ts
   const ScreenshotItem = styled(Animated.View)<{ readonly $isWebLayout: boolean }>`
   ```
   Leave the template body (gap/padding/background/border/etc.) untouched — only the base component changes, mirroring exactly how `CtaPanel` differs from a plain `styled.View`.

3. **Add `index` to the screenshot `.map()` and pass `entering` at the call site.**
   Change the map callback signature from `screenshots.map((screenshot) => (...))` to `screenshots.map((screenshot, index) => (...))`, and add the `entering` prop on `<ScreenshotItem>` alongside the existing `testID`, `$isWebLayout`, and `style` props:
   ```tsx
   <ScreenshotItem
     key={screenshot.alt}
     testID="screenshot-item"
     $isWebLayout={isWebLayout}
     entering={FadeInUp.duration(900).springify().delay(index * 100)}
     style={{ boxShadow: `8px 8px 0 ${AppColors.ink}` }}
   >
   ```
   Use `900` (the corrected T130 duration) and `.springify()` to exactly match `CtaPanel`'s easing/curve, per the exit criteria. Add the `.delay(index * 100)` stagger — same 100ms-increment pattern already established in `onboarding-rank-reveal-step.tsx` for sibling entrances — so the four items don't all pop in simultaneously. This is a small, low-risk addition within "the same `FadeInUp` pattern"; if you'd rather stay maximally literal to the exit criteria (which only requires matching duration/easing, not stagger), it's fine to drop `.delay(...)` and use the exact same `FadeInUp.duration(900).springify()` call as the CTA for all four items — note this as a call made during implementation either way.

4. **No changes needed to `ScreenshotSection`, `ScreenshotTitle`, `ScreenshotCaption`, or the screenshot data arrays.** Only `ScreenshotItem`'s base component and its JSX call site change.

## Order rationale

Single-file change; there's no dependency ordering beyond doing step 2 (styled-component base change) before step 3 (passing `entering` — which only exists on `Animated.View`, not plain `View`) since step 3 would fail type-checking otherwise.

## Risks / non-obvious notes

- `styled(Animated.View)` is an established pattern in this codebase already (`CtaPanel`), so no new risk there.
- Because the `ScrollView`'s children all mount immediately (not virtualized), all four screenshot items' entrance animations fire on initial page mount, not when they scroll into view — this matches existing behavior for `LandingCta` itself and is out of scope for this ticket (not a regression to introduce or fix here).
- Keep the `boxShadow` style prop passed as an explicit `style` prop at the call site (not folded into `.attrs`) — this file's own comment above `ScreenshotItem` (and the fuller explanation in `landing-cta.tsx`) documents why `.attrs`-based styled-components/native config wouldn't reliably carry that style into the merged/rendered style array.
