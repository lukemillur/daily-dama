# T129 - Redesign trick goal cards to match the app's visual identity

## Context found in the codebase

- `GoalCard` is defined at `src/features/goals/components/trick-goals-screen.tsx:253`:
  ```
  const GoalCard = styled.View`background-color: ${AppColors.paper}; border: 2px solid ${AppColors.ink}; padding: 16px;`;
  ```
  Used in two places in `GoalRow` (`trick-goals-screen.tsx:109` and `:133`) -- the delete-confirmation card and the normal goal card. No other component in the file (e.g. `FieldInput`, `KindOption`) needs to change; those are form controls, not "cards," and are out of scope.
- The app's established "sticker-style" bold-shadow card treatment has two existing implementations to match against:
  - `trick-card.tsx:34` (`src/features/tricks/components/trick-card.tsx`) -- the closest precedent since it's a plain, non-variant card, same as `GoalCard`:
    ```
    const Card = styled.View.attrs({ style: { boxShadow: '8px 8px 0 #18382e' } })`
      ... background-color: #f6efd9; border: 2px solid #18382e; border-radius: 6px;`;
    ```
    Uses `.attrs({ style: {...} })` to set `boxShadow` because RN Web's css-to-react-native lowers CSS `box-shadow` shorthand to deprecated legacy `shadow*` props -- `.attrs` bypasses that lowering. This pattern is safe here because there's no per-instance/variant style needed (unlike `CtaPanel` in `landing-cta.tsx:62`, which needs a variant-dependent inline `style` prop at the JSX call site instead of `.attrs`, since `.attrs` config isn't concatenated into the final style unless the caller also passes its own `style` prop).
  - `landing-cta.tsx:62` / `landing-page.tsx:240` -- variant-driven panels, not directly relevant since `GoalCard` has no variant.
- `Radii` in `src/constants/theme.ts:81` exposes `control: 4` and `panel: 6`. Use `Radii.panel` (6px) for consistency with `CtaPanel` and `ScreenshotItem`, rather than hardcoding a literal like trick-card.tsx's raw `6`.
- `AppColors.ink` (`#18382e`, confirmed via trick-card.tsx's inlined hex) is the standard bold-shadow/border color used everywhere. Use `AppColors.ink` from the theme import already present in `trick-goals-screen.tsx:8`, not a hardcoded hex -- `trick-card.tsx` inlines the hex only because it doesn't import `AppColors`; `trick-goals-screen.tsx` already does.
- No snapshot tests reference `GoalCard`'s rendered style (`trick-goals-screen.test.tsx`, `all-trick-goals-screen.test.tsx` checked -- neither snapshots styles or the card component). Safe to restyle without touching test files.

## Risks / non-obvious notes

- Do not use the CSS `box-shadow` shorthand in the styled-components template literal -- it gets lowered to deprecated `shadow*` RN Web props (documented inline in both `trick-card.tsx:30-33` and `landing-cta.tsx:54-61`). Use `.attrs({ style: { boxShadow: ... } })` instead, exactly like `trick-card.tsx`.
- `GoalCard` is a plain `styled.View`, not `styled(Animated.View)` like `CtaPanel` -- no animation/entering prop needed or expected here; don't add one, it's out of scope.
- Keep the change scoped to the `GoalCard` definition only. Do not touch `FieldInput`, `KindOption`, or other bordered elements in the same file even though they share the `border: 2px solid ${AppColors.ink}` style -- those aren't "cards" per the task's exit criteria and restyling them would be scope creep.
