# T086 — Visual color picker for theme colors

## Current state (verified against `development`, post-T085.2/T085.3)

`src/features/profile/components/theme-color-picker.tsx` renders `ThemeColorPicker`, which
mounts three `ColorField` instances (Background, Accent, Text), each with its own hex
`TextInput`, contrast hint, and Save button. `ColorField` owns local `hexText` state
(`useState(persistedValue ?? "")`), validates via `isValidThemeHexColor` from
`src/features/profile/model/user-profile.ts`, and computes contrast via
`contrastRatio`/`WCAG_AA_MIN_CONTRAST_RATIO` in `src/shared/color/contrast.ts` against a
`referenceColor` prop. Save calls `onSave(hexText)`, which routes to
`setThemeColors`/`setThemeTextColor` from `useUserProfileActions()`. There is no contrast gate
on Save (removed in T085.2). Tests in `theme-color-picker.test.tsx` drive the hex `TextInput`
via `onChangeText` and the Save `Button` via `onPress`, found through a `findByLabel` helper
that prefers nodes carrying `onChangeText`/`onPress`.

The task is to add a real visual picker *alongside* the existing hex `TextInput` (which must
keep working), for all three `ColorField`s.

## Dependency decision: react-native-svg, hand-rolled HSV square + hue bar

No color-picker component library is vetted. Considered and rejected:
- `reanimated-color-picker` / similar gesture-handler+reanimated pickers: adds a second gesture
  layer whose RNW touch/worklet interaction is unverified here, and drag callbacks aren't easily
  exercised with `react-test-renderer` (no simple prop to invoke in tests).
- `react-color`: DOM/`react-dom`-only, not a React Native component; wrong shape for this
  codebase even though we're web-only right now.

Decision: hand-build the picker (explicitly sanctioned as a fallback in the task notes), using
`react-native-svg` purely as a gradient-rendering primitive (MIT license, Software Mansion,
listed as a supported Expo SDK package, first-class React Native Web compatibility — it renders
real `<svg>` on web). Use React Native core's `PanResponder` (not `react-native-gesture-handler`)
for drag handling: it attaches plain `onResponderGrant`/`onResponderMove`/... props directly onto
the host `View`, which `react-test-renderer` can invoke exactly like the existing
`onPress`/`onChangeText` calls in the current tests — no gesture-handler root wrapper, no
worklet/JSI concerns, consistent with the existing test idiom.

Install with `npx expo install react-native-svg` (not plain `yarn add`) so Expo pins the
SDK 57–compatible version.

**Sizing choice:** give the SV square and hue bar fixed pixel dimensions (constants in the new
component file), not `onLayout`-measured ones. `onLayout` fires unreliably/with zero size under
`react-test-renderer`/jsdom, and fixed dimensions make the gesture math synchronous and trivial
to unit test. This is a deliberate simplification, not a bug.

## Ordered implementation steps

1. **`npx expo install react-native-svg`** — adds the dependency to `package.json` at the
   SDK-57-correct version. Do this first; every later step imports from it.

2. **`src/shared/color/hsv.ts`** — pure HSV↔hex conversion, sibling to `contrast.ts`:
   - `rgbToHsv({r,g,b}): {h,s,v}` (h in [0,360), s/v in [0,1]) and `hsvToRgb`.
   - `hexToHsv(hex?: string): {h,s,v} | undefined` — reuse `hexToRgb` from `./contrast.ts`
     (already exported) rather than re-deriving hex parsing; returns `undefined` for invalid/
     undefined input.
   - `hsvToHex(h, s, v): string` — always emit lowercase `#rrggbb`, matching the format already
     used everywhere else in this feature (`#4477aa`, `AppColors.ink`, etc.), so the result passes
     `isValidThemeHexColor` unchanged.
   - Add `src/shared/color/hsv.test.ts`: pure hues at 0/60/120/180/240/300°, black/white,
     round-trip stability for `#4477aa` and a couple of `AppColors` values, and that
     `hexToHsv` rejects `undefined`/malformed input.
   - Do this before the component — the component's tests and the picker's own logic both depend
     on this being correct and independently verified first.

3. **`src/features/profile/components/color-spectrum-picker.tsx`** — new component,
   `ColorSpectrumPicker({ persistedHex, accessibilityLabelPrefix, onChange })`:
   - Internal state `hue/sat/val`, lazily initialized from
     `hexToHsv(persistedHex) ?? hexToHsv(DEFAULT_SEED_HEX)!` where `DEFAULT_SEED_HEX = "#4477aa"`
     (matches the existing `TextInput` placeholder, so the picker's initial position and the
     hint text agree).
   - **Resync only on `persistedHex` changing** (`useEffect(() => {...}, [persistedHex])`), i.e.
     only after a Save or Reset commits a new value upstream — *not* on every keystroke in the
     sibling hex `TextInput`. This is a deliberate ordering decision: syncing off the live,
     not-yet-saved `hexText` (or worse, keying the component by it) would tear down/remount the
     `PanResponder` mid-drag every time a drag's own `onChange` call round-trips through parent
     state, breaking the gesture. Get this wrong and dragging will visibly jitter/reset.
   - **SV square** (fixed `SV_SIZE`, e.g. 200): an `Svg` with two stacked `Rect`s — one filled
     with a horizontal white→`hsvToHex(hue,1,1)` `LinearGradient` (saturation axis), one with a
     vertical transparent→black `LinearGradient` (value axis) — plus a `PanResponder`-driven
     absolutely-positioned "puck" `View` (small square, 2px `ink` border, matching this file's
     existing chunky-border swatch aesthetic — do not use a soft circular iOS-style handle, it'll
     look inconsistent with the rest of the app). `onResponderGrant`/`onResponderMove` read
     `evt.nativeEvent.locationX/locationY`, clamp to `[0, SV_SIZE]`, derive `sat`/`val`, call
     `onChange(hsvToHex(hue, sat, val))`.
   - **Hue bar** (fixed `HUE_SIZE` × `HUE_BAR_HEIGHT`): an `Svg` with one horizontal
     `LinearGradient` with 7 stops (red/yellow/green/cyan/blue/magenta/red at 0, 1/6 … 1) and its
     own `PanResponder`-driven puck. `locationX / HUE_SIZE * 360` → `hue`; calls
     `onChange(hsvToHex(hue, sat, val))`.
   - **SVG gradient IDs must be unique per mounted instance.** Three `ColorField`s render three
     pickers simultaneously on one page; a hardcoded gradient `id` (e.g. `"sat-gradient"`) will
     collide across instances on web (SVG ids are document-global) and gradients will silently
     render wrong/blank for 2 of the 3 fields. Use `useId()` and **strip non-alphanumeric
     characters** before using it inside `url(#...)` — React's `useId()` output contains colons
     (e.g. `:r1:`), and colons inside an `id` referenced via `url(#id)` are a known cross-browser
     fragility (fine in Chrome, can silently fail to resolve in others). Sanitize with
     `useId().replace(/[^a-zA-Z0-9]/g, "")`.
   - `accessibilityLabel`s: `` `${accessibilityLabelPrefix} saturation and lightness` `` and
     `` `${accessibilityLabelPrefix} hue` `` on the two responder `View`s, so tests can locate them
     the same way existing tests locate the hex `TextInput`/Save `Button`.

4. **`src/features/profile/components/color-spectrum-picker.test.tsx`** — unit-level coverage
   decoupled from `ThemeColorPicker`/the profile provider: mount `ColorSpectrumPicker` directly
   with a spy `onChange`; fire `onResponderGrant`/`onResponderMove` at known corners
   (`locationX/Y = 0` and `= SIZE`) on both the SV square and hue bar; assert `onChange` receives
   the hex predicted by `hsvToHex` for that exact corner (import the same conversion function
   used by the component rather than hardcoding hex literals, so the test isn't fragile to minor
   rounding). Also assert the `persistedHex`-change resync effect updates the rendered puck
   position/gradient hue without requiring a fresh `onChange` call.

5. **Wire into `theme-color-picker.tsx`**: inside `ColorField`, render
   `<ColorSpectrumPicker accessibilityLabelPrefix={label} persistedHex={persistedValue}
   onChange={setHexText} />` above the existing `FieldRow` (swatch + hex `TextInput`). Leave the
   `TextInput`, `Swatch`, hint, and Save button entirely as-is — `onChange={setHexText}` reuses
   the exact same state and Save path the hex input already uses, so "same `onSave`/profile
   path" and "manual hex entry still works" both fall out of not touching that code. No changes
   needed to `ThemeColorPicker` itself, `user-profile-provider.ts`, or the reducer.

6. **Extend `theme-color-picker.test.tsx`**:
   - Update the file-local `findByLabel` helper's `interactive` predicate to also match nodes
     carrying `onResponderGrant`/`onResponderMove` (currently only checks for
     `onChangeText`/`onPress`), so it can locate the new picker regions using the same pattern as
     everything else in this file — or add a small sibling `findResponderByLabel` helper if you'd
     rather not overload the existing one. Either is fine; pick whichever keeps the diff smaller.
   - Add one test per field (Background, Accent, Text) that fires the SV-square and hue-bar
     responders with synthetic `nativeEvent.locationX/locationY`, then clicks that field's
     existing Save button, then asserts through `ProfileProbe` — mirroring the existing
     `"saves a valid, sufficiently-contrasting background color..."` tests but sourcing the hex
     from a drag instead of `onChangeText`. Compute the expected hex via the same `hsvToHex`
     helper rather than a literal, for the same fragility reason as step 4.
   - Do not modify the existing manual-hex-entry tests; they must keep passing unmodified,
     which is itself the "manual hex entry still works" regression check.

7. **Run verification.** Use `node .claude/scripts/verify.mjs` (full, not `--skip-export` — this
   is a real UI/dependency change). Two known risk points to watch for, not necessarily bugs:
   - Jest transforming `react-native-svg`: `jest-expo`'s default `transformIgnorePatterns`
     usually already covers it, but if `yarn test` throws a `SyntaxError` from inside
     `node_modules/react-native-svg`, add an explicit override to the `jest.transformIgnorePatterns`
     block in `package.json` rather than trying to work around it another way.
   - `yarn tsc --noEmit`: confirm `react-native-svg`'s bundled types resolve cleanly for `Svg`,
     `LinearGradient`, `Stop`, `Rect`, and that `PanResponder`/`GestureResponderEvent` import from
     `react-native` without issue on RN 0.86.

8. **In-browser check** (exit criteria requires this explicitly): `yarn expo start --web` (per
   AGENTS.md, not a static export server), open Profile, and for at least one field: drag inside
   the SV square, drag the hue bar, confirm the swatch/hex text/contrast hint update live, click
   Save, reload, confirm persistence; then confirm typing a hex manually still works and still
   updates the picker's puck position after Save. iOS/Android are out of scope per the active
   platform-scope note — web-only check is sufficient here.

9. **Update `TASKS.md`** to close out T086 in the same commit, per the working agreement.

## Non-goals for this iteration (note, don't build)

- A curated preset-swatch row (quick-pick palette) — the hue+SV square already satisfies "visual
  picker," a swatch row is additive polish, not required by the exit criteria.
- Reconciling the pre-existing minor quirk where, after Reset, the hex `TextInput`'s own local
  `hexText` doesn't visually clear (only the picker will resync, via step 3's effect, since it
  reads `persistedHex`) — that's pre-existing `ColorField` behavior this task doesn't touch and
  isn't in scope to fix.
- Mobile (iOS/Android) verification — deferred per AGENTS.md active platform scope, even though
  `react-native-svg` and `PanResponder` are both cross-platform-portable by construction.
