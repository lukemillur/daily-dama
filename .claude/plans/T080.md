# T080 — Fix Kentei assessment exit and stale wrap-up leak

## Root cause recap (confirmed against current code)

1. `src/features/sesh/components/assessment-entry.tsx:65` calls
   `router.dismissTo('/')` on `onFinished`. `dismissTo` only works when the target
   href is already present in the *current stack's* navigation history. The
   wrap-up screen is reached via `router.push('/profile/kentei-assessment')` from
   `src/app/profile/index.tsx:56`, so the Profile stack's history is
   `['/profile', '/profile/kentei-assessment', .../countdown, .../active,
   .../completed]` (see `src/app/profile/kentei-assessment.tsx` for the nested
   sub-routes) — `/` (the Home tab's index) is never in that history. `dismissTo`
   silently no-ops.
2. `src/app/profile/_layout.tsx` currently has no `tabPress` listener, unlike
   `src/app/sesh/_layout.tsx` and `src/app/tricks/_layout.tsx`, which each add a
   listener on the parent tab navigator that calls `router.replace('/<tab>')`
   whenever their own tab button is pressed — confirmed this fires on *every*
   press of that tab's button, not just re-presses while already active (it's a
   `tabPress` event scoped by `event.target === <tabKey>`, unconditional on the
   previously-active tab). This is what makes it also cover the "immediately
   after Go to Home" case in the exit criteria, not just the "re-press" case.

## Fix

### 1. `src/features/sesh/components/assessment-entry.tsx`

Replace:
```ts
onFinished={() => router.dismissTo('/')}
```
with:
```ts
onFinished={() => router.navigate('/')}
```
`navigate('/')` resolves the href against the full route tree (crossing tab
navigators), unlike `dismissTo`, which only pops within the current stack's own
history. `push('/')` would also cross tabs but risks growing the Home tab's own
back-stack with duplicate entries on repeated assessments; `navigate` is the
correct primitive for "go to this tab/screen" without that side effect. Do not
try to keep `dismissTo` with a corrected argument — there is no href value that
makes `dismissTo` reach across into the Home tab's navigator from here.

Do **not** try to also reset the Profile stack from this handler (e.g. chaining
a `dismissTo('/profile')` first). That responsibility belongs entirely to step 2
below — see the note on test coverage for why splitting it this way is
deliberately simpler and already fully covered.

### 2. `src/app/profile/_layout.tsx`

Mirror `src/app/sesh/_layout.tsx` / `src/app/tricks/_layout.tsx` exactly:

```tsx
import { Stack, useNavigation, useRouter } from 'expo-router';
import { useEffect } from 'react';

export default function ProfileLayout() {
  const navigation = useNavigation();
  const router = useRouter();

  useEffect(() => {
    const tabNavigation = navigation.getParent();
    if (!tabNavigation) return undefined;

    const profileTabKey = tabNavigation
      .getState()
      .routes.find((route) => route.name === 'profile')?.key;

    return tabNavigation.addListener('tabPress' as never, (event: { readonly target?: string }) => {
      if (event.target !== profileTabKey) return;
      router.replace('/profile');
    });
  }, [navigation, router]);

  return <Stack screenOptions={{ headerShown: false }} />;
}
```

This is what actually satisfies the exit criterion's "checked immediately"
clause: when the user taps the Profile tab button — whether that's the very
first tab switch after "Go to Home" or a later re-press while already on
Profile — the listener fires and resets the Profile stack to `/profile`,
discarding the stale `/profile/kentei-assessment...` history. `router.navigate`
in step 1 only needs to get the user onto the Home tab; it doesn't need to know
anything about Profile's internal stack state, because this listener owns that
independently, the same way Sesh/Tricks already do for their own stacks.

## Order of operations

Do step 2 (layout listener) first, then step 1 (assessment-entry navigate
fix), then tests. There's no hard dependency, but the layout fix is the one
that actually resolves the "stale wrap-up" half of the bug and is most similar
to existing, well-tested code — get it right and tested before touching the
one-line `assessment-entry.tsx` change, so if something about the `tabPress`
timing surprises you, you find out before layering the other change on top.

## Risks / non-obvious things to watch

- `router.navigate` vs `router.replace` for step 1: `replace('/')` would also
  work functionally (Home's own stack index is trivially reachable), but
  `navigate` is the more semantically correct "switch to this tab" call and
  avoids conflating with the "reset-within-tab" semantics `replace` carries
  elsewhere in this codebase (see `sesh/_layout.tsx`, `tricks/_layout.tsx`,
  and the `/tricks/*` back-button call sites). Don't mix the two up when
  writing the mock in the test — the mock object literal in
  `assessment-entry.test.tsx` needs a `navigate` key, not a `replace` rename.
- Double-check `src/app/profile/kentei-assessment.tsx` for how its own nested
  sub-routes (countdown/active/completed) are wired — confirm `router.replace('/profile')`
  from the new listener correctly unwinds all of them (it should, since it's
  the exact same mechanism `sesh/_layout.tsx` already uses for its own equally
  deep nested completed/countdown/active sub-routes — see the parametrized
  `it.each` test in `src/app/sesh/__tests__/layout.test.tsx` for the pattern if
  you want an analogous deeper test, though it's not required to match Sesh's
  test depth here since Profile's nested structure doesn't have Sesh's
  query-param wrinkle).
- Don't touch `src/app/profile/index.tsx` or `src/app/profile/kentei-assessment.tsx`
  — neither needs to change for this fix.
