# T045 - Auto-dismiss in-sesh celebration banners

## Current shapes (verified against development HEAD)

All four banners are rendered inside ActiveSesh (src/features/sesh/components/sesh.tsx,
~lines 493-600) via CelebrationBanner (~lines 714-738), which today only plays an entrance
animation on mount:

- showFirstLaceCelebration = hadPriorLaceAtSeshStart === false && landings.length === 1
- showPersonalBestCelebration = personalBest !== undefined && landings.length === personalBest + 1
- countGoalCelebrations - goals newly crossed this landings.length vs landings.length - 1
  (recomputed fresh every render, so it naturally drops out again on the next Laced press).
- timeGoalCelebrations - driven by crossedTimeGoalIds (a useMemo that's true for every
  render once elapsedMs passes the goal's target, i.e. permanently true from that point on),
  gated through celebratedTimeGoalIdsRef + celebratingTimeGoalIds state (lines 548-566): once
  an id is added to celebratingTimeGoalIds it is never removed, so that banner's element
  stays mounted (and, since nothing animates it out, visible) for the rest of the sesh regardless
  of further Laced presses. This is the specific defect called out in the exit criteria.

FirstLaceBanner and GoalCelebrationBanner already take a tense: 'inSesh' | 'wrapUp' prop and
are also rendered by CompletedSesh (static wrap-up screen, tense="wrapUp", no Laced button -
explicitly out of scope). PersonalBestBanner has no tense prop and is only ever rendered by
ActiveSesh.

## Design

Keep the reducer/timer boundary intact: none of this touches seshReducer or a Date.now() call
in the reducer - it's local UI-only component state/timers, same category as the existing
useNow polling interval in this same file, so it doesn't conflict with the AGENTS.md rule about
keeping timer effects and Date.now() out of the reducer.

Push the auto-dismiss lifecycle into CelebrationBanner itself, opt-in via a new
autoDismiss?: boolean prop, rather than tracking per-banner "dismissed" state up in ActiveSesh.
This works because React reuses the same CelebrationBanner component instance across re-renders
for as long as its parent keeps rendering it at the same JSX position/key - which is exactly the
"stays visible until the next Laced press" case today. So a self-contained timer inside the banner
that flips to dismissed = true (render null) after a few seconds, independent of any prop,
is sufficient: it fires regardless of whether landings.length (or, for the time-goal case,
crossedTimeGoalIds) is still "true" on every subsequent render. No per-key Set bookkeeping is
needed at the ActiveSesh level for the first three banner types, since their host arrays/booleans
are already recomputed fresh each render and drop the entry on the next Laced press anyway (first
one to happen - timer or press - wins, which matches "auto-fade after a few seconds instead").

Do not gate the internal dismissal on the Animated.timing completion callback. RN's Animated +
useNativeDriver: true falls back to a JS/RAF-driven path in the test environment (this is the
documented benign useNativeDriver fallback warning), and while jest's modern fake timers do
drive requestAnimationFrame, coupling correctness of the unmount to that RAF/callback
interaction is an unnecessary risk. Instead use two independent setTimeouts: one to kick off the
fade-out animation, one (fixed duration later) to flip local dismissed state to true and return
null. This makes jest.advanceTimersByTime fully deterministic for tests.

### 1. src/features/sesh/components/sesh.tsx - CelebrationBanner

Add module-level constants near the component (after the existing imports/before the component,
alongside other such constants in the file):

    const CELEBRATION_VISIBLE_MS = 4000; // time fully shown before starting to fade
    const CELEBRATION_FADE_MS = 250; // fade-out duration

(These are a UX call, not a technical constraint - "a few seconds" per the task description. Feel
free to adjust, but keep CELEBRATION_VISIBLE_MS comfortably above 2000ms: the existing time-goal
test at line ~1085 advances fake timers by up to 3500ms total from mount without expecting
dismissal - see step 4.)

Change the signature and body:

    function CelebrationBanner({
      accessibilityLabel,
      eyebrow,
      title,
      autoDismiss = false,
    }: {
      readonly accessibilityLabel: string;
      readonly eyebrow: string;
      readonly title: ReactNode;
      readonly autoDismiss?: boolean;
    }) {
      const [scale] = useState(() => new Animated.Value(0.55));
      const [opacity] = useState(() => new Animated.Value(0));
      const [dismissed, setDismissed] = useState(false);

      useEffect(() => {
        Animated.parallel([
          Animated.spring(scale, { toValue: 1, damping: 9, stiffness: 180, useNativeDriver: true }),
          Animated.timing(opacity, { toValue: 1, duration: 180, useNativeDriver: true }),
        ]).start();
      }, [opacity, scale]);

      useEffect(() => {
        if (!autoDismiss) return undefined;
        const fadeTimer = setTimeout(() => {
          Animated.timing(opacity, {
            toValue: 0,
            duration: CELEBRATION_FADE_MS,
            useNativeDriver: true,
          }).start();
        }, CELEBRATION_VISIBLE_MS);
        const removeTimer = setTimeout(() => {
          setDismissed(true);
        }, CELEBRATION_VISIBLE_MS + CELEBRATION_FADE_MS);
        return () => {
          clearTimeout(fadeTimer);
          clearTimeout(removeTimer);
        };
      }, [autoDismiss, opacity]);

      if (dismissed) return null;

      return (
        <Animated.View style={{ opacity, transform: [{ scale }] }}>
          <CelebrationBannerCard accessibilityLabel={accessibilityLabel}>
            <CelebrationBannerEyebrow>{eyebrow}</CelebrationBannerEyebrow>
            <CelebrationBannerTitle>{title}</CelebrationBannerTitle>
          </CelebrationBannerCard>
        </Animated.View>
      );
    }

opacity/autoDismiss are stable for the component's lifetime (fixed prop, useState ref), so
this effect runs exactly once per mount - it does not re-fire on every ActiveSesh re-render
(which happens ~every 250ms via useNow's polling interval while a sesh is active).

### 3. Fix the time-goal latch at the source (ActiveSesh, ~lines 528-566)

The self-dismissing banner alone is enough to stop the visible latch, but the underlying
celebratingTimeGoalIds state is redundant complexity now (it exists only to prevent
re-triggering, which CelebrationBanner's own dismissed state already handles as long as the
array entry for that goal id stays present). Simplify:

- Remove celebratedTimeGoalIdsRef, the celebratingTimeGoalIds state, and the useEffect that
  populates it (lines 548-562).
- Replace the timeGoalCelebrations computation (line 564-566) so it filters goalBaselines
  directly against crossedTimeGoalIds instead of the now-removed celebratingTimeGoalIds array
  (crossedTimeGoalIds already exists as a useMemo, unchanged): keep only baselines whose goal
  kind is time and whose goal id is present in crossedTimeGoalIds.

- Since a goal id stays in crossedTimeGoalIds for the rest of the sesh once crossed, React keeps
  reusing the same GoalCelebrationBanner instance for that key, so its internal dismissed state,
  once set, persists and the banner never reappears. This directly resolves the "nothing ever
  clears it" defect at its root instead of papering over it.
- Check whether useRef becomes unused in this file after removing celebratedTimeGoalIdsRef -
  grep confirms it is currently the only useRef call in sesh.tsx, so remove useRef from the
  react import near the top of the file too (otherwise lint/tsc will flag an unused import).

## Risks and non-obvious things to watch

- Do not let the dismiss-timer useEffect depend on anything that changes every render, such as
  landings, elapsedMs, or goalBaselines - that would restart the timer on every tick and the
  banner would never dismiss. Its dependency array must stay limited to autoDismiss and opacity.
- useNow's 250ms polling interval keeps ActiveSesh re-rendering throughout an active sesh; this
  is exactly why the old landings-length-coupled approach was insufficient, and also exactly why
  the new timer must live in a mount-once effect rather than something recomputed per render.
- Remove useRef from the react import only if it truly becomes unused - re-grep after the edit
  rather than assuming, in case some other part of this same change reintroduces a useRef call.
- Keep PersonalBestBanner un-parameterized (no tense prop) since it is genuinely in-sesh-only
  today; do not add a tense prop to it speculatively - that would be scope creep beyond this task.
