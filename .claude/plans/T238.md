## 4. The capture fixture

AsyncStorage on web is plain `localStorage` with the key used verbatim (no prefix) — the same seeding approach T115 and T117.1 used. Seed with Playwright `context.addInitScript(...)` so the writes land **before** the app bundle runs; the providers hydrate once from storage and skip the first persistence effect, so a post-load write would be ignored or clobbered.

Document shapes (validated against the real parsers — a malformed document silently recovers to empty state, which looks like "the fixture did not work"):

- `daily-dama:user-profile` = `{"version": 1, "profile": {...}}` — `hasCompletedOnboarding` must be `true` **and** `kenteiRank` an integer 1-12, or `parseUserProfile` rejects the whole document.
- `daily-dama:practice-history` = `{"version": 1, "sessions": [...]}` — each session needs `id, trickId, trickName, startedAt, completedAt, durationMs, laceCount`, with `completedAt >= startedAt` and `durationMs <= completedAt - startedAt`, and unique ids.
- `daily-dama:goals` = `{"version": 1, "goals": [...]}` — each goal needs `id, trickId, trickName, kind, createdAt, updatedAt` with `updatedAt >= createdAt`; `kind: "count"` requires `targetCount` and forbids `targetMs`, `kind: "time"` requires `targetMs` and forbids `targetCount`.

Concrete values:

```
profile: {
  hasCompletedOnboarding: true,
  kenteiRank: 5,
  selectedTrickIds: ["big-cup", "baseball", "around-the-block", "swing-spike", "earth-turn", "lunar-flip-in"],
  lastSesh: { trickId: "around-the-block", plan: { kind: "openEnded", targetLandingCount: 10 } }
}
```

Those ids are real (`createId` in `src/features/tricks/data/kendama-kentei-tricks.ts` lowercases and hyphenates the name) and span ranks 1, 2, 3, 4, 5 and 7 — Basic through Expert. The sesh picker renders the descriptor on each card as `Rank N · Level`, so the rank span is visible on the face of the screenshot without any extra work.

`lastSesh` is doing real work here: `src/app/app/sesh/index.tsx` turns a persisted open-ended `lastSesh` into `initialPlan`, which makes `TrickPicker` open with `planKind === "openEnded"` **already selected** and the target-laces field pre-filled with `10`. No clicking is needed to reach the Open-ended flow, and `around-the-block` is hoisted to the top of the list as `Up next · Rank 3 · Basic`. Note the side effect: with an open-ended plan selected, `personalBestsByTrickId` is empty, so the "When you beat your best" block and the per-card "Best at ..." lines do not render — that is correct for this screenshot and keeps it uncluttered.

Practice history: three sessions with timestamps computed from `Date.now()` inside the init script (a 3-day streak reads correctly only relative to capture time), for example `around-the-block` two days ago (900000 ms, 12 laces), `big-cup` yesterday (600000 ms, 24 laces), `baseball` today (780000 ms, 9 laces). Set `completedAt = startedAt + durationMs`.

Goals: three goals created ~7 days before the oldest session (goal progress only counts sessions with `completedAt >= goal.createdAt` — see `selectGoalProgress`), mixing both kinds so the goal screenshot shows a time goal and count goals:

- `{ kind: "time", trickId: "baseball", trickName: "Baseball", targetMs: 3600000 }`
- `{ kind: "count", trickId: "big-cup", trickName: "Big cup", targetCount: 40 }`
- `{ kind: "count", trickId: "around-the-block", trickName: "Around the block", targetCount: 25 }`

Cards are grouped by trick and sorted by trick name, so they render Around the block, Baseball, Big cup. If three cards do not frame well at 375x812, drop to two rather than shrinking anything.

No `daily-dama:custom-tricks` seed is needed — the custom-trick screenshot is of the empty creation form.


## 5. Ordered implementation steps

Assets first, code second: the `aspectRatio` and `require` edits in step 5 depend on the final filenames and pixel dimensions produced in step 3.

### Step 1 — Start the dev server on an explicit port

`yarn expo start --web --port 8097` (AGENTS.md: pick an explicit free port rather than assuming 8081 belongs to this repo). No `.env` is needed — `getSupabaseClient()` returns `null` when the Supabase env vars are absent and the app runs as a guest; that is the state all existing screenshots were taken in.

### Step 2 — Write a throwaway capture script

Put it in the scratchpad directory, **not** in the repo — this is a one-off, and the repo has no committed screenshot tooling to extend (`.claude/scripts/` is workflow tooling, `e2e/` is auth/security Playwright). `@playwright/test` is already a devDependency and the Chromium browser is already installed locally.

Skeleton (`.mjs`, importing `chromium` from `@playwright/test`):

1. `chromium.launch()`, then one `browser.newContext({ viewport, deviceScaleFactor: 1 })` per platform size.
2. `await context.addInitScript(seed)` where `seed` writes the three JSON documents from section 4 into `window.localStorage`.
3. For each shot: navigate to `http://localhost:8097` plus the route, wait on a text marker that only appears once the screen has rendered (for example `page.getByText("Focused tricks")` for sesh, `page.getByText("Trick goals")` for goals), then `page.screenshot({ path })`. Use viewport screenshots, **not** `fullPage` — the existing assets are exact viewport frames and the declared aspect ratios assume that.

The splash overlay (`AnimatedSplashOverlay`) removes itself after two animation frames, so waiting on a content marker is sufficient.

## 6. Risks and edge cases

- **The `__DEV__` links are the highest-probability mistake in this ticket.** They are invisible to anyone not looking for them, they sit in the bottom-right corner, and they will silently reappear in the new Home captures. Check the output files, not the live page.
- **A malformed fixture fails silently.** Every domain parser recovers to empty state on a validation failure rather than throwing, so a typo in the JSON produces an onboarding screen or an empty sesh list, not an error. If `/app/sesh` shows "Nothing queued", the profile document was rejected — most likely `kenteiRank` missing while `hasCompletedOnboarding` is true, or a duplicate id in `selectedTrickIds` (`isStringArray` rejects duplicates).
- **Seed timing matters.** Use `addInitScript`, not a post-navigation `page.evaluate`. The providers wait for hydration and skip the first persistence effect; writing after load can be ignored or clobbered.
- **Goal progress needs `createdAt` older than the sessions.** `selectGoalProgress` only counts sessions whose `completedAt` is at or after `goal.createdAt`. Goals created "now" read zero against their target and the recapture looks broken.
- **The nav pill is an absolutely positioned overlay** (from the T136-era `CustomTabList` restructure) and does not scroll with content. Scrolling the sesh picker slides content under it — leave enough offset that the PRACTICE FORMAT label is not obscured.
- **Do not switch to serving the static export** to get `__DEV__` false. AGENTS.md explicitly warns that a generic static file server mishandles Expo Router extensionless routes.
- **Aspect ratio and file size.** Keep `deviceScaleFactor: 1`. A 2x capture would quadruple the byte size of eight bundled images for no visible gain.
- **Do not repoint `landing-hero-fallback.png` or revive `LandingHero`.** Cropping the asset is in scope; changing what the landing page renders is not.
- **T242 and T243 also touch the landing page** and are open in `TASKS.md`. They edit `landing-auth-cta.tsx` and `landing-cta.tsx`, not `landing-page.tsx` or the assets, so a conflict is unlikely — but rebase onto `development` before opening the PR if either has merged in the meantime.
