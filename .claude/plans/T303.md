# T303 plan: picker keeps the gesture on iOS

## Findings
- `src/features/profile/components/color-spectrum-picker.tsx` has two `View`/`HueBarWrapper` responders (SV square, hue strip). Each sets `onStartShouldSetResponder`/`onMoveShouldSetResponder` = true plus Grant/Move handlers, but no `onResponderTerminationRequest`. The default lets the parent ScrollView take the responder, so a vertical drag scrolls the page.
- Profile uses `ProfileScroll = styled(KeyboardAwareScroll)` (`src/app/app/profile/index.tsx`), a thin RN `ScrollView` wrapper (iOS: `automaticallyAdjustKeyboardInsets`, `keyboardDismissMode: interactive`, `keyboardShouldPersistTaps="handled"`). Nothing in it interferes with responder negotiation.
- Existing tests (`color-spectrum-picker.test.tsx`) locate responders via `findByLabel` (label + `onResponderGrant`/`onResponderMove` props) and call `props.onResponderGrant` directly.

## Steps
1. Edit only `color-spectrum-picker.tsx`: add `onResponderTerminationRequest={() => false}` to both responder views (SV square and `HueBarWrapper`). Prefer one module-level `const refuseTermination = () => false;` shared by both, with a short comment: the picker must keep a drag that began on it, otherwise the enclosing ScrollView takes over and scrolls the page. Also add `onResponderTerminationRequest` only; do not change start/move-should-set (a drag that starts outside must still scroll the page).
2. Tests (same test file, written first / TDD): for each of the two responders (found by label), assert `node.props.onResponderTerminationRequest` is a function and returns `false`. Keep existing tests untouched.
3. Verify:
   - `yarn jest src/features/profile` (picker + theme-color-picker tests), then `yarn tsc --noEmit`, `yarn eslint src/features/profile/components/color-spectrum-picker.tsx src/features/profile/components/color-spectrum-picker.test.tsx`.
   - iOS Simulator (iPhone 17e, iOS 27.0, dev build with bundle pinned per `outputs/ios-personal-build-setup.md`): open Profile, scroll so the Background spectrum is mid-screen. Vertical drag from the spectrum square and from the hue strip: colour changes, page does not scroll. Vertical drag starting outside the picker (e.g. beside it) still scrolls. Record each result.
   - Web: run the Expo dev server on an explicit free port; drag the spectrum and hue strip with a mouse; behaviour unchanged. (`onResponderTerminationRequest` is harmless in react-native-web.)
   - Record Android and physical device as not run.

## Risk and fallback (decide only if step 3 iOS check fails)
UIKit's UIScrollView pan recognizer can in some cases begin natively regardless of the JS responder, so the one-line fix might not be enough on device. Check on the simulator before adding anything. If the page still scrolls, fall back, keeping it local to the picker and avoiding a gesture library:
- Add an optional `onDragStateChange?: (dragging: boolean) => void` prop to `ColorSpectrumPicker`; call it true in Grant and false in `onResponderRelease`/`onResponderTerminationRequest`-refused `onResponderTerminate`. `theme-color-picker.tsx` (and ultimately Profile) forwards it to toggle `scrollEnabled` on the scroll view. This touches more files and state, so only do it if needed, and add a test for the callback. Mention the decision in the PR.
- Do not change `KeyboardAwareScroll` globally.
