# T029.4 — Auto-advance on lace during an assessment

## Findings from exploration

- `MultiTrickSesh` (`src/features/sesh/components/multi-trick-sesh.tsx`) already implements
  `advanceOnFirstLace` exactly as [T028.1] left it: the `active` branch's `handleLaced` dispatches
  `trickLaced`, then, when `advanceOnFirstLace` is set and the pre-dispatch state shows zero prior
  landings for the current trick, immediately dispatches `seshEnded` (lines 213–220). This reuses
  the existing `completed`-state advance path — no reducer or `trick-sequence.ts` changes needed.
  The Notes' assumption ("Should be wiring only if T028.1 put the behavior in `MultiTrickSesh` as
  intended") is confirmed true. **No blocker.**
- `AssessmentEntry` (`src/features/sesh/components/assessment-entry.tsx`), lines 48–59, renders
  `<MultiTrickSesh>` in the `'running'` branch and currently passes `showAttemptsReminder`,
  `skipTarget`, `endActionLabel="End assessment"`, `skipCountdownBetweenTricks`, and `hideTimer` —
  every one of those **unconditionally**, not user-selectable. `advanceOnFirstLace` is simply
  missing from that call.
- `multi-trick-sesh.test.tsx` already has a full `describe('MultiTrickSesh advanceOnFirstLace', ...)`
  block (lines 126–193) from [T028.1], covering both the enabled path (one lace per trick advances
  through all three tricks, one recorded landing each) and the disabled/default path. This is the
  exact "records the trick and advances on the first landing" behavior the exit criteria asks for,
  and it already runs against the same `MultiTrickSesh` component `AssessmentEntry` renders.
- No test file mounts `AssessmentEntry` directly (`grep -rl "AssessmentEntry" --include="*.test.tsx"`
  found nothing) — T029.1/T029.2/T029.3 each relied on `multi-trick-sesh.test.tsx` coverage plus an
  in-browser walkthrough of the real `/profile/kentei-assessment` route to confirm the one-line
  prop pass-through, rather than adding a dedicated `AssessmentEntry` test file. This task follows
  the same precedent.

## The open call: always-on vs. user-selectable

**Resolved: always on, unconditional — the same pattern as every other assessment-only prop
(`showAttemptsReminder`, `endActionLabel`, `skipCountdownBetweenTricks`, `hideTimer`).**

Reasoning:
- [T013]'s own scoping notes record that the "5 attempts" reminder is purely informational — there
  is no attempt-counting or fail state anywhere in the assessment feature. The product shape of an
  assessment trick is "try until you land it, then move on" — once landed, there is no reason to
  keep practicing that trick within an assessment run; that would defeat the point of testing
  whether the user can land it. Auto-advance-on-lace is a direct expression of that, not an optional
  practice-session convenience.
- Every other assessment-shaping prop T029.1–T029.3 added (`endActionLabel`, `skipCountdownBetweenTricks`,
  `hideTimer`) was wired unconditionally with no entry-screen toggle, establishing a clear local
  precedent: `AssessmentEntry`'s `choosingFlow`/`choosingRank` screens are a simple linear
  flow-selection UI (large `FlowButton`s), not a settings form — there's no existing footer/checkbox
  affordance like `MultiTrickSeshEntry`'s setup screen has for `advanceOnFirstLace` in regular
  practice. Introducing one here would be new UI surface for a decision that's already effectively
  made by what an assessment *is*.
- This is also lower-risk and smaller scope, consistent with "wiring only."

Record this decision in the TASKS.md → TASKS_DONE.md notes when the task closes (per the Notes'
instruction to "resolve it while implementing and record the choice here").

## Implementation steps

1. **`src/features/sesh/components/assessment-entry.tsx`** — in the `'running'` branch's
   `<MultiTrickSesh>` call (around line 49), add `advanceOnFirstLace` as a boolean-shorthand prop,
   unconditional, alongside the other opaque assessment-shaping props (`skipCountdownBetweenTricks`,
   `hideTimer`, etc.). Suggested placement: next to `skipCountdownBetweenTricks`/`hideTimer` since
   it's the same category of "always-on assessment behavior," e.g.:

   ```tsx
   <MultiTrickSesh
     tricks={tricks}
     plan={OPEN_ENDED_SESH_PLAN}
     onFinished={() => router.replace('/profile')}
     showAttemptsReminder
     skipTarget={isMultiRankFlow ? (index) => selectNextRankStartIndex(tricks, index) : undefined}

     advanceOnFirstLace

   ```

   the prop and its behavior already exist and are already tested.
