# T043.1 plan: reconcile active Sesh state after foregrounding

## Current-state findings (verified in code)

- `seshReducer` (`src/features/sesh/model/sesh.ts`) is already timestamp-derived. `timerElapsed` is a no-op unless `status==='active'`, timed, not paused, and `now >= startedAt + durationMs + pausedDurationMs`; it then completes at the logical deadline (`completeSesh`). Open-ended elapsed is `now - startedAt - pausedDurationMs`. Paused sessions ignore `timerElapsed`.
- The gap is in the component layer, not the arithmetic. `ActiveSesh` (`sesh.tsx`) drives `onTimerElapsed` only from a `useNow` 250 ms `setInterval` tick (`useNow`, ~line 816). iOS suspends JS in the background, so after foregrounding the screen shows a stale `now` until the next tick, and nothing explicitly reconciles on the AppState transition. There is no lifecycle coordination anywhere in Sesh or MultiTrickSesh (`AppState` is used only in `use-live-clock.ts` and the sync coordinator).
- Completion recording is deduplicated in two places: `recordedSummaryId` ref in `sesh.tsx` (~line 114/154) and `multi-trick-sesh.tsx` completed effect, keyed by `createPracticeSessionRecordId` (`startedAt:endedAt:trickId`, in `src/features/stats/model/practice-history.ts`), plus the history reducer. Because a foreground-driven completion lands at the logical deadline, `endedAt` is deterministic, so the id is identical whether the foreground path or the interval path completes it. This is what makes double-recording impossible; keep it that way.
- Multi-trick: a timed overdue trick completes, the completed effect records it and `seedNextTrick` starts the next trick (countdown, or immediate `countdownCompleted` with `Date.now()` when `skipCountdownBetweenTricks`). Overdue time is NOT replayed onto later tricks; the next trick starts fresh at foreground time. That is the coherent behavior; keep it and document it.
- Countdown uses a chained `setTimeout` (not timestamp-based). It is out of scope (no persisted/timestamped countdown state is wanted); note it as an observation for T043.2, do not change it.

## Design

Add one reducer action as the authoritative, testable lifecycle transition, and one small hook that owns the AppState effect.

1. Reducer: `{ type: 'appForegrounded'; now: number }`.
   - active + timed + unpaused + `now >= deadline` -> same result as `timerElapsed` (complete at logical deadline). Implement by sharing a small internal helper with `timerElapsed` rather than duplicating the deadline arithmetic.
   - Everything else (choosing, countdown, completed, open-ended, paused, timed-not-yet-due) returns the same `state` reference. Open-ended elapsed time and paused non-accrual need no state change because both are derived from timestamps; the action must not touch `pausedAt`/`pausedDurationMs`.
   - Do NOT auto-resume or auto-pause on background/foreground. No new state fields; nothing persisted.
2. Hook `src/features/sesh/hooks/use-app-foreground.ts`: `useAppForeground(onForeground: (now: number) => void)`. Subscribes with `AppState.addEventListener('change', s => { if (s === 'active') onForeground(Date.now()) })`, removes on unmount, keeps the latest callback in a ref (update in an effect, not render) so the subscription is not re-created. Mirror the guard comment from `use-live-clock.ts` (the listener fires for inactive/background too).
3. Wire it:
   - `sesh.tsx` `Sesh`: `useAppForeground((now) => dispatch({ type: 'appForegrounded', now }))`. Do not set `timerElapsedTransitionRef` for this path, so the completion chime is not played as a late surprise on return (document with a one-line why-comment). The interval path still plays it.
   - `multi-trick-sesh.tsx`: same dispatch. The existing completed effect then records and advances exactly once.
   - `ActiveSesh`/`useNow`: also refresh `now` on foreground so the displayed clock is correct on the first frame instead of waiting up to 250 ms (use the shared hook; `setNow(Date.now())`). Keep `Date.now()` in the listener callback, not render. If both the reducer action and the interval effect fire `timerElapsed`, the second is a reducer no-op on `completed`.
   - Make sure the `Sesh` dispatch happens before/with the `useNow` setNow in the same event so ActiveSesh unmounts rather than flashing `00:00` (verify in a test; reorder or drop the `useNow` refresh if it causes a visible stale/duplicate frame).
4. Keep-awake: unchanged (tied to `state.status`; completion releases it). Do not add background handling.

## Risks and notes

- Do not add a Sesh-wide `Date.now()` into the reducer or any persisted/serialized in-progress state.
- Chime suppression on foreground completion is a judgment call (no sound on return); flag in the recap as an assumption.
- Guard against double side effects: the completion-side-effect effect in `sesh.tsx` (celebrations, goals, invite) runs once per `summaryId`; the new path must go through the same `state.status === 'completed'` effect, never a parallel recording call.
- Background-driven overdue time across several timed multi-trick tricks is deliberately collapsed to one completed trick; mention in the recap.
